## 1. 3-D mesher

`devsim_3d.Devsim3DEquilibrium._build_mesh`: the `mesher="gmsh"` warning now reads "... mesher='gmsh' is
kept ONLY to reproduce pre-v0.14 numbers and will be REMOVED in v0.15; use mesher='tensor', the default".
The module docstring and the `Stacked3DSpec.mesher` comment say the same.

**Warning class: kept `UnreliableResultWarning`.** `DynaMetaDeprecationWarning` is documented in
`dynameta/warning_types.py` as the class for "a deprecated spelling (renamed keyword, aliased function)
that still works", i.e. the same answer under another name. The gmsh mesh returns WRONG numbers (sum
NodeVolume 1.20-1.52 x the region volume), which is exactly what `UnreliableResultWarning` means; a
caller filtering deprecations must not silence it.

Gate: `tests/test_devsim_3d_mesh.py::test_legacy_gmsh_mesher_keeps_the_defect_and_warns` now also asserts
the message names "pre-v0.14" and "REMOVED in v0.15" (fails on ee0ad04).

## 2. Density-gradient gamma

**Inventory of every gamma parameter** (grep of `dynameta/`): `physics_density_gradient.dg_b_coefficient`
(`gamma=1.0`), `setup_dg_quantum_correction` (`gamma=1.0`), `setup_bipolar_dg` (`gamma_n=gamma_p=1.0`);
post-hoc `density_gradient.dg_length_m`, `quantum_potential_V`, `dg_correct_density_1d` (`gamma=1.0`).
`set_dg_gamma(frac)` is the ramp FRACTION, not gamma. gamma is NOT exposed by `TransportModel`, `Design`
or any builder. All defaults stay 1.

**`GAMMA_WALL = (3 pi/4)/I^2 = 1.6716999095045508`**, `I = int_0^1 (1 - t^2)/sqrt(t^2 ln t^2 - t^2 + 1) dt
= 1.187206890494961043770811572951519755863` (mpmath tanh-sinh, 80 digits). It lives in
`carriers.density_gradient` (numpy-only) and is re-exported by `physics_density_gradient`. The comment at
the constant derives it as the DG audit doc (GATE B) does: equal DG and exact free-gas wall deficits,
`I sqrt(gamma/6) = sqrt(pi)/(2 sqrt 2)`.

**"Choosing gamma"** sections (full at `setup_bipolar_dg`, `setup_dg_quantum_correction`,
`dg_correct_density_1d`; short self-contained ones at `dg_b_coefficient`, `dg_length_m`,
`quantum_potential_V`) state: what gamma does (b, L_q ~ sqrt(gamma)); gamma = 1 = the Wigner / Ancona
smooth-potential value (bulk / smooth problems, literature; also the post-hoc closure's ITO calibration);
GAMMA_WALL = the exact free-gas dark space at a hard wall (accumulation / inversion against a gate oxide)
with the GATE C numbers from docs/audit/2026-11-03-devsim-bipolar-density-gradient.md (sheet +21.3 / +17.3 %
vs +5.6 / +4.0 %, centroid -17.5 / -14.7 % vs -5.1 / -3.7 %, electrons / holes); unvalidated: strong
inversion (only weak inversion converges in 1-D, so the "inversion" use is inferred), degenerate FD beyond
GATE C's regime, 2-D/3-D, GAMMA_WALL in a wall-free problem; and that the unipolar kernel's GATE C
applicability is inferred (same kernel, comparison not rerun on a unipolar region).

Gate: `tests/test_density_gradient.py::test_gamma_wall_is_the_exact_free_gas_wall_gamma` -- I by an
independent scipy quadrature (rel 1e-12 on gamma; quad lands 4.0e-14 low on I because F(t) cancels near
t = 1), AND physics: `dg_correct_density_1d` on a flat profile carries the exact free-gas deficit at
GAMMA_WALL (MEASURED -2.1e-10 relative, 2001 nodes) and 0.773430 of it at gamma = 1 (doc: 0.7734).
Fails on ee0ad04 (ImportError).

## 3. quantum_srh

`setup_bipolar_dg` docstring: what it does (SRH reference `n p = n_i^2 exp((Lambda_n + Lambda_p)/V_t)`,
entered as `RTerm_dgsrh`), the measured consequence (GATE E: max |phi_n| = 3.3e-16 V, |phi_p| = 5.6e-17 V
with it; without it phi_n 6 mV off the wall node and phi_p 62 V at the wall node), when to turn it off
(only to reproduce a code / paper that keeps the classical reference), and that only the built-in channel
is corrected. Documentation only.

## 4. External generation shot noise

`noise_analysis.noise_spectrum` (full), `terminal_noise`, the module header, `BipolarOptions.generation_m3s`
(field comment) and the bipolar_options module doc item 5: True = Poisson photogeneration, GR source
`2 G_ext`, shot noise `2 q I_ph` for full collection; False = G_ext deterministic (it still sets the
operating point) -- for a prescribed drive / injection, a continuation aid, a noiseless pump, or source
statistics handled elsewhere. **Not validated:** no test or validation exercises G_ext noise (grep); the
2 q I_ph limit is the textbook expectation, not a measured gate. Documentation only.

## 5. chi_eV / band_gap_eV default None

**Inventory** (`dynameta/`, `examples/`, `validation/`, `tests/`):
- `TransportModel.chi_eV` is read only by the Anderson alignment: the 2-D `LayeredDevsimBuilder` frame
  (`_semiconductor_frames`) and the 3-D `Stacked3DSpec.from_design` -> `band_alignment`.
- `TransportModel.band_gap_eV` is read only by the 2-D builder: the bipolar-heterojunction gap check and
  the old value-based warning.
- No gate work function, Schottky contact, band diagram, optics model or materials preset reads either
  (`physics_traps.InterfaceTraps.band_gap_eV` is that class's own field). `examples/lumenairy_gated_grating.py`,
  `README.md`, `validation/_reference_device.py`, `bipolar_diode_2d.py`, `contact_current_drivers.py`,
  `devsim_heterojunction.py` pass explicit values.

**What changed.** Both defaults are `None` (band_gap_eV too: the inventory shows its only consumer is the
heterojunction path, so a default value served nothing but the silent-offset case).
`physics_heterojunction.anderson_alignment(..., materials=, hint=)` now holds the ONE same-material rule
(missing affinity + same material -> zero offset by identity; different materials -> ValueError naming
the field via `hint`), used by both builders (the 3-D `band_alignment` rule moved there unchanged). The
2-D builder's value-based AdvisoryWarning is removed; a bipolar heterojunction with `band_gap_eV=None`
refuses naming `band_gap_eV`. `from_design` carries None through.

**Gates** (tests/test_devsim_heterojunction.py; MEASURED failing on ee0ad04):
- `test_transport_model_has_no_default_affinity_or_gap`;
- `test_defaulted_affinity_at_a_heterointerface_refuses[one|both]` -- on ee0ad04 both built SILENTLY
  ("DID NOT RAISE"): 'both' at zero offset (the old warning also needed both gaps at 3.6), 'one' with a
  0.43 eV conduction-band offset of the wrong sign from the 4.5 default;
- `test_defaulted_band_gap_at_a_bipolar_heterojunction_refuses`;
- `test_3d_from_design_refuses_a_defaulted_heterostack_affinity` (ITO / AZO: refuses; ITO / ITO: builds);
- no-regression: `test_defaults_still_build_where_no_offset_is_read` (same-material stack, unipolar
  heterojunction with defaulted gaps).
- **Bit-identity vs ee0ad04** with explicit values: bipolar GaAs/AlGaAs p-n and isotype unipolar DD, at 0
  and 0.3 V, Potential / Electrons / Holes / terminal current / frames: 26 arrays, 4092 values,
  `np.array_equal` all. `run_all --tier full carriers_3d_multisemi devsim_heterojunction`: 2/2 PASS (GATE B
  of carriers_3d_multisemi now expects None, not the 4.5 default).

## 6. materials.TrapSpec

`TrapSpec.__setattr__` raises `NotImplementedError` when `enabled` is set truthy -- at construction AND on
later mutation; the message names `physics_traps.TrapLevel` (`TransportModel.srh_traps`,
`srh_trap_energy_eV`, `Stacked3DSpec(srh_traps=...)`) and `physics_traps.InterfaceTraps`
(`LayeredDevsimBuilder` / `Stacked3DSpec` / `from_design` `interface_traps=`). **Why there:** a check in
`TransportModel.__post_init__` or a builder is bypassed by `spec.enabled = True` after construction, and a
consumer-side check has to be repeated in every consumer; `__setattr__` covers both (only
`object.__setattr__` gets past it). `enabled=False` (default) unchanged and inert.
Gate: `tests/test_traps.py::test_legacy_trapspec_enabled_refuses_and_points_to_the_working_api` (ee0ad04:
DID NOT RAISE).

## 7. Per-process default 3-D mesh path

**Reproduced on ee0ad04.** Two processes building different 3-D devices (650 vs 425 nodes) with the default
`msh_path` (`~/.dynameta/_devsim3d.msh`), 100 builds each: 1 build came back with the OTHER process's mesh
and 199 of 200 died with "DEVSIM FATAL"; the gate's 25 builds each: 8 / 25 bad. Sequential default builds
in ONE process were fine.

**A DEVSIM finding on the way (pure-devsim repro, Windows, 2.11.2):** `create_gmsh_mesh(file=...)` never
closes the file -- `os.remove` fails with WinError 32 after `create_gmsh_mesh`, after `finalize_mesh` and
after `delete_device` + `delete_mesh`. So a per-build temporary FILE cannot be deleted in-process on Windows
(rewriting it works). Repro (session scratch, not in the repo): `C:/Users/Tesla/AppData/Local/Temp/claude/C--Users-Tesla/2446cd33-1dc4-4fe3-b419-8eafba706074/scratchpad/devsim_handle/repro_gmsh_handle.py` and `.out`.

**What changed.** `msh_path=None` with the tensor mesher (the default) hands DEVSIM the mesh IN MEMORY
(`create_gmsh_mesh(coordinates=, elements=, physical_names=)`, `devsim_3d._gmsh_lists`) -- no file at all.
An explicit `msh_path` is written, read and kept as before. The legacy gmsh mesher with the default gets a
fresh `tempfile.mkdtemp` per build (removed where the OS allows). The mesh/device step is now
`Devsim3DEquilibrium._create_mesh_device()`.

**Gates:** `test_two_processes_building_default_path_3d_devices_get_their_own_meshes` (0/25 + 0/25; 8/25 bad
on ee0ad04); `test_default_mesh_path_is_in_memory_and_bit_identical_to_the_file_route` (node coordinates,
NodeVolume, EdgeCouple and the solved Potential at Vg = 0.5 V: 12 arrays / 5864 values `array_equal`;
no file written or passed to DEVSIM on the default route, by a spy).

## 8. Lazy ngsolve

## Release-note lines (v0.14.0)

- carriers: `Stacked3DSpec(mesher="gmsh")` is kept only to reproduce pre-v0.14 numbers and will be removed
  in v0.15; its `UnreliableResultWarning` says so.
- carriers: `density_gradient.GAMMA_WALL = (3 pi/4)/I^2 = 1.6717` (re-exported by
  `physics_density_gradient`), the DG gamma whose dark space at a hard wall equals the exact free-gas one;
  the default stays gamma = 1. Every gamma entry point documents which to use: 1 for smooth potentials and
  literature comparisons, GAMMA_WALL for oxide-bounded accumulation / inversion layers (3-4x closer to
  Schrodinger-Poisson in GATE C).
- carriers: `setup_bipolar_dg(quantum_srh=True)` and `noise_spectrum(external_generation_shot=True)` keep
  their defaults; both are now documented at the function (what they do, the measured consequence, when
  to switch them off).
- materials: **behaviour change** -- `TransportModel.chi_eV` and `band_gap_eV` default to `None` (were 4.5
  / 3.6). A device with semiconductors of different materials refuses to build while an affinity is None
  (a bipolar heterojunction also needs both gaps), naming the field to set. Single-material and
  same-material devices need neither. Results with explicit values are bit-identical.
- materials: **behaviour change** -- `TrapSpec(enabled=True)` raises `NotImplementedError` (it was never
  read); use `physics_traps.TrapLevel` / `InterfaceTraps`.
- carriers: the 3-D builder no longer shares one default mesh file between processes: with
  `msh_path=None` the tensor mesh goes to DEVSIM in memory (bit-identical); an explicit `msh_path` is
  unchanged. Two concurrent default-path processes previously corrupted each other's builds.
- carriers: the FEM carrier modules (`electrostatics_fem`, `electrothermal`, `fem_mesh`, `thermal_fem`)
  import ngsolve lazily (`dynameta.lazy_import.LazyModule`): resolving every `dynameta.carriers` name now
  commits 1.65 GB instead of 6.17 GB per process.
- validation: `dd_field_mobility` and the 3-D noise resistor moved off gmsh onto exact Kuhn meshes; their
  Ohm's-law / conductance gates tightened from 16 % (the DEVSIM volume defect) to round-off.
