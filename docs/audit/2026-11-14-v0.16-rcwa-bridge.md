### The rule (`_auto_formulation`, `AUTO_RULE_VERSION = 1`)

A patterned isotropic layer (inclusions on a scalar background, or a laterally structured scalar
gridded field) is **hard** when it holds Re(eps) < 0 anywhere or max|eps|/min|eps| > 10. Per stack:
no hard layer -> `'laurent'`; 1-D stack -> `'li'` when the incident field has an E_x component
(`'x'`, `'p'`, or conical), else `'laurent'` (TE stays bit-identical); 2-D stack -> `'laurent'`
(MEASURED, deviation 1 below; the plan sent hard 2-D rectangle layers to `'li'`). Tensor layers
keep their own factorization. An explicit `'laurent'` on a stack the rule sends to `'li'` warns
once per solver (once per call of `design_to_rcwa_stack`); no default path warns. `solve_sweep`
resolves the rule at every wavelength and uses `'li'` for all if any asks for it (a material
crossing the threshold inside a band cannot switch the discretization mid-spectrum).

### The raster

Pixel j of an S-pixel axis is the cell `[x_j - P/2S, x_j + P/2S]` around lumenairy's node
`x_j = j P/S` and takes the area average of the painted permittivity; under `'li'` (lumenairy
>= 5.31) the companion `(exx, eyy)` = harmonic across x walls then arithmetic along y, and the
transpose, goes to `add_layer(eps_cell_normal=)`. Default lattice `max(128, 8 N)` per axis and at
least 8192 on a 1-D stack (the raster and its FFT cost nothing there; below). A gridded laterally
structured field is resampled by ITS coordinates (periodic piecewise-linear interpolant, exact
pixel means; endpoint-inclusive / node / cell-centred grids all read correctly), with at least as
many pixels as distinct samples.

### Per-layer absorption of an 'li' solve

lumenairy's `layer_absorption` integrates Im(eps)|E|^2; with Li's rule the truncated series of the
wall-normal E_x is not consistent with that integral (lumenairy 5.51 fixes the same defect for its
'li' layers). With `absorption=True` and a resolved `'li'`, the bridge attributes every layer its
Poynting-flux difference across its two faces from the retained modal fields (`_face_flux_split`),
normalized by the incident flux -- an independent measurement that closes on 1 - R - T to
round-off. A Laurent solve keeps lumenairy's split bit for bit.

## Hand-overs

* **A (`rcwa_design.py`)**: every add_layer names its formulation (uniform / tensor 'laurent',
  cells the caller's). Default stays 'laurent', documented: `jax.grad` through `formulation='li'`
  raises `TracerArrayConversionError` on lumenairy 5.50.2 (measured), lumenairy 5.51 keeps traced
  cells on Laurent, and a rule differing between a traced gradient and its concrete FD check would
  compare two discretizations. A concrete (non-traced) TM metal cell can use 'li' safely (its
  forward is the eps_cell 'li' path the bridge validates) -- recommended in the docstring, not made
  the default (no measurement on the design path warrants a default that differs between the
  traced and concrete calls). No number moves; no warning.
* **B (`validation/lumenairy_pmm_bridge.py` GATE D)**: the probe is now a 16-sample laterally
  varying field on a full-period x grid: `lateral_partition=None` must refuse it naming the
  keyword, the default must accept it and return a passive result. PASS (4/4).
* **C (`fem_2d_tm._kz`)**: replaced by `resonance._kz`. Every FEM call passes a cladding
  eps = n**2 of a passive end medium (Im >= +0), where the principal root IS the passive branch
  bit for bit. (Amended 2026-11-16: this note originally added that CPython's n**2 turns a -0.0
  imaginary part into +0.0. That holds only before Python 3.14, and it does not cover the
  square-root ARGUMENT eps k0^2 - k_par^2, which could still carry Im = -0.0 for a lossless metal
  and select the growing root. The shared kernel now reads a -0.0 imaginary part as +0.0 itself;
  see the square-root branch entry in `2026-11-15-v0.16.0-release.md`.) Same-process A/B (old kernel
  re-created vs the shared one) on six cells: bit-identical R, T, r, t, A_independent.
  `validation.fem_2d_tm_strip` prints identical numbers on the old and new trees; in
  `validation.fem_2d_tm_hydro` every H-form (this solver) number is identical and one E-form
  number (an independent NGSolve solve in the script, not fem_2d_tm) differs in the 8th digit
  (|d| 1.68e-7 -> 1.55e-7) -- and the OLD tree run twice gives the same two values (1.68e-7, then
  1.55e-7): run-to-run variation of that threaded solve, not this change. The two kernels differ
  only for Im(eps) < 0 (a gain substrate): the principal branch keeps Re(kz) > 0, the causal
  outgoing choice, and is kept.
  `tests/test_nonlocal_tmm.py::test_q19_one_kz_admittance_kpar` passes again.

## Deviations from the plan, and plan statements found wrong

1. **2-D rule.** Plan: 'li' on hard 2-D stacks whose analytic layers are rectangles. Measured
   (above): lumenairy's 2-D Li rule drifts away from the FEM and PMM references on a metal-patch
   array; on a disk array it fits R but not the phase. 'auto' keeps Laurent on 2-D stacks; the
   plan's "curved -> laurent + AdvisoryWarning" branch is therefore moot and not implemented
   (no warning on any default path). `LumenairyStackSolver` (always 2-D when structured) resolves
   'auto' to Laurent: its default is v0.15.1 bit for bit.
2. **Area raster lattice.** The plan keeps `max(128, 8 N)`; on the TM metal strip that leaves
   3.7e-2 on the generic cell (the plan gate "within 1e-3 of the S = 2960 area raster" fails). The
   area raster's smoothing error is O(S^-2); on a 1-D stack the default lattice is at least 8192
   (1.6e-4 from the exact geometry on the generic cell, no cost). The gate records the comparison
   against the analytic 'li' layer instead (a better oracle than another raster).
3. **Face-flux absorption (not in the plan).** With 'li' the default on 1-D TM metal cells,
   lumenairy 5.50's per-layer absorption would have been badly wrong by default (generic cell,
   n_orders 150: strips 0.480 vs 0.337 FEM). The bridge computes the Poynting-flux split itself for
   an 'li' solve.
4. **Sweep resolution (not in the plan).** solve_sweep resolves 'auto' once per spectrum.
5. **cache_fingerprint** also carries the lumenairy version ('auto' routes depend on it). The
   cache SCHEMA bump stays with P15 (`cache.py` is P15's file); the new fingerprint already
   changes every RCWA key, so a v0.15.1 entry is never served.
6. **N1 resample** uses `_lateral_partition.periodic_samples` / `interval_means` (imported, not
   copied: the census test asserts identity), which also brings P3's x-coverage guard (a metre-
   valued x axis is refused).
7. **ci.yml**: two file names appended to the `solvers` job (the coverage census requires it).
8. **Floor leg (lumenairy 5.22)** not run (no network). Below 5.31 the companion is omitted (the
   width stays exact); below 5.31 analytic shapes are absent and 'auto' rasterizes (area). Gates
   that need a younger feature are skip-gated by FEATURE_FLOORS.

## Left undone / uncertain

* The 2-D measurement covers two weak-metal cells (eps -3+1i); a strong metal (Ag, Au) 2-D cell
  was not measured against a 3-D reference (each 3-D FEM point is 4-25 min and up to 18 GB here).
* The face-flux split assumes a lossless superstrate for its normalization (n_super real); with
  a lossy superstrate its sum still closes on 1 - R - T only if lumenairy's efficiency
  normalization agrees -- not exercised.
