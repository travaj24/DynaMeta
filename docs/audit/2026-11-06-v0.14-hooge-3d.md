# Hooge 1/f noise in 3-D: one P1 element kernel for 2-D and 3-D

DEVSIM phase, release v0.14.0 blocker. Branch `wip/v014_hooge3d`, cut from integration be719d5.
DEVSIM 2.11.2, Windows dev box. All numbers below are MEASURED by me on this branch unless they are
labelled otherwise.

**Bottom line.**
- **The bug.** `noise_analysis` assembled the per-element Hooge source with DEVSIM's circumcentric
  `ElementEdgeCouple`. In 3-D that biases the result, even on the default Kuhn tensor mesh:
  S f N / (alpha I^2) = **1.12499999** on `validation.devsim_noise.unipolar_3d_resistor`. I
  re-measured this on be719d5 with `noise_analysis` itself.
- **The fix.** The element sum now uses P1 (linear-FEM) element couples,
  c_eT = -V_T L_e grad(lambda_i) . grad(lambda_j), computed from the node coordinates. One kernel
  (`_p1_element_couples`) serves 2-D and 3-D, and the 1-D path is unchanged.
- **After the fix.** The Kuhn bar reads 1 - 5.80e-9, and that residual is the predicted SG density
  term. An oblique, non-well-centred Delaunay box with exact geometry reads 1 + 2.7e-9; it was
  1.0547 before. 2-D results move by <= 7e-16.
- **What changed in the code.** Only the weight assembly inside `_hooge_elements` (plus the new
  kernel and docstrings). The `_RegionData` / `noise_spectrum` plumbing is untouched, so the ii2d
  branch's refusal call should merge cleanly.

## 1. The defect, and why the suggested fix is right

The Hooge source for an ohmic conductor:
- Hooge's law S_I/I^2 = alpha_H/(N f) comes from a conductivity fluctuation delta j = xi J, with
  <xi xi'> = alpha_H/(n f) delta(r - r').
- The adjoint field of the short-circuit terminal current in a uniform bar is y = (x . u)/L.
- So S = Int alpha_H (J . grad y)^2/(n f) dV = alpha_H (I/A)^2 L^-2 A L/(n f) = alpha_H I^2/(N f).

I re-derived this in the new test's docstring; it is the oracle there.

The discrete form:
- With one xi per element, S_T = (alpha/f) |Sum_e c_eT a_e (y_0 - y_1)|^2 / V_T, where
  a_e = J_e/sqrt(n_eff).
- For a uniform field, y_0 - y_1 = -L_e t_e . grad y and J_e = J . t_e.
- The element sum is therefore -J^T (Sum_e c_eT L_e t_e t_e^T) grad y / sqrt(n). It equals the
  continuum V_T J . grad y / sqrt(n) **iff** Sum_e c_eT L_e t_e t_e^T = V_T I. That is a tensor
  identity, not just a trace identity.

Why the P1 couples satisfy it, on every simplex and in any dimension:
- Write K_ij = V grad(lambda_i) . grad(lambda_j). Its row sums vanish.
- Sum_{i<j} -K_ij (x_i - x_j)(x_i - x_j)^T = Sum_ij K_ij x_i x_j^T = V (Sum_i x_i grad(lambda_i)^T)(Sum_j grad(lambda_j) x_j^T) = V I,
  because Sum_i x_i grad(lambda_i)^T = grad x = I.
- Hence c_eT = -L_e K_ij satisfies the identity exactly.
- In 2-D, c_eT is L cot(theta)/2, which is the signed circumcentric couple. So 2-D does not move.

Why the circumcentric couples fail in 3-D:
- Their per-element tensor has only the right trace.
- MEASURED with `devsim_geometry.tetrahedron_dual_pieces`, for the Kuhn path tet x, y, z:
  - circumcentric couples (0.125, 0, 0, 0.25, 0, 0.125) give the tensor diag(0.75, 1.5, 0.75) V_T;
  - P1 couples (1/6, 0, 0, 1/6, 0, 1/6) give exactly I V_T.
- Each axis is the middle step in 2 of the 6 path tets and an end step in 4, so an axis-aligned
  current sees (2 x 1.5^2 + 4 x 0.75^2)/6 = 1.125. This matches the measured 1.12499999.
- Over a cube interior, both couple sets assemble to the same 7-point weights. Inside a single cube
  they differ (by 1/12). That difference is irrelevant to every other consumer, because only the
  Hooge source uses per-element weights.

What the new form means for non-uniform fields:
- Sum_e c_eT a_e (y_0 - y_1) = -V_T j_T . grad y_T.
- grad y_T is the element gradient of the adjoint field.
- j_T = V_T^-1 Sum_e c_eT a_e L_e t_e is the element vector that the SG edge projections determine,
  and it is exact for a constant J/sqrt(n).
- So it is the rank-one source evaluated with element-constant vectors, as suggested. It is written
  through the edge projections so that the per-edge SG density n_eff is kept.

## 2. Gates (tests/test_devsim_noise_hooge_3d.py, new, 4 tests, ~10 s)

The oracle is the closed form above. Each fixture asserts its own exactness first: n uniform to 1e-12,
n = N_D, and I = q mu n V A/L to 1e-9.

**Derived budget.**
- (v/2) coth(v/2) <= 1 + v^2/12, so each a_e carries a relative error in [0, v_max^2/24]. Here v is
  the edge's SG argument `vdiff_g`.
- Sign-mixed P1 couples on non-well-centred elements amplify that error by
  kappa_T = Sum |c| L (t . u)^2 / V_T. kappa_T = 1 when every couple is >= 0, which is the case on Kuhn
  meshes.
- Budget = Sum_T V_T (2 eps kappa_T + (eps kappa_T)^2) / V + 4 |I/I_ohm - 1| + 1e-11.

S f N/(alpha I^2) - 1 at 1 and 1e3 Hz:

| Fixture | be719d5 | This fix | Budget | Perturbed (couples on the wrong edges) |
|---|---|---|---|---|
| Kuhn bar 10x4x4 cells of 20 nm (= validation unipolar_3d), current along x | +0.1249999935 | -5.8015e-9 | 5.812e-9 | +0.770 |

Notes on these gates:
- The Kuhn bar's -5.80e-9 is the SG density term itself: v_max^2/12 = 5.802e-9.
- Rotations are covered by the rigid rotation and by the rotated-lattice Delaunay box. The Kuhn
  mesher only builds axis-aligned bars, and by the 6-permutation symmetry of the construction the
  x-axis result also covers y and z.
- **Without** the exact geometry the Delaunay fixtures are invalid, because DEVSIM's own solve is off
  (I/I_ohm - 1 = 0.338 in 3-D, 0.036 in 2-D). They read:
  - 3-D: -0.244 with the new kernel, -0.198 with the circumcentric one;
  - 2-D: -0.048 with the new kernel, -0.022 with the circumcentric one.

  This is the only 2-D case that moves. It is an uncorrected obtuse mesh, where DEVSIM's 2-D
  `ElementEdgeCouple` is the unsigned |cot|, so the old Hooge weights were wrong there too. Neither
  number is meaningful. The ii2d refusal and `apply_exact_geometry` are the remedies.

## 4. Merge notes

- `noise_analysis._hooge_elements` no longer reads `ElementEdgeCouple`. It reads the node coordinates
  `x`/`y`/`z` and calls `_p1_element_couples`, and its return signature is unchanged.
- The Hooge source therefore no longer depends on DEVSIM's geometry models. The DC / adjoint fields
  still do, and so do the ii2d element-geometry refusal's premises.
- With `apply_exact_geometry` applied, the refusal passes and the Hooge result is exact on
  non-well-centred meshes (gated above).
- Recorded digests: none moved. No noise digests exist, and the 2-D / 1-D values are unchanged to
  round-off.
