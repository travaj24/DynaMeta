# optics.soa: an opt-in, sourced C-band active material (InGaAsP on InP) (2026-11-08)

Branch `wip/v015_soacband` (from `0554410`, the v0.15.0 tip). User decision 2026-11-08: "I would like
the option to use the SOA for C-band." The L-band default stays exactly as it is; this adds a cited
C-band material next to it.

Source: Vurgaftman, Meyer & Ram-Mohan, "Band parameters for III-V compound semiconductors and their
alloys", J. Appl. Phys. 89, 5815 (2001), DOI 10.1063/1.1368156. Every number below was re-read from
the full text (Tables I, III, IV, VI, XIII; Secs. IV.A.2, V intro, V.B.1). "Measured" means run on
this box against this worktree. "Inferred" is labelled as such.

## Terms

- **Gap (E_g)**: the band gap, the lowest photon energy the material absorbs. Its wavelength
  (1239.84 nm eV / E_g) is the **band edge**.
- **Gain peak**: the wavelength where the material gain is largest. In an injected SOA it sits *above*
  the gap in photon energy (shorter wavelength), because the injected carriers fill the bottom of the
  bands first (**band filling**). Here the shift is 31 meV.
- **Lattice matched**: a layer whose natural lattice constant equals the substrate's (InP), so it grows
  thick without strain. **Vegard's law**: an alloy's lattice constant is the composition-weighted mean
  of its binaries' constants.
- **Q(lambda)**: growers' name for an InGaAsP composition by its *gap* wavelength ("Q1.55" = gap at
  1.55 um). It is not the gain-peak wavelength.
- **Bowing parameter C**: the curvature term of an alloy gap, E_g = (1-z) E_a + z E_b - z(1-z) C.
- **Drift**: how far the gain peak moves per kelvin (nm/K).

## Before this change

The default `BulkGainParams()` is bulk Ga0.47In0.53As (v0.14 correction). It is an L-band medium: its
gain peak is 1612.5 nm at the reference drive. For a C-band device, the v0.14 notes told users to pass a
device-effective Varshni triple (0.816 eV, 2.9e-4 eV/K, 193 K). That triple is `CBAND_GAP` in
`tests/test_soa_qw.py`. It has no source. It is the pre-v0.14 mislabelled InGaAs triple.

## What the paper gives (re-read)

- **Eq. (5.4)**, Sec. V intro: a lattice-matched quaternary is built from two lattice-matched end
  points a and b, each a binary or a ternary: G(z) = (1-z) G_a + z G_b - z(1-z) C_ab.
- **Sec. V.B.1**, GaInAsP lattice matched to InP: (InP)(1-z)(Ga0.47In0.53As)(z), which is
  Ga(x)In(1-x)As(z)P(1-z) with x = 0.47 z. So z is also the As fraction y. The paper says: "We
  recommend using Eq. (5.4) with a bowing parameter of C = 0.13 at all temperatures". For temperature
  it says that "Deducing the temperature variation of the quaternary band gap from the bulk Varshni
  parameters ... is therefore probably a safer procedure" than the two published, mutually
  inconsistent GaInAsP Varshni fits.
- **The end points**: InP (Table VI: 1.4236 eV, 0.363 meV/K, 162 K) and Ga0.47In0.53As (Eq. (4.1)
  over GaAs Table I and InAs Table III, C = 0.477 eV, Table XIII). The code already had both (v0.14).
  The paper quotes 300 K end points of 1.353 eV and 0.737 eV.
- **A typo in the paper (measured).** The printed closed forms are "Eg = 1.4236(1-z) + 0.816z +
  0.13z^2" at 0 K and "1.353(1-z) + 0.737z + 0.13z^2" at 300 K. They drop the -0.13 z part of
  -z(1-z)C. At z = 1 they give 0.946 / 0.867 eV, not the paper's own end points 0.816 / 0.737 eV. At
  z = 0.937 the 300 K form is 121.6 meV too wide. The code follows Eq. (5.4), as the text says to.
- **Lattice constants at 300 K** (the a_lc rows): GaAs 5.65325, InAs 6.0583, GaP 5.4505, InP 5.8697,
  AlAs 5.6611 Angstrom.

## What changed

1. **One gap kernel, extended.** `materials.band_temperature._gap_terms` already evaluated the
   `(A, B, x, C)` closed form for ternaries. It now also accepts an end point that is an
   `ALLOY_GAP_PARAMS` ternary *name*, which is Eq. (5.4). Such a spec flattens to the binaries' Varshni
   terms, with the weights multiplied and the bowings combined. No second Varshni or bowing formula was
   written. The v0.14 ternary branch is untouched.
   - An alloy end point is accepted only if it is lattice matched to the other end point. The test is
     Vegard's law on the new `LATTICE_CONSTANT_300K_A`, with `LATTICE_MATCH_RTOL = 1e-3`. That is 2x
     the worst mismatch among the paper's own named lattice-matched end points: Ga0.51In0.49P/GaAs
     +4.7e-4, Al0.48In0.52As/InP -3.5e-4, Ga0.47In0.53As/InP -3.0e-4.
   - These are refused: `("InGaAs_LM", "InAs", ...)` (3.1 % mismatch; the v0.14 "not a binary" test
     still passes), a quaternary used as an end point, and an end point with no known lattice constant.
2. **New names** (in `materials.band_temperature`, re-exported where the gap law is):
   - `ingaasp_lm_gap_law(z)` returns `("InP", "InGaAs_LM", z, 0.13)`, for any InP-matched GaInAsP layer.
   - `"InGaAsP_LM_C"` in `ALLOY_GAP_PARAMS`: the C-band composition z = `INGAASP_LM_C_Z` = 0.937.
   - `INGAASP_LM_BOWING_EV = 0.13`, `LATTICE_CONSTANT_300K_A`, `LATTICE_MATCH_RTOL`.
   - `ingaasp_lattice_mismatch(z, x_Ga=None)`: Vegard over the four binaries.
   - `ingaasp_lm_gap_law` is also exported from `dynameta.materials` and `dynameta.optics.soa`.
3. **One-line API**: `BulkGainParams.c_band(**overrides)` gives every default except
   `gap_material="InGaAsP_LM_C"`. Gap overrides (`gap_material`, `Eg0_eV`, ...) raise `TypeError`,
   because they would make it a different material. `BulkGainParams()` is unchanged.
4. **The QW path.** `qw_gain` is the only "QW" model, and it is bulk-like: one parabolic joint density
   of states, no subbands, all on `BulkGainParams`. So `c_band()` covers it. The same material key also
   works in the other gap-law consumers:
   - `gain_peak_drift_nm_per_K(lam, "InGaAsP_LM_C")`;
   - `qd_params_at_temperature(material="InGaAsP_LM_C")`, the QD red-shift for a dot in that matrix;
   - the carriers' `BandTemperature("InGaAsP_LM_C", ...)`.

   No quantum-well subband model exists, so nothing here models confinement.

## How z was chosen (measured)

The target is the material-gain peak at **1550.0 nm** at the library's reference operating point:
every other `BulkGainParams` default, 298 K, 130 mA, P = 0, so N0 = 1.6950e24 m^-3. N0 depends only on
the recombination, not on the gap.

1. brentq on z. The peak was located continuously with a bounded scalar maximisation of
   `material_gain_per_m` over the excess energy. This gave z* = 0.93737.
2. Rounded to the 0.001 a grower specifies: **z = 0.937**. One step of 0.001 moves the peak about 1 nm
   (measured: 0.936 -> 1548.66 nm, 0.938 -> 1550.61 nm).

| quantity (z = 0.937) | value |
|---|---|
| composition | Ga0.440 In0.560 As0.937 P0.063 |
| E_g(0 K) / E_g(298 K) / E_g(300 K) | 0.84672 / 0.76906 / 0.76837 eV |
| band edge at 300 K | 1613.6 nm ("Q1.61") |
| dE_g/dT at 300 K | -0.3485 meV/K |
| Vegard mismatch on InP (x = 0.47 z) | -3.50e-4 (exact Vegard match would be x = 0.4353) |
| gain peak - gap at N0 | 31.0 meV |

A "Q1.55" composition (gap at 1.55 um, z = 0.875) would peak at about 1491 nm in this model (measured).
That is outside the C-band, so the preset is named by its gain peak, not by Q.

The fixed-drive drifts used a 10x finer `gain_peak` grid. On the default grid they are 1.007
(`c_band`) and 0.813 (old triple) nm/K. The new device passes every `test_soa_qw` gate, including the
two C-band device gates: 3 (1500-1600 nm, 20-33 dB) and 8 (24-30 dB, BW > 40 nm).

**Against the old triple, only the gap moves.** At equal N and T, g(E_g + x)(E_g + x)^2 is the same
function of the excess energy x for both devices, to 1e-12 relative. The peak moves by the gap
difference to within 0.3 meV (gate `test_c_band_vs_old_triple_moves_only_through_the_gap`). The new
gap is 5.5 meV wider at 298 K, which explains the 10.8 nm blue shift and the ~0.5 dB lower gain. The
old triple's slope (-0.246 meV/K) is 30 % below the sourced alloy law, so its drift was low too.

## Temperature drift against the literature

**Model (measured):**

- The gap alone contributes **0.675 nm/K**.
- At a fixed drive current the peak drifts **1.00 nm/K**. The extra 0.33 nm/K is *inferred* to be
  band filling at fixed N. The model's recombination coefficients do not depend on T, so N0 does not
  fall as T rises, and at fixed N a hotter carrier distribution pulls the peak toward the gap.

**Literature I could read:**

| source | device | measured drift |
|---|---|---|
| Eyal et al., Opt. Express 25, 27262 (2017), abstract via Europe PMC | InAs/InP quantum-dot SOA at 1550 nm, 25-100 C | 0.78 nm/K (peak-gain wavelength) |
| Mao et al., Micromachines 14, 2230 (2023), full text via Europe PMC | InAs/InP quantum-dash SOAs at 1550 nm | 0.77 nm/C (ASE peak); the paper notes this matches Eyal |

Both are InP-substrate 1550 nm SOAs, but neither is bulk InGaAsP. Against them:

- The gap-only drift (0.675) is 13 % below.
- The fixed-current model drift (1.00) is 30 % above.

So the model brackets the measured values but does not reproduce them. A real device's carrier density
falls with T at fixed current (Auger and leakage grow), which offsets part of the band-filling term
this model keeps.

**Not sourced:**

- **No measured bulk-InGaAsP SOA gain-peak drift was read.** Mazzucato et al., IET Optoelectronics
  (2015), "Gain, amplified spontaneous emission and noise figure of bulk InGaAs/InGaAsP/InP SOAs",
  appears in a search-result snippet with a linear band-gap law E_g(300 K) - 3.6e-4 eV/K x dT. That
  is 3 % above this model's -0.3485 meV/K. The publisher page was not readable from here, so this is
  NOT verified.
- The ~0.5-0.6 nm/K for 1550 nm InGaAsP wells in `optics/soa/temperature.py`'s module docstring is
  pre-existing and uncited. It is not used as evidence here.

## Not done / open

- Only the gap changes in `c_band()`. The masses (m_e 0.045, m_dh 0.46), recombination coefficients,
  index and geometry are the module's generic InGaAsP-band defaults. They were not re-derived for this
  composition. Vurgaftman's GaInAsP electron-mass and light-hole rules (Sec. V.B.1) are available if a
  later change wants them.
- No measured bulk-InGaAsP SOA drift was read (see above).
- The 1550 nm target holds at the reference drive only. The peak moves with current (band filling) and
  with T. For a different operating point or target, use `ingaasp_lm_gap_law(z)` with your own z.
- The gap ignores strain. With the paper's x = 0.47 z scheme the layer is -3.5e-4 off InP, which is
  negligible for the gap.

## Release-note lines

- **optics.soa: opt-in C-band SOA material.** `BulkGainParams.c_band()` is an InP-lattice-matched
  Ga0.44In0.56As0.937P0.063 active region (Vurgaftman 2001, Eq. (5.4), C = 0.13 eV). Its gap is
  0.768 eV at 300 K. At the reference drive its gain peak is at 1549.7 nm and its device gain is
  26.2 dB (alpha_i = 3000 /m). The default `BulkGainParams()` (InGaAs, L-band) is unchanged bit for bit.
- **New gap-law names:** `ingaasp_lm_gap_law(z)` (any InP-matched GaInAsP) and the material key
  `"InGaAsP_LM_C"`. `varshni_eg_ev` now accepts a lattice-matched quaternary whose end point is a
  ternary name (Eq. (5.4)), and refuses mismatched end points.
- **Replaces the v0.14 advice** to pass `Eg0_eV=0.816, varshni_alpha_eV_K=2.9e-4,
  varshni_beta_K=193.0` for a C-band device. That triple has no source, and its gap slope is 30 % low.
