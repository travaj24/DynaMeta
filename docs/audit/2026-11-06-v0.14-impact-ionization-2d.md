Branch `wip/v014_ii2d` (from `189c648`, head of `feat/devsim-2.11-v0.14`). Consolidated plan rows 3.2-12 and

## What changed

* **One kernel, 2-D and 3-D.** `impact_ionization._impact_generation_elements_3d` is now
  `_impact_generation_elements` for dim 2 and 3 (components `"xyz"[:dim]`); no 2-D copy. 3-D arithmetic
  is unchanged (same model reads, same order).
* **`quadrature=` on `impact_generation_edges` / `substrate_current`**: `"auto"` (default; 1-D -> `"edge"`,
  2-D/3-D -> `"element"`), `"element"` (2-D/3-D; ValueError in 1-D, DEVSIM has no 1-D element models),
  `"edge"` (1-D/2-D; ValueError in 3-D). The edge branch is the pre-v0.14 code verbatim (measured: the old
  module's default and the new `quadrature="edge"` are bit-identical at 0/30/45/60 deg). The docstrings say
  when `"edge"` is valid: mesh-aligned current only.
* **One shared exact-volume check**, new module `dynameta/carriers/element_geometry.py`:
  `check_element_geometry(device, region, *, caller=None, rtol=1e-9, raise_error=True) -> dict` measures,
  per element, 2 sum(ElementNodeVolume) / true simplex volume (|det|/d!) and raises
  `InexactElementGeometryError` (a `NotImplementedError` subclass carrying `.ratios`) if any element is off
  by more than 1e-9. Returned keys: `dim`, `n_elements`, `volume_ratio` (region total), `max_element_deviation`,
  `max_element_ratio`, `n_inexact`. It replaces the 3-D impact-ionization region-total check (per-element
  is stricter; since sum |piece| >= |sum piece|, DEVSIM's per-element ratio is >= 1 with equality exactly when
  no circumcentric piece is negative, so it is also the well-centredness test). It reads DEVSIM's
  `ElementNodeVolume` as reported, so a geometry correction that replaces those weights with exact ones
  (the concurrent `devsim_geometry.py` work, branch `wip/v014_ecfix`) makes it pass with no change here.
* **Used by**: impact ionization (2-D and 3-D element path), `tunneling.setup_btbt` (2-D/3-D, before any model
  is created), and the Hooge 1/f source (`noise_analysis._hooge_elements`, 2-D/3-D). Diffusion and GR noise
  (edge / node assembled) are not element quantities and are not refused.
* **Docs**: impact_ionization module header (both quadratures, when to use which), tunneling header (BTBT
  refusal), noise_analysis item 3 (Hooge refusal), `reliability/hci.py` stale "2D layered meshes only, the 3D
  tet quadrature is guarded" text (row 3.2-15), D2c doc (2026-11-03-devsim-3d-mesh.md) section 8 item 3
  closed, CI: `tests/test_devsim_element_geometry.py` added to `solvers-devsim`.

## Row 3.2-12: what was wrong, the gates

The 2-D edge form `sum_e alpha(|E_e|)|J_e| c_e L_e` on DEVSIM's tensor mesh (zero-couple hypotenuses, x- and
y-edges each owning the region volume) converges to Int [alpha(|E_x|)|J_x| + alpha(|E_y|)|J_y|] dA, not
Int alpha(|E|)|J| dA. All in `tests/test_impact_ionization.py`; fixtures are 2-D tensor devices whose state is
SET to an exact discrete solution (uniform n, linear or harmonic-quadratic psi: SG current exactly q mu n E_e,
zero discrete divergence), so the gates see only the quadrature.

| gate | oracle | element (new default) | edge (= old code) |
|---|---|---|---|
| U1 uniform field, 0/30/45/60 deg, b_n/E = 4 | alpha(E) J Area closed form | rel <= 7e-16 (bound 1e-12) | 1.000000 / 0.475590 / 0.269744 / 0.475590 of the truth; equals the componentwise closed form to <= 1.3e-15 |
| H1 harmonic psi = V0 (x^2 - y^2)/L^2 on [L,2L]^2 (27-63 deg), n = 10..80 | 400x400 Gauss-Legendre of alpha(\|E\|)\|J\| | order 2.000, Richardson limit 6.1e-10 (bound 1e-6) | order 2.000 to the componentwise integral (limit 7.0e-11), which is 0.359 of the truth |
| U2 laterally uniform 3 V diode, 2-D strip vs 1-D | element == edge on the strip (gate); 1-D edge (check) | == edge exactly (0); 1.7e-8 vs 1-D (SG cancellation noise of the solve, both forms equally) | same |
| R1 / G1 / X1 | ValueErrors; element models cleaned, pre-existing ElectricField_x/y only read (bit-identical); obtuse mesh refused | pass | -- |

Shown failing on the old code (measured): U1 fails the element gate by 0.524 / 0.730 / 0.524 at 30 / 45 / 60
deg; H1 fails the limit gate by 0.641. Adversarial: U1 resolves a 1e-9 change of |E| (5e-9 in I); H1's
x <-> y rotation leaves the element result unchanged to 1e-12.

## Open questions

1. The edge form on a NON-rectilinear 2-D mesh is not refused (decision D3-b: explicit opt-in, no warning);
   its weights EdgeCouple * EdgeLength carry the same unsigned-piece defect there. Documented in the
   docstring ("valid only for mesh-aligned current"), not checked.
2. DEVSIM's own box-method volumes (NodeVolume / EdgeCouple, used by every continuity equation) are equally
   wrong on such meshes; this check guards only the element quantities. The equations themselves are the
   subject of the geometry-correction work (`wip/v014_ecfix`).

## Release-note lines

- carriers: 2-D impact ionization (`impact_ionization.substrate_current` / `impact_generation_edges`) now uses
  the isotropic element quadrature by default (the 3-D kernel). The old 2-D edge quadrature was directional
  (0.27 of the true I_sub for a 45-deg current at b/E = 4); it stays available as `quadrature="edge"`, valid
  only for mesh-aligned current. 2-D I_sub values (and HCI lifetimes computed from them) move.
- carriers: element-based quantities (impact ionization 2-D/3-D, BTBT 2-D/3-D, Hooge 1/f noise) refuse a mesh
  whose element volumes are not exact (`InexactElementGeometryError`, a NotImplementedError; check with
  `element_geometry.check_element_geometry`). Library meshes (2-D rectilinear, 3-D Kuhn tensor) pass; meshes
  with obtuse triangles or non-well-centred tetrahedra (e.g. the deprecated `mesher='gmsh'`) are refused.
