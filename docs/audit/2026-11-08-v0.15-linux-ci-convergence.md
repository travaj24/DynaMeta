# v0.15: three Linux-only DEVSIM convergence failures (2026-11-08)

Branch `wip/v015_lfx_conv` (from `098553f`, the PR #36 tip). The CI `solvers-devsim` leg (ubuntu-latest,
py3.12, OpenBLAS 0.3.26, DEVSIM 2.11.2, `-n 2`) failed on three Newton solves that pass on the Windows dev
box. DEVSIM 2.11.2 with UMFPACK 5.1 on both platforms. Linux = WSL Ubuntu 24.04 with the runner's OpenBLAS
(the recipe in the session scratchpad, `wsl_ci_recipe.md`).

"Measured" means run on this box (Windows, or WSL on the same Ryzen 9 5900XT). "Inferred" says so.

## 0. Summary

| Failure | Mechanism | Fix |
| --- | --- | --- |
| (a) `test_btbt_nonlocal_2d.py` S2: the `slant` child's build fails | Relative test on a potential that is exactly 0 at 25 nodes (Laplace presolve of a symmetric diode) | The presolve's relative test sits above that floor (1e-3, the 1024-ulp margin) |
| (b) `test_isotype_heterojunction_obeys_the_coth_law_under_bias` | Relative test on the circuit's source current, which is round-off at zero bias | `solve_zero_current`: relax only the circuit test and check the device test (1e-5) |
| (c) `test_o7_newton_quality` | A near-singular Jacobian gives a linear Newton tail whose length depends on rounding; the gate compared two such counts | Gate on the sweep total and on the per-iteration contraction rate |

Library: `solve_dc` failure messages now list the circuit and recognise case (a)/(b) (section 4).

**Why Linux and not Windows.** Every count in this note is deterministic for a given OpenBLAS kernel:
1, 2 and 4 OpenBLAS threads give the same Newton histories. The kernel is picked from the CPU at run time
(DYNAMIC_ARCH). WSL on this Ryzen uses the Haswell kernel. `OPENBLAS_CORETYPE=Sandybridge` or `Nehalem`
forces others (SkylakeX needs AVX-512, which this CPU lacks). Windows uses scipy's own OpenBLAS build. The
CI runner's CPU picks a kernel of its own (inferred). Failures (a) and (b) are coin flips at the round-off
floor; the kernel decides the last bits and so the outcome. Failure (c) is a margin of zero. `-n 2` and
xdist ordering play no part: each child scenario runs in a fresh process.

**How to reproduce on one box:** `OPENBLAS_CORETYPE=Sandybridge` (or `Nehalem`) in WSL reproduces (a)
deterministically. The plain WSL run reproduces (b) and (c).

## 1. Common cause of (a) and (b): DEVSIM's relative test on a zero unknown

DEVSIM's relative update per equation is `max_nodes |dx| / (|x| + 1e-10)`. It is ANDed with the absolute
test (`dc_solve.py` module comment). For an unknown with `|x| << 1e-10` it is in effect an absolute test,
`|dx| < relative_error * 1e-10`. When that bound is below the round-off of the converged update, Newton
keeps iterating at that floor. It exits only if a fluctuation happens to dip below the bound. The device
physics has long since converged. Which side the last bits fall on depends on the BLAS kernel and on libm.

## 2. (a) The 2-D slanted diode: the presolve's relative test at psi = 0

**Where.** `tests/_btbt_nonlocal_child.py::build_2d` (also used by `lat2d` and `corner`). Before the coupled
Newton it runs a frozen-carrier Poisson presolve with `absolute_error=1e10, relative_error=1e-8`.

**Mechanism.** The seed is locally neutral (equilibrium_seed_psi with n, p at the intrinsic seed), so
freezing the carriers makes the presolve a **Laplace** problem. psi is linear between the contacts at
+-0.1786 V. On the symmetric slanted diode (+-1e22, 1.2 um) the middle column x = 0.6 um solves to
psi = 0 +- 9e-17 V (25 nodes, measured). With `relative_error = 1e-8`, the test at those nodes is
`|dpsi| < 1e-18 V`. That is 1/100 ulp of the contact potential. The converged update there is
1.3-3.5e-18 V (measured). The `abs = 1e10` test is no constraint on a potential.

Newton history of the presolve (the device relative error; the absolute error is max |dpsi| in V):

| iteration | Haswell (WSL) | Windows | Sandybridge (WSL) | Nehalem (WSL) |
| --- | --- | --- | --- | --- |
| 4 | 1.8e8 (abs 2.5e-2 V) | 1.8e8 | 1.8e8 | 1.8e8 |
| 5 | 6.8e-6 (abs 7.2e-16 V) | 6.7e-6 | 7.2e-6 | 6.4e-6 |
| 6 | **9.4e-9: converged** | 4.7e-8 | 1.7e-8 | 3.0e-8 |
| 7 | | **5.0e-9: converged** | 1.7e-8 | 3.5e-8 |
| 8 .. 100 | | | 1.3e-8 .. 2.8e-8: **Convergence failure** | 2.7e-8 .. 3.0e-8: **failure** |

The Laplace solve has converged at iteration 5 (abs 7e-16 V, from 2.5e-2 V). Iterations 6 onward are
round-off. The WSL serial pass was 7 % under the bound. The lateral Zener (`lat2d`, also symmetric) has the
same column: with the old criterion its presolve took **94 of 100** iterations on Sandybridge and 35 on
Nehalem. It passed by luck.

The coupled Newton that follows is **not** affected. Its doping puts the slant centre on the p side, so no
node solves to 0. It converges in 8 iterations to 1.4-2.5e-14 against 1e-8 on all four kernels.

**Fix.** `build_2d` calls `_poisson_presolve`, which uses `relative_error = PRESOLVE_REL = 1e-3`. The bound
is derived from the floor with the house 1024-ulp margin (`dc_solve.ABS_TOL_ULPS`):
1024 u max|psi| / 1e-10 = 2.1e-4 for the 0.18 V slant, so 1e-3 covers |psi| <= 0.88 V. At that bound the
test is still only the exit test of a quadratically converging Laplace solve. The step that passes it is the
one where max |dpsi| drops from 2.5e-2 to 7e-16 V. The presolve is only the starting point of the coupled
Newton, which keeps its own criteria. `absolute_error` stays at 1e10.

The **first version of this fix** tested the absolute potential update instead (1e-12 V, relative parked
at 1e-3). It broke `test_btbt_nonlocal.py` (the reverse-refusal child): DEVSIM applies ONE
`absolute_error` to every live device, and an earlier, unsolved drift-diffusion device was live, whose
absolute error is a density update. That is the joint-Newton trap of `dc_solve.default_abs_tol`. The
relative bound has no such coupling.

The 1-D Zener (`build_zener`, xj = L/2) also has a psi = 0 node. Its presolve exits at 5.7e-11 against 1e-8
(175x margin, Sandybridge), and its gates are pinned on its exact states (`test_n6_*` budgets are at the FD
noise). It is left unchanged; it is a candidate for the same helper if it ever wanders.

**Margin after the fix (measured).**

Presolve iteration counts of every `build_2d` device the 2-D gates use, old criterion vs new
(`scratchpad/lfx/presolve_probe.py`; FD = the v0.15 default statistics):

| device | Windows old / new | Haswell old / new | Sandybridge old / new | Nehalem old / new |
| --- | --- | --- | --- | --- |
| slant, Boltzmann | 8 / 6 | 7 / 6 | **100 FAIL** / 6 | **100 FAIL** / 6 |
| slant, FD (n_dos 2e21) | 10 / 7 | 16 / 7 | 12 / 7 | 14 / 7 |
| lat2d, Boltzmann | 29 / 11 | 38 / 11 | 94 / 11 | 35 / 11 |
| lat2d, FD | 21 / 11 | 16 / 11 | 21 / 11 | 15 / 11 |
| corner (h 0.5 nm), both statistics | 13 / 13 | 13 / 13 | 13 / 13 | 13 / 13 |

With the new criterion the counts are the same on every kernel. At exit the relative error is <= 3.6e-5
against 1e-3 (28x). It is caught in its quadratic step, not at its floor: the previous iteration is at
1.5e8-1.8e8. max |dpsi| is then 2.5e-16 to 3.6e-15 V. The corner has no psi = 0 node (asymmetric contacts), so it is unchanged.
Its 186 / 290-step FD equilibrium (audit note 2026-11-07, section 10) is the coupled Newton and is not
this mechanism.

Threads and affinity do not matter. On Sandybridge, `OPENBLAS_NUM_THREADS` = 1 or 4, and `taskset -c 0,1`
(two cores, like the runner), give identical counts, old and new: old 94 / 100 FAIL / 21 / 12, new
11 / 6 / 11 / 7. Only the kernel moves the old counts.

## 3. (b) The isotype heterojunction: the circuit's relative test at zero current

**Where.** `validation/devsim_noise.py::dc_conductance(0.0, ...)`, called first in the test. It solves at
-0.1 mV and +0.1 mV, then returns to 0 V with `_solve(ae)` at relative 1e-5. The builder
`hetero_isotype_1d` had already documented the same floor at its own zero-bias solve and used 1e-3 there.
The return solve in `dc_conductance` did not.

**Mechanism.** At V = 0 the source current is round-off (Windows: 9.5e-15 A/m^2). The circuit test is then
`|dI| < 1e-5 x 1e-10 = 1e-15 A/m^2`. The converged |dI| is a few ulp of the interface's one-way stream
J_s = (kT/q) G_0 = 1.6 A/m^2. Measured: 1-7e-15 A/m^2, a circuit relative error of 1.3e-5 to 7e-5. Circuit
relative error at the return solve (the device sits at 4-8e-15 from iteration 3 on):

* Windows: 1e6, 8.0e4, 0.12, 3.0e-5, 3.4e-5, 2.3e-5, 1.3e-5, **9.3e-6: converged at iteration 8**.
* WSL: 1e6, 5.5e4, 0.64, 5.9e-5, 7.3e-5, 4.4e-5, ... then an exact period-4 cycle 5.74e-5 / 4.31e-5 /
  5.33e-5 / 6.75e-5 until the 80th iteration: **Convergence failure**.

**Fix.** `validation/devsim_noise.solve_zero_current(ae, re=1e-5, re_circuit=1e-3)` solves with DEVSIM's one
`relative_error` at 1e-3. That is 14x the worst measured circuit floor. It then **requires the device's
relative error at the accepted iteration to be below 1e-5**. The device criterion is the one the caller
asked for; only the ill-posed circuit test changes. `dc_conductance(..., zero_current=True)` uses it for the
return solve. The test passes that flag. `hetero_isotype_1d` now calls it too: the DEVSIM call is the same
as before, plus the device check.

**Margin (measured, both zero-bias solves of the test: the build, then the return).**

| platform | iterations | circuit rel at exit (vs 1e-3) | device rel at exit (vs 1e-5) |
| --- | --- | --- | --- |
| Windows | 9 / 4 | 1.9e-6 / 3.0e-5 | 3.7e-15 / 5.2e-15 |
| WSL Haswell | 9 / 4 | 4.4e-6 / 5.9e-5 | 3.9e-15 / 7.0e-15 |
| WSL Sandybridge | 9 / 4 | 2.1e-5 / 4.9e-5 | 5.8e-15 / 7.7e-15 |
| WSL Nehalem | 9 / 4 | 2.9e-5 / 8.2e-6 | 6.5e-15 / 6.8e-15 |

**The other zero-bias callers of `dc_conductance`** (gate A resistors) were measured on Sandybridge. Their
circuit floors at exit are 4.3e-14, 8.3e-9, 5.7e-20 and 5.1e-11 against 1e-5, so they have at least 1000x
margin and are left as they were.

## 4. Library: `solve_dc` named neither the circuit nor this cause

`dynameta.carriers.dc_solve.solve_dc` has the same exposure. On WSL,
`solve_dc` of the isotype device at 0 V (default relative 1e-5) fails as follows:

* It runs 60 iterations, then raises "Convergence failure!".
* Its list "unconverged at the last iteration" is **empty**: `_unconverged` never looked at the circuit.
* The stall branch appends the dense-SVD diagnosis "DC Jacobian conditioning (5.3e-09): mode in Holes",
  which points at the wrong cause.

A user at an equilibrium bias with a circuit contact gets this misdiagnosis.

Changes (only the failure path; every converged solve is unchanged):

* `_unmet_tests` lists every unmet test, **including the circuit**.
* An entry whose absolute test passed is tagged when `|x| <= abs/rel - 1e-10 <= 1e-10` is provable at its
  worst node. Such an entry is a relative test on a ~0 unknown.
* When every unmet test is of that kind, the message carries `ZERO_UNKNOWN_NOTE`, which states the
  cause and the remedies, and skips the SVD.
* A conditioning stall (`test_well_posedness`' MOS) is not of that kind and keeps its diagnosis.

There is no automatic acceptance. DEVSIM restores the pre-solve state on failure, and accepting a relative
test the caller asked for is the caller's decision.

Gates (in `tests/test_devsim_noise_thermionic.py`):

* `test_zero_current_circuit_floor_is_named_not_blamed_on_the_jacobian`: the isotype device at 0 V, run at
  relative 1e-12 so that it fails deterministically on every platform. The test requires:
  * the circuit is the only unmet entry, and it is tagged;
  * the note is present and no SVD ran;
  * `solve_zero_current` then converges the device to below 1e-5.

  OLD CODE: IndexError, because the list was empty.
* `test_unmet_tests_bounds_the_unknown_only_when_it_is_provably_zero`: the bound on DEVSIM-shaped info:
  * the presolve's psi = 0 case is tagged;
  * an ordinary unconverged potential and an unmet absolute test are not tagged.

## 5. (c) O7: an iteration-count gate on a near-singular Newton

**Where.** `tests/test_devsim_oxide_tunneling_sc.py::test_o7_newton_quality` (b). The O4 deep-depletion sweep
of p-Si, 0.1 to 3 V. The gate asserted per step: iterations with the tunnelling term <= iterations without it
plus 3. The no-term reference uses tau = 1e-12, the only tau at which it converges.

**Mechanism.**

* With the term, the sink IS the interface node's electron balance. The inversion-layer electrons
  (x > 1450 nm) are pinned only by SRH generation and the sink. The equilibrated sigma_min/sigma_max is
  <= 4.4e-16 at 0.3, 1.0 and 3.0 V (measured with `well_posedness`).
* So the Newton tail is **linear**, not quadratic. Each step leaves a fraction ~kappa u of the error along
  that mode.
* For example, at 0.3 V on WSL the tail is 6.0e-4, 2.6e-5, 1.4e-6, 5.2e-8, 2.1e-9, 8.9e-11, 2.3e-12: a steady
  ~0.04 per iteration. On Windows the same tail runs at 0.01-0.03.
* The rate and the count are set by rounding and differ by kernel. They are deterministic per kernel.
* The O6 Jacobian check is exact: the term's Jacobian matches central differences at 2 V. So this is
  conditioning, not a Jacobian error.

| kernel | count at 0.3 V, on / off | max per-step (on - off) | sum on / sum off | max contraction from 1e-2 |
| --- | --- | --- | --- | --- |
| Windows | 16 / 13 | +3 (pass, zero margin) | 364 / 524 | 0.070 |
| WSL Haswell | 17 / 13 | **+4 (fail)** | 369 / 517 | 0.075 |
| WSL Sandybridge | 15 / 13 | +2 | 362 / 504 | 0.078 |
| WSL Nehalem | 14 / 13 | +3 | 362 / 554 | 0.081 |

The reference is near-singular too at 1.0-3.0 V. Its count at 0.6 V is 12 / 26 / 12 / 49 iterations on the
four kernels. A per-step difference of two rounding-set counts measures neither the term nor its Jacobian.

**Fix.** The (b) gate now asserts, on quantities the rounding does not move:

1. every step of both sweeps converges (unchanged);
2. the sweep with the term needs no more iterations **in total** than without it (measured 0.65-0.72 of it);
3. at every step the relative error contracts monotonically from 1e-2 to convergence by **<= 0.2 per
   iteration**. That is 2.5x the worst measured 0.081 (the near-singular mode's linear rate). A Jacobian
   error delta along the converging direction shows up as a linear rate ~delta, so this bounds it.

The refutation is stronger than before. With the n_s column halved, the 0.3 V step still converges, but its
error contracts by only 0.32-0.46 per iteration. That fails (3); `w[-2]` is now asserted to fail it. The
Newton then fails at 0.4 V as before. Part (a) (accumulation: identical counts and quadratic convergence) is
unchanged.
