### Public API

```python
from dynameta.optics.lumenairy_bridge import make_lumenairy_pmm_solver, design_to_pmm_stack

solver = make_lumenairy_pmm_solver(
    degree=16, n_orders=21,                       # n_orders -> PMMStack(far_field_orders=)
    lateral_partition="auto",                     # or a sequence of edge fractions, or None (refuse)
    partition_rtol=0.1, max_segments=24,          # adaptive partition controls
    lateral_average="auto",                       # 'auto' | 'laminate' | 'arithmetic'
    z_average="auto",                             # 'auto' | 'laminate' | 'arithmetic'
    z_merge_rtol="auto",                          # 'auto' | None | float
    pmm_kwargs={"elements_per_region": 3},        # forwarded to PMMStack
)
res = solver(design, None, {"film": eps_field}, 1200e-9, None, None)   # OpticalResult
solver.native_carrier_grid        # True: run_pipeline hands it the carrier solve's native z grid
stack, names = design_to_pmm_stack(design, 1200e-9, eps_by_region={"film": eps_field})
stack.dynameta_partition_report["film"]          # e.g. (illustrative values)
# {'n_segments': 13, 'max_spread': 0.094, 'converged': True, 'capped': False, 'n_slabs': 40,
#  'n_layers': 15, 'z_merge_rtol': 0.03, 'lateral_average': 'auto', 'z_average': 'laminate',
#  'edges': (0.0, ..., 1.0)}
```

`eps_field` may be a y-invariant gridded EpsField varying along x (axes in nm, any of the usual x
grids: endpoint-inclusive, endpoint-exclusive, cell-centred -- all read as the periodic
piecewise-linear interpolant of the samples). Gridded tensor fields and fields varying along y
still raise.

### How a gridded layer becomes PMM layers

1. `slice_layer_eps_field(ef, L, 1/S, n_slices=...)`: one slab per native z interval (non-uniform
   grids consumed as they are), the slab-thickness guard.
2. Laterally uniform field: one uniform PMM layer per slab, eps = the endpoint average -- the
   v0.15.1 construction, bit for bit, unless `z_average` / `z_merge_rtol` are set. No lateral
   averaging is ever involved, also under a patterned layer.
3. Laterally structured field:
   * z: each native interval is a z-laminate, diag(arith, arith, harm) of the z-linear interpolant
     (`z_average='auto'` -> 'laminate'; 'arithmetic' when `n_slices` is set);
   * x: one partition per layer for all its slabs, seeded with every wall the other layers own
     (and the partitions of structured layers built before it), refined while the spread
     max|eps - mean| / max(|mean|, 1) of any slab exceeds `partition_rtol`, each cut placed at
     the sample minimizing a two-piece constant misfit, up to `max_segments` (minimum width
     P/4096); the AdvisoryWarning fires when an 'auto' partition stops above the tolerance;
   * per interval: E_x sees the harmonic mean when the profile's domains in the interval are
     narrower than the layer thickness, else the arithmetic one (`lateral_average='auto'`); E_y
     the arithmetic one; E_z the arithmetic one of the z-harmonic column means;
   * consecutive slabs whose components agree within `z_merge_rtol` (auto 3e-2) merge as a
     z-laminate (xx, yy thickness-weighted arithmetic; zz harmonic).
   Seeding with the other layers' walls means a partition wall is always co-owned with any wall
   it lies close to, so lumenairy's cross-layer wall snap (and its UserWarning) never fires.

### pmm_kwargs (version tolerant)

Forwarded verbatim to `PMMStack`. Refused with ValueError: the keys the bridge sets (`period`,
`degree`, `far_field_orders`, `n_orders`, `n_substrate`, `n_superstrate`, `layer_grids`). Checked
against the INSTALLED `PMMStack.__init__` signature: an unknown key raises
`LumenairyFeatureUnavailable` listing the accepted keys and, where known, the release that adds it
(`window_halfwidth`: 5.33.0). `grade` other than a bool raises below 5.51.0 (naming 5.51.0): older
releases coerce `grade` with bool(), so `grade='geometric'` would silently be read as `True`.
Nothing about the 5.51 grading itself is relied on; the value is passed through when the
installed release is >= 5.51.0.

## Measured

The test cell is the strip cell of tests/_strip_cell_fixture (400 nm period, 40 nm metal strip of
150 nm, eps -60+4i, 2 nm oxA / 6 nm oxB / 6 nm Drude film / 6 nm oxB / 2 nm oxA on an 80 nm mirror
metal, glass, 1200 nm, TM). The numbers the tests measure on it are given below; the exploratory
studies of this package (cost per layer, z-sampling of a crossing profile, partition_rtol sweeps of a
moderate and a crossing profile, the degree ladder) were made on a different cell: their conclusions
are kept, their numbers are not quoted.

### Cost of a PMM layer

Every layer of the stack (structured or not) pays an eigensolve on the union of all walls; the cost
grows steeply with the union segment count and the degree (0.05 / 0.27 / 1.7 s per layer at 8 / 16 /
32 segments, degree 16; pmm_backend docstring). This sets the defaults: `max_segments=24`, and the z merge for structured fields.

### Laterally uniform graded film under the strip (the v0.15.1 path)

On a profile crossing Re eps = 0 near the top face, the default arithmetic staircase converges in
the z sample count about twice as slowly as `z_average='laminate'`, and the z merge (3e-2) keeps the
accuracy at a fraction of the layers. The defaults
keep this path bit-identical to v0.15.1; `z_average='laminate', z_merge_rtol=3e-2` is both more
accurate and several times faster and is recommended in the docstring (switching the default is an
owner decision). Against the FEM (`fem_2d_tm`, which uses the z-linear interpolant) the remaining gap
of the z-converged PMM is its algebraic TM corner convergence in the degree, not the bridge.

Test fixture (accumulation-only profile, 41 samples, `uniform_field` in the test): FEM order 4
0.354238-0.147728i; default bridge path, degree 16, 3 elements per region: abs(dr) 3.8e-3 (fast gate
4e-3; the plain cell's PMM corner error at that setting is 4.4e-3 against R_FEM_CONVERGED, the
staircase 2.5e-4). Slow gate, degree 16, laminate z + merge, elements_per_region 3 / 6 / 8: 3.7e-3 /
6.6e-4 / 2.4e-4 against FEM order 5 (gate: monotone, < 6e-4).

### Laterally varying film (two z profiles joined by 20 nm ramps at the strip edges)

41 uniform z x 200 x samples; FEM on the same samples (bilinear interpolant). Test fixture of the
slow gate (accumulation-only profiles): partition_rtol 0.5 / 0.2 / 0.1 at degree 10 -> steps 3.5e-2,
1.3e-2; the 0.1 result is 1.5e-3 from the FEM (order 5). The partition converges as partition_rtol
falls, the balanced cut needs about half the segments of midpoint bisection, and a profile crossing
Re eps = 0 under the strip can stop at the default cap (and warns). The partition walls near the strip corners also h-refine the PMM there, which
is why the structured solves sit closer to the FEM than the laterally uniform ones at equal degree.

### Which lateral mean: the aspect-ratio rule (correction to the plan)

Planar stack (no metal corner, degree 12 converged), sixteen 25 nm lamellae of eps 2.72 / 1.69 (the
generic film at 1 and 1.8 times its density), one segment for the whole period against the resolved
solve, TM:

| film | laminate (harmonic E_x) | arithmetic |
|---|---|---|
| 6 nm | 1.25e-4 | 4.5e-5 |
| 50 nm | 1.10e-3 | 4.38e-3 |

(TE, E along the lamellae: both means give the same r to 1e-13, 2.2e-7 / 1.9e-5 from the resolved solve
at 6 / 50 nm.) In a film thinner
than its lateral domains E_x is pinned by tangential continuity with the layers above and below and
sees the arithmetic mean; the laminate (harmonic) average is right only for domains narrower than the
layer. `lateral_average='auto'` applies that rule per interval (domain size = interval width / (1 +
mean crossings)); it picks the closer column in every row above.

### x-axis coverage guard

A structured field whose x samples span less than half the period raises (e.g. x in metres: "x
samples span ... of the 4e-07 m period (< half) (ratio ~1e-9: the x axis looks like it is in METRES
where nm are read)"), the lateral counterpart of the slab-thickness z guard.

### Exactness and limits

* Kernel: constant intervals exact to 1e-14 (summation round-off, 4.4e-15 measured); a linear ramp
  interval equals (a+b)/2 and (b-a)/log(b/a) to 5e-14; the harmonic piece matches scipy quadrature
  to 1e-12 (incl. a lossy pass near zero and a metal/dielectric pair); three x-grid conventions of
  one interpolant agree to 1e-14.
* Hand-built stack: an explicit partition on the ramp ends reproduces the hand-built segment stack
  with segment values to 4e-14 and widths to 1e-16; the solved results agree within the gate's 5e-9
  (the PMM solve's own round-off amplification on such a cell: perturbing the hand-built eps by 1e-14
  relative moved R by 2-3e-10 on a lamellar test cell). The plan's "to 1e-12" is not reachable for any
  construction.
* Sharp-step limit on shared walls: ramps of 4 / 2 / 1 nm vs the sharp switch: 4.04e-4 / 1.33e-4 /
  4.20e-5 (ratios 3.05 / 3.15 per halving; the gate asks for > 1.6 and < 2e-4 at 1 nm).
* `pmm_kwargs={'elements_per_region': 3}` vs a direct `PMMStack(..., elements_per_region=3)`: bit for
  bit on the generic cell (W / P = 3/8 is exact in binary; where strip widths differ by ulps the
  difference was 3.1e-13 in R); the knob moves r by > 1e-4.

## Plan statements found wrong or incomplete

1. **Laminate everywhere (O1).** The harmonic E_x average is right for lateral domains narrower
   than the layer, not for a thin film under wider domains (table above: 2.8x worse than the
   arithmetic mean on a 6 nm film). Implemented as the aspect-ratio rule ('auto'); 'laminate' and
   'arithmetic' remain selectable. "The laminate converges faster than 'arithmetic'" did not hold
   on the ramped film: with a resolving partition both agree to 4e-6.
2. **Defaults partition_rtol=1e-2, max_segments=32.** With a linear ramp, a 1e-2 spread needs ~125
   segments (always capped) and 32 segments cost ~3.8 s per PMM layer at degree 16 on 5.50.2.
   Defaults are 0.1 / 24 (2.5e-4 from the FEM at 13 segments on the moderate film). The spread is
   taken relative to max(|mean|, 1) (see above), and cuts are placed where the profile varies
   rather than at midpoints.
3. **"For a z-varying layer under laterally structured layers"**: no lateral averaging is needed;
   the bridge keeps it exact (step 2 above).
4. **z treatment.** The plan did not cover the z direction. An arithmetic staircase on a profile
   through Re eps = 0 is 12x less accurate at 41 samples than the z-laminate slab; and slicing a
   native carrier grid (~190 nodes across a few-nm film) into one PMM layer per interval multiplies
   the cost. Added `z_average` and `z_merge_rtol` (structured default laminate + 3e-2; laterally
   uniform default unchanged for bit-identity).
5. **Hand-built to 1e-12, `pmm_kwargs` to 1e-14.** Below the PMM solve's round-off amplification on
   these cells (measured above); gates use 5e-9 / 1e-11 with the measurement in the docstring.
6. **The plan's exact two-value lamellar test.** A sampled field is a piecewise-linear interpolant,
   so a sharp step is not representable; the gates instead use (a) an explicit partition on the
   ramp ends against closed-form segment values and (b) the sharp-step limit on shared walls.
7. **ci.yml** gains one test-file line (rule 7; the census test requires it; P15 unions).
8. **Lumenairy floor leg (5.22).** Not run: installing 5.22 needs the network, which this task
   forbids. Read from the v5.22.0 tag: `PMMStack(far_field_orders=, elements_per_region=, grade=,
   factorization=, min_feature=)` all exist there; `window_halfwidth` arrived in 5.33.0 and
   `layer_grids` in 5.32.0 (both version-gated). 5.22-5.50.0 solve the lateral mirror image of every
   patterned layer (fixed in 5.50.1): the strip fixtures here are mirror-symmetric, so unaffected;
   an asymmetric lateral profile through the PMM bridge needs lumenairy >= 5.50.1.

## Left undone / uncertain

* The spread criterion is a proxy; the true partition error depends on where the field is strong
  (near the strip corners). On a profile through Re eps = 0 the default stops at the cap (warns).
* The aspect-ratio rule is a two-limit switch (harmonic below, arithmetic above the layer
  thickness); between the limits neither mean is exact. It only matters for partitions that do not
  resolve the variation.
* `lateral_average`/`z_average` choose per interval / per slab; no off-diagonal (xz) terms are
  formed, so a profile varying along a slanted direction is approximated by its axis-aligned means.
* Bitwise gates were run on this workstation only (rule 2: confirm on CI).

## Gain media (added with the v0.16.0 release fixes)

lumenairy 5.50.x splits the modes of a gain layer (Im eps < 0) in a PMMStack wrongly: the growing root of
every evanescent gain mode enters the layer propagator and R + T reads 1e1 .. 1e4 (strip cell with the
strips made eps 2.25 - 0.05i, degree 16: R = 6448 on 5.50.2; the 2-D TM FEM gives r =
-0.64131547-0.74579539i, R = 0.9675). lumenairy 5.22.0 and 5.51.0 (fe408f0a) are right: 5.5e-7 from the FEM
at degree 16. No API marks the fix, so the bridge decides it by a probe solve (feature row
'pmm_gain_media': a gain ridge, PMMStack degree 14 against RCWAStack 'li' at 40 orders on the zeroth-order
Jones; 1.8e-4 where right, 1.83 on 5.50.2, threshold 1e-2), run only when a layer holds a gain medium.
Where the probe fails, design_to_pmm_stack and the differentiable PMM forward refuse the gain layer
(LumenairyFeatureUnavailable naming the layer). The RCWA and PMM2D bridges solve gain layers correctly on
all three releases (3.1e-7 / 2.6e-4 from the FEM). A gain half-space is refused by every engine on every
release: PMMStack dropped the transmitted power (T = 0) on 5.22.0 / 5.50.2, PMM2DStackHybrid returned
R = 30, RCWAStack raised an energy error. Gates: tests/test_lumenairy_feature_detection.py.
