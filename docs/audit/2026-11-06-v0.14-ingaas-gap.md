# InGaAs band gap in optics.soa: Vurgaftman alloy rule, not a Varshni triple (2026-11-06)

Branch `wip/v014_ingaas` (from `189c648`, head of `feat/devsim-2.11-v0.14`). Row 3.2-14 of
`docs/plans/2026-11-04-devsim-v0.15/00_consolidated_plan.md`; the user chose to fix it in v0.14.0.
Source: Vurgaftman, Meyer & Ram-Mohan, J. Appl. Phys. 89, 5815 (2001). Every table value below was
re-read from the full text. "Measured" means run on this box against this worktree; "inferred" says so.

## What was wrong

`optics/soa/temperature.py` had `VARSHNI_PARAMS["InGaAs_LM"] = (0.816 eV, 2.9e-4 eV/K, 193 K)`, and
`optics/soa/qw_gain.BulkGainParams` used the same three numbers as its default gap. Both said they
were the Vurgaftman "Varshni row for In0.53Ga0.47As". The paper has no such row. It gives Varshni
parameters only for binaries (Tables I-IX). An alloy is built with Eq. (4.1),
`Eg(A(1-x)B(x)) = (1-x) Eg(A) + x Eg(B) - x(1-x) C`, from the two binary Varshni laws. For GaInAs the
paper takes the bowing to be temperature-independent (Sec. IV.A.2) and sets C = 0.477 eV (Table XIII)
from its composite Eg(0) = 816 meV at x = 0.53.

| T (K) | Vurgaftman alloy rule (eV) | old triple (eV) | old - new (meV) |
|---|---|---|---|
| 0   | 0.816119 | 0.816000 | -0.12 |
| 77  | 0.805658 | 0.809632 | +3.97 |
| 300 | 0.737257 | 0.763059 | +25.80 |
| 400 | 0.701351 | 0.737754 | +36.40 |

The slope at 300 K was -0.2456 meV/K against the alloy rule's -0.3505 meV/K, so it was 30 % low
(all measured). The paper quotes Eg(300 K) = 0.737 eV for this alloy itself, as the end point of the
InP-lattice-matched GaInAsP law in Sec. V.B.1. It quotes no measured room-temperature value: it says
only that a temperature-dependent C would put the room-temperature gap "higher than nearly all
experimental values" (refs 438, 439, 443). These checks pass:
- Eg(0) = 816 meV (Sec. IV.A.2) and Eg(300) = 0.737 eV (Sec. V.B.1), to within 0.5 meV of the
  rounded values.
- The InP row gives the paper's own InP 300 K end point of 1.353 eV.

**Composition.** The module uses x(In) = 0.53, which is the paper's composition. Vegard's law on the
paper's 300 K lattice constants (GaAs 5.65325, InAs 6.0583, InP 5.8697 Angstrom) gives an exact
lattice match at x = 0.534. That would lower the gap by about 4.6 meV (inferred, from dEg/dx = -1.04 eV
at 300 K). x = 0.53 was kept, because it is the composition at which the paper fixes C.

**Other rows.** The GaAs (Table I), InAs (Table III) and InP (Table VI) rows match the paper exactly.
`InGaAs_LM` was the only alloy entry in the table. No InGaAsP entry exists anywhere in the code.
Two places carry the old numbers and are flagged here but not changed:
- `docs/plans/.../P1_tunneling.md` (the BTBT Kane-B planning row) quotes the old 0.763 eV.
- The frozen vendor copy at `Fiber_Amplifiers/price_of_gain_report/vendor/DynaMeta` still has the old
  code.

The SAT56 study scripts do not import `optics.soa`. A grep of `Fiber_Amplifiers/` outside `vendor/`
for `optics.soa`, `qw_gain` and `varshni` found nothing.

## What changed

* **One gap law.** `temperature.varshni_eg_ev(T, material)` is the one Eg(T) kernel in
  `optics.soa`, and `d_eg_dT_ev_per_K` is its analytic slope. A material can be any of:
  - a binary (`VARSHNI_PARAMS`: GaAs, InAs, InP);
  - a custom `(Eg0, alpha, beta)` triple;
  - a ternary (`ALLOY_GAP_PARAMS["InGaAs_LM"] = ("GaAs", "InAs", 0.53, 0.477)`);
  - a custom `(A, B, x, C_eV)` tuple, evaluated with Eq. (4.1).

  Binaries and custom triples give the same bits as before: one term of weight 1.0 and a zero offset.
  `"InGaAs_LM"` was removed from `VARSHNI_PARAMS`, because an alloy has no Varshni row. The name
  `"InGaAs_LM"` is still accepted everywhere a material is passed.
* **qw_gain uses that kernel.** `band_edge_Eg_J` calls `varshni_eg_ev(T, params.gap_law)`, so the
  duplicate inline Varshni formula is gone. `BulkGainParams` gains `gap_material` (default
  `"InGaAs_LM"`), added as the last field so positional order is unchanged. `Eg0_eV`,
  `varshni_alpha_eV_K` and `varshni_beta_K` now default to `None` and act as an optional
  device-effective override. The override is all-or-nothing: setting one or two of the three raises
  `ValueError`.
* **The SOA device gates run on an explicit C-band device.** Gates 3 and 8 in `tests/test_soa_qw.py`
  check a 1500-1600 nm peak and a BOA1004P-class gain. Both are statements about a 1550 nm-band
  active region, so they now run on `CBAND_GAP`, the old triple passed as an explicit override. It is
  labelled as device-effective, not as a material law, and its numbers are unchanged. Gates 1, 2 and
  4-7 do not depend on the material, so they are parametrized over both the C-band device and the
  new InGaAs default.

## What moved (measured; `BulkGainParams()` default, 130 mA, 600 um, P = 0)

| quantity | before (old triple) | after (Ga0.47In0.53As) |
|---|---|---|
| Eg(298 K) | 0.763550 eV | 0.737957 eV (-25.59 meV) |
| gain peak at N0 = 1.695e24 m^-3 | 1560.4 nm | 1612.5 nm (+52.1 nm; d(h nu) = -25.65 meV) |
| peak material gain | 4.415e4 /m | 4.714e4 /m |
| device gain, alpha_i = 3000 /m (gate 3) | 26.69 dB | 29.03 dB |
| device gain, alpha_i = 2500 /m (gate 8) | 28.00 dB | 30.33 dB |
| net -3 dB bandwidth, alpha_i = 2500 /m | 50.1 nm | 51.6 nm |
| Psat_out (gate 4) | 7.01 dBm | 6.70 dBm |
| NF (gate 7) | 5.05 dB | 4.97 dB |
| N_tr at the 2e24 peak (gate 1) | 1.2210e24 | 1.2194e24 |
| 298 -> 338 K peak-gain drop / red-shift (gate 6) | 29.6 % / 33.1 nm | 28.7 % / 44.8 nm |
| `gain_peak_drift_nm_per_K(1550, "InGaAs_LM")` | 0.476 nm/K | 0.679 nm/K |

The carrier density does not move: N0 = 1.695e24 depends only on recombination. A Ga0.47In0.53As
bulk active region is an L-band gain medium, so the default device now fails both 1550 nm device
windows: its peak is 1612.5 nm against the 1500-1600 nm window, and its gain at alpha_i = 2500 /m is
30.33 dB against the 24-30 dB window. That is why those two gates use the explicit C-band device. To
model a 1550 nm device, pass a device-effective Varshni override or a gap from a quaternary law
(**v0.15.1:** done -- `BulkGainParams.c_band()`, `docs/audit/2026-11-08-v0.15-soa-cband.md`). A
GaInAsP-on-InP quaternary (Sec. V.B.1, Eq. (5.4), C = 0.13 eV) was not added, because choosing its
composition needs a device source that is not in hand (Connelly 2001's y is from memory only).

**Cross-check that only the gap changed.** At equal N and T, `g(Eg + x) (Eg + x)^2` is the same
function of the excess energy x for the old and new gaps (Connelly form). It agrees to 4.4e-16
relative, against a budget of 1e-12. The measured peak shift (-25.65 meV) equals ΔEg (-25.59 meV)
to within 0.07 meV, against a 0.3 meV budget from the grid step plus the 1/nu^2 tilt. No digest or
pin recorded these numbers. The `test_soa_qw` windows are physics windows, not pins, and none was
changed.

## Gates (new: `tests/test_soa_ingaas_gap_vurgaftman.py`, 10 tests)

The independent oracle is the Table I/III/VI/XIII values re-typed in the test, with Eq. (4.1)
evaluated in the test at 0, 77, 300 and 400 K. The tolerance is 1e-13 eV: at most about 20 double
operations on O(1 eV) terms give about 7e-15 eV. The values the paper quotes are checked to 0.5 meV.
The tests also cover:
- the slope against a central difference of the oracle (rel 1e-8);
- the `BulkGainParams` default gap and the all-or-nothing override;
- the scaling-identity and peak-shift cross-check above.

**On the old code, all 10 fail (measured).** The four T-gates miss by -0.12, 3.97, 25.80 and
36.40 meV; the 300 K quoted value misses by 26.06 meV; the rest fail on the old API.

**Adversarial checks.** These perturbations each break a gate:
- In the test: swapping the composition (x = 0.47) moves the gap 62 meV, and Paul et al.'s
  C = 0.475 eV moves it 0.50 meV. Both are far above the 1e-13 eV tolerance.
- Run by hand on the scaling identity: m_e x 1.001 gives a 0.28 relative deviation, and
  n_index x 1.0001 gives 2.0e-4. Both break the 1e-12 tolerance.

## Release-note lines

- **optics.soa: the In0.53Ga0.47As band gap now follows Vurgaftman et al. (2001).** It uses Eq. (4.1)
  over the GaAs and InAs Varshni laws with C = 0.477 eV, replacing an uncited Varshni triple. The
  300 K gap is 26 meV narrower, at 0.737 eV.
- **`BulkGainParams()` moves to the L-band.** It now uses that gap, so the default bulk device's gain
  peak moves from 1560 to 1612 nm and its 130 mA gain rises by 2.3 dB. For a 1550 nm device, pass
  `Eg0_eV`, `varshni_alpha_eV_K` and `varshni_beta_K` together. (Superseded in v0.15.1: use
  `BulkGainParams.c_band()`, a sourced InGaAsP-on-InP material.)
- **API change:** `VARSHNI_PARAMS["InGaAs_LM"]` is removed; use `ALLOY_GAP_PARAMS`. The
  `"InGaAs_LM"` material name still works everywhere, and custom `(A, B, x, C)` ternaries are
  accepted.
