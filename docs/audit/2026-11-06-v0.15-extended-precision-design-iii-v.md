**Precedence.** An explicit builder argument wins. ONE `AdvisoryWarning` is raised when it contradicts a
value the design **states** (True vs False, either way). `CarrierSpec.extended_precision` is tri-state:
None means "not stated" (off). This keeps the v0.14 call `LayeredDevsimBuilder(design,
extended_precision=True)` on a default design silent. That call exists in `test_extended_precision.py`,
which runs under warnings-as-errors. Interpretation note: the brief says "one advisory if the two
disagree". A default (unstated) design does not count as disagreeing. A design that explicitly says
`CarrierSpec(extended_precision=False)` does disagree with an explicit `True`, and that warns.

**Rejected placements** (CarrierSpec docstring):
- On `Mesh2DSpec`: the 3-D builder would then read a "2-D mesh" setting.
- Per material (`TransportModel`): DEVSIM solves all regions of a device in one Newton, and
  mixed-precision regions in one Newton have no gate.

**Process-global DEVSIM state (handled and documented).**
- The opt-in is device-scoped: device-level `extended_model` / `extended_equation`, cleared with the
  device. DEVSIM's `extended_solver` is global, and DEVSIM solves every live device in one Newton.
  DynaMeta sets the flag only for the duration of each `XP.solve`, and only if some live device opted
  in.
- Two designs that disagree, alive side by side in one process: the default device is solved by the
  extended Newton too. Every such solve raises the existing mixed-devices `AdvisoryWarning`, which
  names both devices. MEASURED: 3 warnings over the 3 solves of a 0 V bipolar solve.
- `LayeredDevsimBuilder.teardown()` deletes **every** DEVSIM device and mesh in the process, not only
  its own. This is gated and documented as a trap.
- Designs run one after another are independent, because `run_pipeline` tears its builder down after
  the carrier sweep. This is gated bitwise (E3).
- Custom terms: the extended Newton converges linearly (plan 5.9, decision 8). This is stated in the
  CarrierSpec docstring.

### Findings

1. **The Auger split is ambiguous in the literature (finding).** Shipping C_n = C_p = 3.5e-30 cm^6/s reads
   Strauss's C_eff as the ambipolar **sum**: at n = p, U = (C_n + C_p) n^3 = C_eff n^3. A secondary user
   reads it differently: Sachenko, Kostylyov, Sokolovskyi & Shkrebtii (arXiv preprint 2026, GaAs
   solar-cell model, Eq. (18), Ref. [28] = Strauss 1993) uses C_e = C_h = 7e-30 **each**, which is 2x our
   sum. The +/-4 (57 %) does not decide between the two readings. Shipped as decided (equal split). It
   is labelled `verification="secondary"`, and the locator says the sum reading is assumed.
2. **InP 1.2e-10 is an extrapolation.** Semyonov's fit covers n = 2-8e18 cm^-3, and 1.2e-10 is its n -> 0
   intercept (Eq. (6) gives 0.98e-10 at 2e18). The roll-off is documented, not modelled. InP Auger is not
   shipped.
3. Strauss also quotes B = 1.7 +/- 0.2e-10 for its structure. This value is not shipped: it depends on
   the structure, and whether it is internal or effective is not stated in the abstract.

## Release-note lines

- **Extended precision from the design (new, opt-in):** `Design(..., carriers=CarrierSpec(extended_precision=True))`
  runs the carrier solve in DEVSIM 128-bit precision, including through `run_pipeline`. An explicit
  builder argument still wins, with one advisory if it contradicts the design. Default off is
  byte-identical (7/7 cross-commit fingerprints). A GaN-like 2-D diode current matches the
  Sah-Noyce-Shockley oracle to < 1e-3, against 1e4-1e12x off in double.
- **III-V recombination presets (new, opt-in):** GaAs B_int = 3.3e-10 cm^3/s (Niemeyer 2019), GaAs Auger
  C_n = C_p = 3.5e-30 cm^6/s (Strauss 1993 ambipolar 7 +/- 4e-30, split equally; secondary source), and
  InP B_int = 1.2e-10 cm^3/s (Semyonov 2010), in `materials.semiconductor_presets`. All B presets are
  INTERNAL. Apply the layer's photon recycling once with `preset.with_photon_recycling(P_r)` (B_eff =
  B_int (1 - P_r); 4.2x smaller for a 2 um GaAs DH). Without it, a one-time advisory says recycling is
  ignored.
- **`RadiativeModel.kind` / `photon_recycling_factor`:** label any radiative coefficient as internal or
  effective. Adding a recycling factor to an effective B is refused, because recycling would be counted
  twice.
