# v0.15 band-temperature model (2026-11-06): Varshni E_g(T) anchored at T_ref, chi(T) by a required fraction, derived n_i(T)

Branch `wip/v015_bandT` (from integration commit `cc0bdf0`, which carries every v0.14 fix including the
temperature fixes and the InGaAs gap fix). DEVSIM 2.11.2, Python 3.14, box A. Plan item 4.3.3 of
`docs/plans/2026-11-04-devsim-v0.15/00_consolidated_plan.md` (P3 item 3, H2), with decisions 32 (anchored
Varshni), 46 (chi fraction required, no default) and plan sections 4.0.4 (one Varshni kernel) and 5.2-5.4.
Gates: `tests/test_band_temperature.py` (devsim-free, 10 tests) and `tests/test_devsim_band_temperature.py`

extracted with `git archive` (with the new test files dropped in). Everything else is labelled.

## What changed

* **One gap law for the package** (plan 4.0.4). `dynameta/materials/band_temperature.py` now holds
  `varshni_eg_ev`, `d_eg_dT_ev_per_K`, `VARSHNI_PARAMS` and `ALLOY_GAP_PARAMS`, moved verbatim from
  `optics/soa/temperature.py`. That module re-exports the same objects, so every `optics.soa` name keeps
  working. New: the AlAs Gamma row (Vurgaftman Table II: 3.099 eV, 0.885 meV/K, 530 K) and
  `algaas_gap_law(x)`, which returns `("GaAs", "AlAs", x, -0.127 + 1.310 x)` (Table XII, a temperature-
  independent bowing per Sec. IV.A.1). There is no second Varshni definition in the package; a test walks
  the AST to check.
* **`BandTemperature(gap_law, affinity_fraction, anchor="reference", derive_n_i=False)`**, a frozen
  dataclass attached as `TransportModel.band_temperature` (a new last field, default `None` = off). The
  reference temperature T_ref is the existing v0.14 field `TransportModel.chi_reference_T_K` (`None` =
  300 K). It is the temperature the material's `band_gap_eV`, `chi_eV` and `n_i_m3` are quoted at, so there
  is one field, not two.
  * Gap, `anchor="reference"` (the default, decision 32): E_g(T) = band_gap_eV + [V(T) - V(T_ref)]. This is
    bit-identical to the input at T_ref, because the delta is exactly 0.0.
  * Gap, `anchor="absolute"`: E_g(T) = V(T), for data quoted at 0 K. `band_gap_eV` must then be `None`;
    otherwise it would be a second, unused gap. `chi_reference_T_K = 0.0` is now accepted, but only
    together with a model.
  * Affinity: chi(T) = chi_eV - gamma_chi [V(T) - V(T_ref)]. `affinity_fraction` is REQUIRED (decision
    46) and lies in [0, 1].
  * n_i: by default it is used as given, i.e. at the device T. With `derive_n_i=True`, `n_i_m3` is the
    value at T_ref and n_i(T) = n_i(T_ref) (T/T_ref)^(3/2) exp(-[E_g(T)/kT - E_g(T_ref)/kT_ref]/2). This
    is bit-identical at T_ref, and it makes the material's statistical gap kT ln(N_c N_v/n_i^2) track
    E_g(T). It cannot be anchored at 0 K, and that case is refused.
* **One kernel the builders read band data through:** `materials.band_data_at_T(tr, T) -> (E_g, chi, n_i)`.
  Without a model it returns the three input objects unchanged at any T, which is the v0.14 behaviour.
  * In `LayeredDevsimBuilder` it supplies the Anderson-frame chi of every semiconductor region, the E_g of
    the bipolar-heterojunction band-gap check, and the bipolar region n_i.
  * In `Stacked3DSpec.from_design` it supplies the chi of the primary and of the extra semiconductors, and
    the bipolar body n_i.
  * The region T is read from `BipolarOptions.T_K` for bipolar regions and is T_REF otherwise
    (`transport_temperature_K`). This is the same source that sets the region V_t.
* **The v0.14 chi guard** (`physics_heterojunction.affinity_temperature_tags`, used by both builders). A
  material with a model has its chi evaluated at the device T, so its tag is that T and the guard passes
  whatever `on_chi_temperature` is set to. A material without a model is checked exactly as in v0.14. The
  refusal and warning messages now name `TransportModel.band_temperature` as the physics remedy.
* **BTBT hook (plan 5.2 item 2).** `materials.band_gap_ratio(tr, T, T0=300)` returns E_g(T)/E_g(T0) from
  the model, or `None` without one. The BTBT scaling itself is item 4.1.2. `setup_btbt`'s v0.14 T_REF
  warning is unchanged and `tunneling.py` is not touched.

### Which option to use when (also in the module and dataclass docstrings)

| Choice | Use when |
|---|---|
| `anchor="reference"` | The material's gap is a non-zero-T number, especially one tied to a paired statistics bundle. For Si, P3's absolute Varshni (1.17 eV, 4.73e-4, 636 K; primary unverified) gives 1.1245 eV at 300 K. That is 5.2 meV off a paired bundle's 1.12973 eV, and its derived n_i is 1.067e10 instead of 9.65e9 cm^-3. The anchored form changes neither of them at 300 K (gated). |
| `anchor="absolute"` | Data quoted at 0 K, where the law's E_g(0) is the material's gap. |
| `gamma_chi = 1` | Valence-anchored. Vurgaftman et al. take the VBOs independent of T ("in all cases we will take the valence band offsets to be independent of T", Sec. VI, p. 5854, re-read). Use it with band alignments built from that paper. |
| `gamma_chi = 1/2` | Symmetric split. This is the Sentaurus Device default affinity model, chi(0) + alpha T^2/(2(T + beta)), read from a training mirror (a SECONDARY source). Use it to reproduce Sentaurus, or when no offset data constrain the split. |
| `derive_n_i=True` | The recommended "own n_i(T)" for the P2 paired-BGN override at T != 300 K (plan 5.2 item 3). A BGN fit stays a 300 K statement, but this n_i is consistent with the gap the device runs. |

**Adversarial checks.** Each gate has one perturbation that must break it, and each does:
* A swapped composition, and a Table XII digit off by one (1.311 x), break H2-a.
* The absolute form is not the input gap at T_ref (1.6 meV off), so the anchoring is not vacuous.
* The model-on materials 1 K away from T_ref differ in chi, E_g and n_i, so the builder A/B identity is
  not vacuous.
* The other chi convention (gamma 1 <-> 1/2) in the oracle breaks H2-c (by 0.67-1.45 mV), H2-d and H2-e.
* An unmodelled material still refuses.

**H2-c load margin: the P3 fallback, derived.** At P3's 250 / 350 K, the v0.14 route misses V_bi by
0.88 / 1.27 mV for gamma = 1. That is only 4.4x / 6.4x the tolerance, and half that for gamma = 1/2 (all
measured with the oracle). The 5x rule fails at 250 K. P3's fallback is a larger-mismatch pair, i.e. an
AlAs-rich alloy. That would cross the Gamma-X crossover (x = 0.38 at low T, 0.39 at 300 K; Sec. IV.A.1),
where the Gamma gap is no longer the band edge. So the gate widens the temperature range to 200 / 400 K
instead. Every case asserts its own margin in the test.

**H2-e: why 1e16 cm^-3 and 400 K (derived, not tuned).**
* The FD-SG bulk uses the rational g fit. MEASURED against scipy F_1/2 quadrature, its Delta(u) misses the
  exact offset:

  | u | 0.01 | 0.05 | 0.1 | 0.2 | 0.5 | 1 | 2 | 5 |
  |---|---|---|---|---|---|---|---|---|
  | error (kT) | -3.1e-5 | +1.9e-4 | +6.9e-4 | +2.0e-3 | +6.5e-3 | +1.4e-2 | +2.5e-2 | +4.2e-2 |

* An exact-FD barrier therefore differs from the solved one by about the fit error over the profile.
* At 1e17 cm^-3 (the D1a doping) the GaAs accumulation layer reaches u ~ 2. MEASURED: the solved barrier
  sits 2.33 / 2.54 / 2.60e-4 eV below the exact-FD oracle at 0.5 / 0.25 / 0.125 nm interface spacing at
  300 K. The gap does not shrink with refinement, so it is not discretization. G misses the oracle by
  +0.84 / +0.91 / +0.93 % (300 K) and +1.8 % (200 K), against 2e-3.
* At 1e16 cm^-3 and 400 K the peak u is 0.092 (asserted <= 0.1), where |dDelta| <= 6.9e-4 kT. One such
  error is allowed for the bulk reference and one for the local activity: |dG/G| <= 1.4e-3 < 2e-3.
* At 350 K the peak u is 0.13, outside that budget. The residual measured there, +9.7e-5, would still
  pass, but the gate is not placed there.

## Findings outside scope (reported, not changed)

* **The FD-SG g fit limits any exact-FD heterointerface oracle at 1e17 cm^-3.** See H2-e above: about
  2.5e-4 eV of barrier, or about 0.9 % of TE conductance at 300 K. It is mesh-converged and consistent in
  size with the fit's Delta error at u = 0.2-2. This is the same family as the v0.14 note's finding that
  Delta is 1-3 % off in the moderately degenerate range. The shipped D1a gate C passes only because it
  reads phi_B from the solved densities.
* **CI `solvers-devsim` step: fixed (pre-existing bug).** The last line of its file list started after a
  literal backslash-n left by a merge, so bash passed a stray argument `n` and pytest would fail with
  "file or directory not found". I fixed it on the line where this branch adds
  `tests/test_devsim_band_temperature.py`.
* Not modelled (documented in the module):
  * the temperature dependence of the DOS and Richardson masses;
  * the temperature dependence of the BGN fits;
  * the X-valley edge of AlAs-rich AlGaAs.

## Release-note lines

- New opt-in band-temperature model: set `TransportModel.band_temperature =
  materials.BandTemperature(gap_law, affinity_fraction)`. It evaluates the gap (Varshni, anchored at the
  material's quoted temperature so 300 K data stay exact), the electron affinity (a required fraction of
  the gap change: 1 is valence-anchored per Vurgaftman 2001, 1/2 is the Sentaurus convention) and,
  optionally, n_i at the device temperature. A heterostack whose materials carry it no longer needs
  `chi_reference_T_K` tags or `on_chi_temperature`.
- One Varshni law and table for the whole package (`materials.varshni_eg_ev`, now with AlAs and
  `algaas_gap_law(x)`). The `optics.soa` names are unchanged and its results are bit-identical.
