## Measured numbers

All on the Windows dev box, DEVSIM 2.11.2, scipy OpenBLAS. Fixture: `tests/_gated_film_fixture.py`, the generic
gated-film cell (degenerate film "TCO", n_bg 3e26 m^-3, DOS mass 0.30 m_e, eps_s 9.0, 6 nm, between 2 nm oxA (eps 9)
+ 6 nm oxB (eps 20) on both sides, metal gates, 40 nm cell, no edge ground). Its screening length
(`screening_length_m`) is 0.777 nm. All numbers below are on this fixture; entries marked "--" are not recorded
here.

**Oracle.** An independent 1-D box-method nonlinear Poisson solve written in
`tests/test_mesh_screening_grading.py` (same Aymerich-Humet closure, Dirichlet gates on the outer oxide
faces), converged at second order to < 1e-5. Its lower-face density agrees with every DEVSIM mesh to <= 7e-7.

| 6 nm | screening (new default) | 204 | -9.57e-5 | +3.72e-4 | +1.8e-5 |

("--": not recorded here. On a gated degenerate film of this kind, a factors / 4 row and a zone-factor 3 / 4 / 8
comparison showed that the face and zone spacing, not the zone factor, set the error.)

**Gates in `tests/test_mesh_screening_grading.py`.** Exact node counts are not pinned. The test checks that the
DEVSIM nodes in each refined zone ARE the builder's explicit mesh lines and that the legacy mesh has no gap finer
than 0.05 nm. The legacy-mesh miss is gated as |err_legacy| > 10 x the default's tolerance (3e-3 at +5 V, 2e-2 at
-3 V; measured -1.88e-2 / +1.12e-1). The face gap is gated by the bound that follows from the grading rule,
|gap0 / (L_s/40) - 1| <= h1 / (2 (zs - h1)) (0.73 % on the 6 nm film, 0.63 % on 20 nm; measured +0.50 % / -0.17 %).

**A DEVSIM property that changed the design.** DEVSIM's own grading between two mesh lines drops the
generated points within ~1e-10 mesh units before the upper line: lines at 0 and 1 nm graded 0.1 -> 0.01 nm
give cells [..., 0.0218, 0.1076, 0.01] nm; uniform 0.01 nm cells end in a 0.1 nm cell. With the builder's SI
metres that is a ~0.1 nm cell next to the face cell at the UPPER face of every layer, whatever spacing is
requested. Every DEVSIM-graded mesh therefore converged to a wrong limit: MEASURED on a gated degenerate film of
this kind, the plan's candidate meshes and the audit's fine meshes sat ~7e-4 below the oracle in strong
accumulation and their depletion values did not converge. The screening grading
places every node of a refined zone as an explicit mesh line (DEVSIM keeps explicit lines at any separation),
which removes the hole and gives the second-order convergence above. Below a 5e-12 m face spacing the region
and interface bloat (1e-12 m) becomes unsafe: DEVSIM-graded 1.1e-12 m / 2.2e-12 m face spacings decoupled the
film from its gate / moved the depletion density by -69 %; the grading never emits a spacing below 5e-12 m.
The legacy lines and any user mesh still have the hole; it is reported here as a finding, not fixed for them.

**C1, native grid.** Fine fixture mesh (189 nodes across the 6 nm film, legacy lines), +5 V: excess sheet density
from the native `grid_fields` equals the raw-node trapezoid to < 1e-12 (the x = 0 column is bitwise the node
column); the v0.15.1 32-point grid misses it by +7.40e-3.

**C3.** rel_tol 1e-5 and 1e-6 converge on both meshes; 1e-7 converges on the default (screening-graded) mesh
and fails on the legacy one; 1e-8 fails on both, each at the 0 V seed with the zero-unknown note (relative 2.6e-8
default, 1.3e-7 to 3.6e-7 legacy, at absolute updates 3e-18 to 5e-17 V); abs_tol=1e-14 converges at 0 V and 0.5 V
on both.

**Cost.** `validation/gated_dd_builder.py` (the shared validation device of `validation/_reference_device.py`,
131 / 301 x columns, film 17 -> 188 z nodes): 17.6 s -> 115 s (6.5x) on one run. The two new test files: ~30 s
serial.

## Plan statements found wrong or incomplete

1. "Refining only interface_ps_m does nothing; what matters is the spacing out to a few screening lengths" is
   right, but every DEVSIM-graded mesh, however fine, also keeps a ~0.1 nm cell at the upper face (above), so
   "converged" DEVSIM references are off by ~1e-3 in accumulation and depletion (MEASURED on a gated degenerate
   film of this kind); the gates here use an independent 1-D oracle instead.
2. "For each semiconductor layer": bipolar_dd layers are excluded. Their n_bg is a doping; its Debye length sets
   neither an inversion layer nor a p-n depletion width (junction_band refines junctions), and grading them would
   move every bipolar validation without a measured gain. Equilibrium and drift-diffusion layers are graded.
3. "Measure node counts ... before/after": a device none of whose layers is refined keeps the v0.15.1 y-line
   call list VERBATIM (same order), so bipolar devices and lightly doped unipolar ones are byte-identical.
4. `EpsField.voxel_bounds_u` cannot name the region (the EpsField does not know it and the callers in
   `optics/eps_assembler.py`, not a P4 file, pass nothing); the message names the axis and the fix.
5. `screening_interface_factor` (1/40) is a field too, so all three spacings of the rule are tunable.
6. `extras["interface_resolution"]` is a per-region dict, and its value is a mesh comparison, not a pass/fail
   number: a depleted face has a steep Boltzmann tail (0.150 with the default grading vs 0.022 in accumulation, on
   the gated-film fixture).
7. The `native_carrier_grid` attribute is set on the layered solvers by P1/P2/P3; on this branch no shipped solver
   has it yet, so the automatic native path is tested with a stub solver. After P1 merges, a test with the real
   `make_layered_tmm_solver` is worth adding (request to P1/P15).

## Release-note lines

- DEVSIM 2-D mesh: unipolar semiconductor layers are now graded to their screening length by default
  (`Mesh2DSpec.semiconductor_refinement="screening"`); interface densities of gated degenerate films move by
  ~2 % in accumulation and ~11 % in depletion (generic gated-film cell, +5 / -3 V). `semiconductor_refinement="legacy"` restores v0.15.1.
- `LayeredDevsimBuilder.solve(grid_n_z=None)` returns native z mesh lines; `run_pipeline` uses them
  automatically for optical solvers with `native_carrier_grid = True`; `carrier_solve_kwargs` overrides.
- `EpsField.voxel_bounds_u` raises on a non-uniform axis.
