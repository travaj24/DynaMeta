## 1. Runtime BTBT resolution check (`dynameta/carriers/tunneling.py`)

**Where.** `setup_btbt` cannot see the solved field, so the check runs AFTER the solve, where the user reads
the BTBT result: `btbt_generation_current(..., check_resolution=True)` (default) calls the new public
`btbt_quadrature_error(device, region, *, index=None)` and warns above `BTBT_QUADRATURE_TOL = 1e-2` (the
module's MESH RESOLUTION budget, h <= 0.35/k <-> (k h)^2/12 <= 1 %). The returned value is never changed
(asserted). `setup_btbt` only records the installed sets in a module dict (no DEVSIM call: the P7 call-log
digest is unchanged, MEASURED). 1-D only: in 2-D/3-D the element rates have no 1-D ordering to interpolate
along, so the function returns None there (stated in the docstring and module header; the h <= 0.35/k rule is
the user's to apply). Terminal currents read through other functions are not checked.

**The criterion (derived, not the bare neighbour ratio).** I first tried the brief's "rate changes by more
than exp(0.35) between neighbouring edges". It is not equivalent: k = (B/E^2)|dE/ds| GROWS away from the
peak, so on the well-resolved 0.025 nm Si-direct mesh (error +0.16 %) edges carrying 1e-3 of the peak rate
already exceed exp(0.35) (MEASURED neighbour log-ratio 0.27 at the peak, larger in the tail), while one long
peak edge with tiny neighbours reads only k h_e/2 and its first-order error (up to 5.5 % at the threshold)
would pass. So the check ESTIMATES the quadrature error instead:

* the FV edge field is exact at the edge midpoint (Gauss's law; btbt-presets audit, 3e-4);
* the continuum field on each half edge is a quadratic through three midpoints containing the edge and its
  neighbour, the ENO choice (smaller second difference) of the outward and inward stencils: exact for the
  piecewise-linear field of uniform depletion whichever side of the edge its cusp lies on (the abrupt
  junction's FV peak sits at an edge midpoint), and for a parabolic peak (graded junction);
* f = A E^P e^(-B/E) is integrated over each half edge by 16-point Gauss-Legendre, the Hurkx D held at its
  edge value; error = Sum |U_e| (h_e - Int f/f_e) / Sum |U_e| Int f/f_e (gross rate). For a rate e^(-k|s|)
  this reduces to (kh/2) coth(kh/2) - 1 on a uniform mesh and k h_e/2 - 1 + e^(-k h_e/2) for one long peak
  edge (the two closed forms of the presets audit).

Two cruder models were measured and rejected: ln f linear between midpoints (+9 % high on the triangle, its
ln f is concave) and E linear between midpoints (invents a 1.2e-3 error on a smooth graded peak whose true
error is 2e-16).

## 2. O3: the 1.8 % sublinearity, explained (`tests/test_devsim_oxide_tunneling_sc.py`, `_oxide_tunneling_child.py`)

**Derivation.** The leak current crosses the 5 um neutral body. Its ohmic drop J R (R = int dx/(q mu_n n))
raises the electron quasi-Fermi potential and, because n = N_D is pinned in the neutral body, the potential of
the body edge of the accumulation layer by the same amount: the surface sees the body contact biased by +J R.
To first order, at fixed electrostatics,

    delta_i = J_sc/J_post - 1 = G_i R J_sc,i,   G_i = d ln J_post / d V_body (ideal capacitor, gate fixed).

The slope of ln|delta| vs ln J over the mass sweep is then 1 + d ln|G| / d ln J, not 1. G is the supply
response (d ln J/d x_s = 0.768 -> 0.763, nearly mass-independent) plus the barrier response to the oxide-drop
change the accumulation layer's screening produces, which scales with the WKB exponent ~ sqrt(m). The
second-order term (delta = -x + 1.5 x^2 for a pure series resistance) moves the slope by < 2e-4 here.

**Measured** (scratch `fu_o3.py`, then the child; G by central differences +-1e-4 / +-2e-4 V with Richardson,
R = 3.0784e-8 Ohm m^2 from the solved densities):

| m_ox | J_post (A/m^2) | G (/V) | delta | delta / (G R J_sc) - 1 |
|---|---|---|---|---|
| 0.42 | 14.65 | -5.0325 | -2.2696e-6 | +1.0e-5 |
| 0.36 | 77.43 | -4.8969 | -1.1672e-5 | +7.5e-6 |
| 0.30 | 473.4 | -4.7494 | -6.9213e-5 | -1.1e-5 |
| 0.25 | 2472 | -4.6148 | -3.5109e-4 | -9.9e-5 |
| 0.21 | 1.050e4 | -4.4972 | -1.4505e-3 | -4.3e-4 |
| 0.18 | 3.408e4 | -4.4014 | -4.5898e-3 | -1.35e-3 |

Fitted slope 0.98210; prediction 0.98224; 1 + ln(4.40/5.03)/ln(2326) = 0.9827.

**Gate (tightened).** (a) every point within |delta_i| + 3e-5 of G R J_sc (second order plus R's
geometric-mean edge density and the FD G); (b) the slope within |delta_max|/ln(J_max/J_min) = 5.9e-4 of the
prediction's slope (was |s - 1| <= 0.05, i.e. 85x looser). Adversarial: "slope exactly 1" misses (b) by 30x
(asserted); the no-feedback refutation (delta at round-off) is kept. MEASURED pass (13.6 s). This is a tighter
test, not a code change: on `b94c2f4` the physics is the same, so it would pass there too.

## 3. E4: why 0.5 nm (`tests/test_extended_precision_design.py`)

**Not the 2-D mesher dropping lines, not element vs edge recombination.** MEASURED (scratch `fu_e4a.py`,
`fu_e4b.py`): the 2-D builder's x lines and the 1-D gate's lines grade identically away from the junction
(dx at 2 / 20 / 100 nm from it: 1.019 / 1.387 / 2.936 nm vs 1.019 / 1.386 / 2.931 nm), but each run leaves a
REMAINDER edge ending at the junction line: 0.7716 nm on the builder (the run starts at the 1.5 nm edge-metal
line) and 0.0099 nm on the 1-D gate (the run starts at 0). The 1-D device built on the builder's own x nodes
reproduces the 2-D miss: +4.944e-3 (2-D +4.9e-3) at 1 nm, +8.394e-4 (2-D +8.39e-4) at 0.5 nm.

**Mechanism.** At 1.0 V the current is all SRH (J_srh/J = 1 - 3.6e-13) and its integrand
1/(cosh((psi - V/2)/V_t) + 1) is a peak of width V_t/E = 1.29 nm at the junction (E = 2.0e7 V/m). The node
quadrature of such a smooth peak is spectrally accurate on a uniform grid; one irregular edge on it is not.
Clean explicit meshes (uniform band of +-20 nm, graded outside), 1.0 V / 1.5 V:

| junction band | miss |
|---|---|
| uniform 1 nm | -6.39e-4 / -6.21e-4 |
| uniform 0.5 nm | -1.64e-4 |
| uniform 0.25 nm | -5.2e-5 |
| 1 nm with ONE 0.7716 nm edge at the junction | +3.49e-3 / +2.21e-3 |
| ... 0.5 nm edge | +4.62e-3 / +3.00e-3 |
| ... 0.2 nm edge | +2.47e-3 / +1.60e-3 |
| ... 0.01 nm edge | +1.3e-4 / +6.5e-5 |

The odd-edge error vanishes at h_odd -> 0 and h_odd = h and peaks near h/2: the quadrature signature. A pure
node-quadrature model of the sech^2 peak gives the same shape at ~40 % of the size (1.5e-3 at 0.77 nm);
the rest is the discrete potential's response (INFERRED, not separated). The audit's "residual ~4e-4 is the
oracle's depletion approximation" was mesh error too: the clean meshes converge at about second order to
-5e-5.

**Action.** Documented; no code change. A builder-side fix (extra uniform lines around the mid line) would
change every existing 2-D mesh, which the defaults-off rule forbids without a plan decision. Same family as
item 1 (a DEVSIM remainder edge on a narrow peak); worth one plan line: "LayeredDevsimBuilder: optional
uniform junction band around x_spacing_feature_mid lines". The E4 comments and the extended-precision audit
note now say this.

**Gate** `test_e4_mesh_cause_is_the_remainder_edge_on_the_recombination_peak` (12.7 s, fast tier): the
builder's remainder edge is 0.7716 nm; 1-D on the builder's nodes misses by > 3e-3; the clean uniform band
meets 3e-3; one 0.5 nm edge in it misses by > 3e-3 (budget: the D2b gate-A 3e-3 E4 inherits). A
characterisation gate: no code changed, so it holds on the old code as well.

## 4. One-call noise method (`tests/test_devsim_noise_method.py`, `_noise_method_child.py`)

**W7 (extended precision 0 / +1 / 0), added as `@slow`.** MEASURED wall: 4 min 16 s for the 4-frequency
sequence (in parallel with another child), 4 min 5 s for 1 frequency alone: the extended build + solve
~86 s, the +1 V call ~130 s (the extended re-settle ramp), frequencies are not the cost. It fits the ~5 min
budget on this box; a 4-vCPU runner may be ~1.5-2x slower (INFERRED), which the nightly's 300 min cap
absorbs. New scenario `seq_xp`; the gate asserts the bitwise repeat, the +1 V digest differs, the device is
extended, no warning at the build, and exactly 12 warnings, all the extended-precision noise advisory.
MEASURED: passes, 261 s (4 min 21 s) in pytest.

**The independent 3-D per-cell check (P2 W3): not feasible, not added.** (i) The reference modulator's patch is
a 175 nm square in a 370 nm cell, so its 3-D twin is NOT y-invariant and S_3D = W S_2D does not hold by
construction; the check needs a y-invariant stripe design. (ii) `Devsim3DEquilibrium` has no circuit-driven
gate (`solve` refuses circuit-driven contacts), so the 3-D noise drive would have to be written first. That is
new machinery, not a follow-up gate.

## Release-note lines

- `btbt_generation_current` (1-D) now checks the mesh: it estimates the quadrature error of the local BTBT
  current on the solved field (`btbt_quadrature_error`) and warns, naming the region and the worst edge, when
  it exceeds 1 % -- e.g. one long edge on the field peak, which refinement elsewhere does not fix. The value
  returned is unchanged; `check_resolution=False` skips the check.
