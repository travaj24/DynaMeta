Branch `wip/v015_infra` (from `9b6937f`). Plan `docs/plans/2026-11-04-devsim-v0.15/00_consolidated_plan.md`
items **4.0.1** and **4.0.3** (P1 section 0, gate C0); user decisions **7** (build the two-point source first and
use it for all new noise), **8** (accept linear extended-precision convergence with custom terms, documented),
**9** (separate mechanism keys). DEVSIM 2.11.2, scipy's OpenBLAS (the `devsim_env` pin), UMFPACK 5.1, Windows,
py3.14. "Measured" = run on this box by this branch's tests or the scripts named; "inferred" says so.

Nothing here implements oxide tunnelling, thermionic shot noise, traps or nonlocal BTBT. These are the two
pieces later agents build those on. Section 3 is their API.

## 1. What changed

* **`dynameta/carriers/noise_analysis.py`: one kernel for every event source.**
  * `SourceRow` and `TwoPointSource` (dataclasses), and `two_point_psd(source, field)`, which computes
    S = q^2 2P |Sum_r c_r y_r|^2 per event.
  * The built-in GR source (SRH, every `PTerm_*` term, edge/element BTBT, aggregated per node as before) is
    now a `TwoPointSource` with rows (hole, +1), (electron, -1) (`_gr_source`). It is evaluated through the
    kernel. The old inline line `Q_E*Q_E*|y_p - y_n|^2*d.gr` is gone. `_RegionData.gr` became
    `_RegionData.two_point`, a list that the P3 trap/thermionic providers append to.
  * Rows may be in any region equation, or be a circuit node (`region=None`). Field lookups outside the
    noise regions are cleaned up afterwards.
  * A row on a circuit-contact node is refused for any equation without the item-4 contact fix-up.
  * Mechanism registry (decision 9): `TWO_POINT_MECHANISMS = (te_n, te_p, trap_n, trap_p, tunnel_ox,
    btbt_nl)` is part of `MECHANISMS`.
  * `DEFAULT_MECHANISMS` is every key except Hooge, and it is now the default of
    `noise_spectrum(mechanisms=)`. A key with no provider adds nothing, so today's `by_mechanism` keys are
    unchanged. Plan 5.7 asks that the P2 noise method inherit this tuple.
  * Live custom terms contribute their `noise_sources()`. A live term with no noise model, or with
    `jacobian_exact=False`, makes `noise_spectrum` refuse the device.
  * My edits sit in the GR / `present` / loop part of `noise_spectrum` and in a new block after
    `TerminalNoise`. The Hooge element code (the v0.14 element-geometry branch) is untouched.
* **`dynameta/carriers/custom_terms.py` (new): DEVSIM's custom-equation hook, done once.**
  * There is ONE process-wide dispatcher, `dynameta_custom_terms`. It is registered lazily by the first
    `add_custom_term` (or `register_dispatcher()`), never at import.
  * Liveness is read back from DEVSIM at every assembly. A term is live only if its device is in
    `get_device_list()` AND carries the marker parameter `_ct_<name>` with this term's token. Stale entries
    are purged.
  * `rows_live()` is False while the target equations are deleted (Gummel / Poisson-only pre-solve).
  * Local terms are refused, with a pointer to `add_recombination_term`. So is a missing locality
    declaration.
  * Structural pattern entries go in as +eps/-eps pairs (section 2.4). An entry outside a declared pattern
    raises.
  * An `AdvisoryWarning` fires for a pattern-changing term that declares no pattern while
    `DEVSIM_NEW_SYMBOLIC=0`.
  * Helpers `node_rows` (refuses contact nodes), `node_columns` and `circuit_row`.
* **Tests:**
  * `tests/test_noise_two_point.py` (6 tests).
  * `tests/test_custom_terms.py` (20 tests). Every case that registers runs through the child-process
    runner `tests/_custom_terms_child.py`.
  * Both files are on the `solvers-devsim` CI job: 46 s serial together, measured.

## 2. Measured findings about DEVSIM 2.11.2's custom-equation hook

1. **Call pattern.**
   * One `("MATRIXANDRHS", "DC")` call per DC Newton iteration.
   * ssac and noise each call `("MATRIXONLY", "DC")`, then `("MATRIXONLY", "TIME")`.
   * So a term's static Jacobian *is* the small-signal and noise matrix.
2. **An exception inside the procedure** aborts the solve with
   `DEVSIM FATAL: Error when evaluating custom_equation "<name>" ... <the Python message>`. DEVSIM stays
   usable afterwards.
3. **`get_matrix_and_rhs` returns rhs = -F** (the negative residual). The finite-difference Jacobian gates
   therefore compare FD = -J.
4. **DEVSIM drops exact zeros.**
   * `CompressedMatrix::AddEntryImpl` returns on `v == 0`. Source read at devsim/devsim main.
   * Measured: a `(r, c, 0.0)` triplet leaves nnz unchanged, so "emit a structural 0.0" reserves nothing.
   * What works is the pair `(r, c, +2^-1022), (r, c, -2^-1022)`. Measured: nnz +1, the slot holds 0.0,
     and every other entry is bitwise unchanged.
   * The pair leaves any value v unchanged for |v| >= 4e-292 or v = 0, because 2^-1022 is below a quarter
     ulp of such v (inferred from IEEE rounding).
   * DEVSIM itself handles a growing pattern: a new slot decompresses the matrix and sets `NEW_SYMBOLIC`.
     The hazard is only PARDISO's symbolic reuse when `DEVSIM_NEW_SYMBOLIC` is overridden to "0".
5. **Equation numbers do not exist before the first solve or assembly.** `get_equation_numbers` on a
   never-solved device hits `ASSERT Region.cc:1201 UNEXPECTED` (measured). The add-time pattern check
   therefore looks at whether the subclass overrides `structural_pattern`; it does not call it.
6. **Registration alone is inert** (gate C0(a), measured in child processes; details in section 4).
7. **Extended precision (decision 8).**
   * Toy A (a link as strong as the segment it bridges) converges linearly, about 2.7x per iteration: 34
     iterations to rel 4e-31, against 4 iterations without the term. Measured.
   * The contact charges then cancel exactly (0.0), and Q matches the closed form to 8 eps.
   * The P1 probe's weak FN sink converged at about 70x per iteration.
   * The rate depends on the term's share of its rows' Jacobian. The `custom_terms` docstring says to
     budget `maximum_iterations >= 60`.

## 3. API for the later agents

**Event noise (thermionic P3, traps P3, oxide tunnel P1, nonlocal BTBT P1).** Build a
`noise_analysis.TwoPointSource(mechanism, region, rate, rows, map_nodes=None)`:

* `rate` is P per event [1/s; per m^2 in 1-D]: the TOTAL event rate, both directions counted (G + R; for a
  two-way flux, (J_f + J_b)/q times the node area).
* `rows` is a tuple of `SourceRow(region, equation, coeff, nodes)`.
  * `coeff` holds c_r: the change of that row's residual per event in units of q, in DEVSIM's convention for
    the row.
  * An electron removed gives -1 on `ElectronContinuityEquation`; a hole removed gives +1 on
    `HoleContinuityEquation`.
  * A current leaving into a circuit node is +1 on its KCL row, with `region=None` and the node name as
    `equation`.
  * Pad events that touch fewer rows with coefficient 0.
* Only relative signs matter. A wrong relative sign is an O(1) FDT miss: measured +6.5x on the GR rows.

Where to put the sources:

* Model-expressible providers (thermionic emission, trap kinetics) append to `_RegionData.two_point`.
* Custom terms return them from `noise_sources()`.
* The mechanism key must be one of `TWO_POINT_MECHANISMS`.
* Interface attribution (`by_interface`, P3 D-T1) is not built. A source is attributed to `region`.
  **Correction (2026-11-06, v0.15 close-out):** built by the thermionic-noise work: `TwoPointSource.interface` and
  `NoiseSpectrum.by_interface` (docs/audit/2026-11-06-v0.15-thermionic-shot-noise.md section 2).

**Custom terms.** Subclass `custom_terms.CustomTerm`:

* Set `locality = "nonlocal"`.
* Implement `assemble(device, what, timemode) -> (rcv, rv)`, flat lists. Look the rows and columns up on
  every call with `node_rows`, `node_columns` and `circuit_row`, and return `([], [])` for `"TIME"` if the
  term is static.
* Optionally provide:
  * `equations(device)`, which drives `rows_live`;
  * `structural_pattern(device)`;
  * `noise_sources(device)`;
  * `jacobian_exact`;
  * `pattern_changes`.
* Attach the term with `add_custom_term(device, term)`.
* Conservation is the term's responsibility: equal and opposite entries, in each row's own sign convention.
  Every new term needs a terminal-balance gate that a flipped sign breaks. Model it on the toys in
  `tests/_custom_terms_child.py`, which are reusable.
* The dispatcher always returns `permute=True`. Address bulk rows of non-contact nodes and circuit rows.
* **Not done here (4.0.2's job):** a `"custom"` kind in `physics_bipolar_dd.recombination_terms`. For now the
  noise refusal reads `custom_terms.live_terms` directly (`noise_analysis._custom_term_sources`).
  **Correction (2026-11-06, v0.15 close-out):** done by 4.0.2: the inventory has the `"custom"` kind and the noise refusal reads it
  (docs/audit/2026-11-06-v0.15-term-bookkeeping-v2.md section 1).

### 4.0.3 (`tests/test_custom_terms.py`)

Every case that registers runs in a child process.

**Defaults off**

* Import, then build and solve: nothing is registered (spy on `custom_equation`). The first add registers
  exactly once.
* Registration alone, with no term: the sgflux fixtures (26 arrays and currents) and the BTBT FDT noise /
  ssac are bit-identical. The dispatcher really ran (325 calls), and the 6595bde gate passes. The call-log
  digest is unchanged (3542731548...205f80, 237 calls).

**Toy A (Poisson link in a dielectric)**

* DC: node potentials match the closed-form network to 1.1e-16 V, and Q to 1.8e-15. Budget 2601 eps.
* Charge balance: 0.2 eps T; budget N eps T. The wrong sign gives Q_lo + Q_hi = -1.6 Q.
* Jacobian share vs FD: 1.4e-14 relative.
* ssac C vs closed form: 1.1e-15. DC dQ/dV: 1.1e-13. The wrong sign makes ssac C collapse.
* Extended precision: converged in 34 iterations, linearly.

**Toy B (electron quasi-Fermi bridge in an n bar)**

* G vs the closed-form network: ssac 5.7e-13, DC (Richardson) 2.7e-13; budget 1e-9 (gate A1). The bridge
  moves G by 1.25x.
* Johnson S = 4kT G through the bridge's two-point source: 6.1e-13. Dropping the source misses by -12.5 %.
* Terminal balance at 0.05 V: 2.4e-7 A/m^2 (1.7e-14 relative), within its budget of sum|rhs| + N eps T =
  1.7e-5. The wrong sign gives -2.2e7 against I = 1.35e7.
* Jacobian share: 1.1e-13 for psi, 3.3e-9 for n (the latter is exactly the O(h^2) truncation of ln n).
* Noise refuses a term without a noise model, and a term with an inexact Jacobian.
* Frozen continuity: `rows_live` is False, the Poisson-only solve converges, and the dispatcher ran with the
  term skipped.

**Liveness**

* Re-creating the device under the same name gives a solve and matrix bit-identical to the term-free one,
  and the registry is purged.
* Refute 1: a forged marker (simulating a name-only check) makes the term apply again.
* Refute 2: a different region name causes no crash, and the term is not applied.

**Structural pattern**

* nnz goes up by exactly 2, the new slots hold 0.0, and every other entry is bitwise equal.
* The DC solution moves by 1 ulp (a different factorisation pattern); budget 2601 eps.
* An escaping entry raises with the term's name.

## 6. Open points

* **The FD-Jacobian round-off budget is an estimate.** It uses R = sum_k |J[r,k] x_k| as the scale of the
  row's terms. That bound is conservative for linear rows and adequate for the SG rows (measured margins:
  0.0002-0.1 of budget). It is not a rigorous bound for every nonlinear term.
* **The mechanism label in toy B.** It borrows `tunnel_ox`, because a test-only mechanism key would need a
  mutable registry.
* **The extended-precision note** belongs also in 4.4.1's design-flag docstring (plan 5.9). That is another
  agent's file, so I did not touch it.
  **Correction (2026-11-06, v0.15 close-out):** the design-flag docstring (`geometry.specs.CarrierSpec`, item 4.2.6) states the linear
  convergence; the close-out corrected its iteration figure to the measured 12-35 and added the stall
  where a term dominates its rows (docs/audit/2026-11-06-v0.15-oxide-tunnelling.md section 8).

## Release-note lines

* New `dynameta.carriers.custom_terms`: Python-assembled, nonlocal residual terms through DEVSIM's
  custom-equation hook.
  * One lazily registered dispatcher.
  * Liveness is read back from DEVSIM.
  * Local terms are refused.
  * Explicit structural entries keep the sparsity pattern fixed.
  * Opt-in; inert until a term is added.
* Noise analysis has a general two-point (event) shot-noise source, S = q^2 2P |Sum c_r y_r|^2
  (`TwoPointSource`, `two_point_psd`). The existing GR noise now goes through it, bit-identical. New
  mechanism keys te_n/te_p/trap_n/trap_p/tunnel_ox/btbt_nl are reserved and on by default
  (`DEFAULT_MECHANISMS`).
* Extended-precision DC solves with a custom term converge linearly (measured 12-35 iterations). Allow
  `maximum_iterations >= 60`.
