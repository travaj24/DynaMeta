# v0.15.1: opt-in uniform mesh band at p-n junctions (2-D builder) -- and how it compares (2026-11-08)

Branch `wip/v015_jband`, cut from `098553f` (the v0.15.0 tip, PR #36). User decision 2026-11-08: "please add
it as an opt-in and see how it compares." The default does not change; whether it should is the user's call
(section 5 gives the data).

## 0. Terms

- **Mesh line.** The 2-D builder (`LayeredDevsimBuilder`) builds a tensor (x, z) grid from DEVSIM mesh lines
  (`add_2d_mesh_line(pos, ns, ps)`): `ps` / `ns` is the wanted spacing just to the right / left of the line.
- **Graded mesh.** DEVSIM fills the interval between two lines with edges that start at the left line's `ps`
  and grow (or shrink) geometrically towards the right line's `ns`.
- **Remainder edge.** The length left over when that progression does not land exactly on the right line.
  DEVSIM puts it into ONE edge that ends on the right line. MEASURED: lines at 0 and 10.3 nm, both 1 nm, give
  ten 1 nm edges and one 0.3 nm edge; the builder's GaN-like diode (20 nm at the contact line, 1 nm at the
  junction mid line) has a 0.7716 nm edge ending on the junction.
- **Junction band.** The new option: lines at x_j + k h, each with ns = ps = h, across [x_j - w, x_j + w]. DEVSIM
  adds nothing between them, the junction x_j is a node with two equal edges, and the remainder edge moves
  to the band's ends, a half-width w away from the junction.
- **Recombination / tunnelling peak.** At forward bias the SRH rate is a narrow peak of width V_t / E at the
  n = p point; the band-to-band tunnelling (BTBT) rate is a cusp e^(-k|x|) at the field maximum, the junction.
  The node / edge quadrature of such a peak is accurate on a uniform grid and not across one odd edge (the
  same mechanism as the BTBT fixed-edge error of `docs/audit/2026-11-06-v0.15-btbt-presets.md`).
- **Reference.** The quantity on a mesh refined until it changes by < 1e-3 (section 3 states each one's
  residual). Error = value / reference - 1.

**API.**

```python
from dynameta.carriers.devsim_layered import LayeredDevsimBuilder
from dynameta.carriers.junction_mesh import JunctionBand
b = LayeredDevsimBuilder(design, junction_band=True)               # physical defaults
b = LayeredDevsimBuilder(design, junction_band=JunctionBand(half_width_m=40e-9, spacing_m=0.25e-9))
b.build_device(); b.junction_band_report      # [{axis, regions, position_m, N_A_m3, N_D_m3, V_bi, W0_m,
                                              #   E0_V_per_m, peak_width_m, btbt_width_m, half_width_m,
                                              #   spacing_m, line_spacing_m}, ...]
```

`junction_band=None` / `False` (default) is the graded mesh, byte-identical (section 4).

**Where the junctions come from.** Only `bipolar_dd` regions carry a signed doping. (i) In-region junctions:
the material's `net_doping_expr` is evaluated BY DEVSIM on a throw-away probe mesh (2001 samples along x and
along z on 5 lines across the region; each sign change is bracketed and refined by three more probes to ~1e-6
of the coarse step; an undoped sliver is centred). The probe device and mesh are deleted before the real mesh
is made (gated). (ii) z-stacked junctions: two z-adjacent bipolar regions whose doping at the shared interface
has opposite signs -- homo- or hetero-junction. An isotype heterointerface (n/N) has no sign change and gets
no band. A junction within 1e-3 h of an existing line is put on it. If no junction is found the builder warns
once (`AdvisoryWarning`) and builds the graded mesh unchanged.

**Defaults (derived, not tuned).** From the doping on each side (the median |N| of the side), the abrupt
zero-bias depletion approximation (Sze, *Physics of Semiconductor Devices* 3rd ed., Eqs. 2.2-2.10; the
two-permittivity form without band offsets for a heterojunction):
- half-width w = W_0 = x_p + x_n, the whole zero-bias depletion width, on each side. The SRH peak sits at the
  n = p point, inside the zero-bias depletion region at every forward bias (it moves into the lighter side, at
  most ~0.3 x_dep from the junction for a one-sided junction); the BTBT / field peak is at the junction.
- spacing h = min(V_t / E_0, sqrt(12 tol) / k_0, the spacing of a line already on the junction).
  V_t / E_0 is the SRH peak width at its narrowest (zero bias). k_0 = B (dE/dx) / E_0^2 on the heavier side is
  the BTBT decay rate; sqrt(12 tol) / k_0 with tol = `tunneling.BTBT_QUADRATURE_TOL` (1 %) is that module's
  own resolution rule h <= 0.35 / k (one kernel). The cap keeps the default from coarsening a spacing the
  design already put on the junction (the cell mid line, a layer interface).
- A triangle field has E_0 = 2 V_bi / W_0, so a band holds ~4 V_bi / V_t lines (~150 for Si, ~500 for the
  GaN-like diode) whatever the doping. The x band runs through every layer (tensor grid).
- The estimate is Boltzmann and ignores band offsets. INFERRED: for degenerate doping it under-estimates V_bi
  by a few V_t.

**Not on the 3-D builder.** `Stacked3DSpec` does not share this grading: its axes come from `_graded_axis`
(devsim_3d.py), which cuts each span between breakpoints into ceil(int ds/h) cells at equal steps of
int ds/h, so a span never ends in a DEVSIM-style remainder edge, and its refinement planes are the
semiconductor/dielectric interface and the patch edges, not junctions. A 3-D band would be a new junction
refinement in a different kernel, and it would multiply a 3-D node count by the band's 150-500 lines per
axis. Not natural; not done.

## 4. Defaults off -- three ways (MEASURED)

1. **Cross-commit**: a scratch recorder run on `098553f` and on this branch, 6 fixtures (GaN E4, Si lateral,
   reference modulator equilibrium + drift-diffusion, AlGaAs/GaAs stack, in-region z junction), with the

2. **Same tree**: gate D2, bitwise.
3. **Code path**: with the option off, `build_device` issues the same `add_2d_mesh_line` calls in the same
   order (the lines are collected into lists, then issued); `_junction_band_lines` and the probe are never
   called (gate D1's log is the proof).

## 5. Recommendation (from the data)

**Do not make it the default.** Keep it opt-in, and point users to it for the cases where it wins:

- It fixes what it was built for. On the case that found the problem the junction-current error drops 8x at
  the same nominal spacing (+4.95e-3 -> -6.1e-4), and BTBT currents at an in-region junction improve 7-10x
  (Ge Zener +2.3e-2 graded at the same 0.32 nm -> +3.1e-3). Depletion capacitance improves 10-50x. On the band
  the error is cleanly second order, so two banded meshes give a Richardson estimate.
- It costs 2.4-6x the nodes and 2.3-6x the solve time (the band holds ~4 V_bi / V_t lines per junction).
- It does not help everywhere. At equal node count it is WORSE for a diffusion-limited forward current (Si
  +0.6 V: +1.1e-3 banded vs +6.1e-4 graded at h/2 with fewer nodes). It does not improve a node-sampled peak
  rate (a point value, second order in the local spacing: -7 % at h = 0.67-1 nm; graded happened to do better).
  It is neutral on z-stacked junctions, whose interface lines already put a fine spacing on the junction
  (AlGaAs/GaAs errors ~1e-4 either way). It does nothing on junction-free gated devices.
- Turning it on by default would also move every existing 2-D bipolar result with an in-region junction.

If a default change is wanted later, the data support a narrow one (the user's call): banding only regions
that have local BTBT and an in-region junction, where the graded mesh's error was 2-3 %.

## Release-note lines

- `LayeredDevsimBuilder(junction_band=True)` (new, opt-in) puts a uniform mesh band around every p-n
  junction of the 2-D builder (`carriers.junction_mesh.JunctionBand` for explicit half-width / spacing).
  It removes the irregular DEVSIM edge that lands on the junction line: the GaN-like diode current error
  drops from +4.95e-3 to -6.1e-4, a Ge Zener's BTBT current from +2.3e-2 to +3.1e-3, at 2-6x the nodes.
- Off by default; every existing result is byte-identical. Not useful for diffusion-limited currents,
  z-stacked layer junctions or junction-free gated devices (measured comparison in this note).
