# v0.15 shared infrastructure: recombination-term bookkeeping, version 2 (2026-11-06)

Branch `wip/v015_terms` (from `8bbf36c`, the v0.15 integration tip with the two-point source and the
custom-equation dispatcher). Plan `docs/plans/2026-11-04-devsim-v0.15/00_consolidated_plan.md` item
**4.0.2** (P3 section 1.3.2 and step K0; P1 section 0.3; plan 5.9 "one owner"). DEVSIM 2.11.2, scipy's
OpenBLAS (the `devsim_env` pin), UMFPACK 5.1, Windows, py3.14. "Measured" = run on this box by this
branch's tests or the scratch scripts named; "inferred" says so.

Nothing here implements kinetic traps or oxide tunnelling. This is the mechanism they use: section 4 is
their API.

## 1. What changed

* **`physics_bipolar_dd.add_recombination_term`** gained four keywords (node assembly only; all default to
  today's behaviour):
  * `carrier="both" | "electron" | "hole"`. `"electron"` stores `RTermN_<name>`, which enters
    `ElectronGeneration` only; `"hole"` stores `RTermP_<name>`, `HoleGeneration` only. The composites are
    `ElectronGeneration = -q (USRH + sum RTerm_ + sum RTermN_)` and
    `HoleGeneration = +q (USRH + sum RTerm_ + sum RTermP_)`. With no N/P term both strings are the
    version-1 strings character for character (one `_generation_exprs` builds both cases).
  * `pair=` for a single-carrier term is its EVENT rate, both directions counted (`PTermN_` / `PTermP_`).
  * `partner=(equation, coeff)`: the other row of the region each event changes (a trap row), with its
    change per event in units of q. `mechanism=` is the `noise_analysis.MECHANISMS` key (default `"gr"`;
    kinetic traps use `"trap_n"` / `"trap_p"`). Both are stored as ONE region parameter
    `_rtN_<name>` / `_rtP_<name>` = `"<equation>,<coeff>,<mechanism>"`, so the inventory reads them back
    from DEVSIM and they die with the device (no module state). Deviation from P3 1.3.2, which derived
    the partner from a naming convention (term `trap<k>` -> `TrapEquation_trap<k>`): an explicit
    declaration is no less "read from DEVSIM", serves any partner row, and does not hard-code the trap
    module's names into the term mechanism.
  * `wrt=(<var>, ...)`: extra node solution variables the term depends on. The term carries
    `<model>:<var>` (closed form from `derivs`, which must then cover Electrons, Holes AND every wrt var,
    or DEVSIM's `simplify(diff())`).
* **Composite derivatives.** Each composite (`ElectronGeneration`, `HoleGeneration`,
  `PotentialNodeCharge`) is differentiated with respect to Electrons, Holes, every variable for which one
  of ITS terms carries a derivative model, and every variable it already has a derivative for. The set is
  read from DEVSIM's model list at every rebuild. The last rule matters when a term is replaced without
  its old variable: the composite derivative is re-differentiated (to 0) instead of keeping a stale one;
  the replaced term's stale `<model>:<var>` is deleted.
* **`add_charge_term(..., wrt=None)`**: the same for `QTerm_*`; `rebuild_poisson_charge` uses the union.
* **Refusals** (all before any DEVSIM call): an unknown `carrier`; `carrier=`/`wrt=` on edge/element
  terms; `partner=`/`mechanism=` on a `"both"` term; a mechanism outside `MECHANISMS`; a partner with an
  empty name or a zero / non-finite coefficient; a `wrt` variable that is not a node model of the region;
  a closed-form `derivs` dict that misses (or adds) a variable; and one name used by two carrier kinds
  (there is no term removal, so a second kind would double-count silently).
* **`recombination_terms(device, region)`** gained three kinds: `"node_electron"` / `"node_hole"`
  (`CarrierTerm(rate, pair, partner_equation, partner_coeff, mechanism, own_equation, own_coeff)`; its
  first three fields are P3's `(rate, pair | None, partner_equation)`), and `"custom"` (plan P1 0.3):
  `CustomTermRecord(term, regions, noise_model, jacobian_exact)` for every LIVE custom term whose
  `equations()` touch the region. A term that declares no region row (unknown footprint) is listed in
  EVERY region, so none can be missed. `noise_model` = the subclass overrides `noise_sources`.
* **`noise_analysis`**:
  * `_custom_term_sources` now reads the custom terms from the inventory, over every region of the
    device (it read `custom_terms.live_terms` directly). The refusal messages are unchanged.
  * `_single_carrier_sources` (new): one `TwoPointSource` per single-carrier term whose mechanism is
    requested, P_i = V_i x event rate, rows (own carrier row, -1 electron / +1 hole) and (partner row,
    coeff). It refuses a term without an event rate (when its mechanism is requested, like the pair kinds)
    and one whose own or partner equation the region lacks. `_RegionData.two_point` gets them after the
    built-in GR source.
  * `_pair_term_models` iterates the three pair kinds explicitly (the inventory now has other kinds).
* **Tests**: `tests/test_term_bookkeeping_v2.py` (12 tests, 3 s serial, MEASURED) on the
  `solvers-devsim` CI job; `tests/test_custom_terms.py` + 1 test (child scenario `inventory` in
  `tests/_custom_terms_child.py`).

## 2. The spike: does DEVSIM 2.11.2 differentiate through named models w.r.t. a non-standard variable?

Scratch scripts (`spike_wrt_chain.py`, plus two one-off probes; not in the repo). A 1-D region with two
node solutions, Potential and U (both with equations); `M = U*U*Potential` a named node model,
`C = 3*M + Potential` a composite naming it.

| Probe | Result (MEASURED) |
|---|---|
| `simplify(diff(3*M + Potential, U))` | `((3 * M:U) + Potential:U)` -- the chain rule through the NAME works for any node solution |
| with `M:U = 2*U*Potential` defined, `C:U` values | equal to 6 U psi (closed form) |
| the equation assembly (`PotEq` node_model C) | consumes `C:U` for U's column: diagonal = 6 U psi V_i to 2.4e-16; FD of the residual 1.0e-10 (h = 1e-6) |
| `M:U` NOT defined | `C:U` evaluates to **0, silently** (no error, no warning); the U column is 100 % wrong |
| `C:U` created BEFORE `M:U` | `C:U` keeps a stale cached 0 after `M:U` is created; it is recomputed only when a solution it depends on changes |
| `M:U` deleted while referenced | no error; `C:U` then evaluates 0 |
| `diff(3*M, Nope)` (Nope not a variable) | `(3 * M:Nope)`, evaluates 0 silently |
| string region parameters | `set_parameter(..., value="TrapEquation_trap0")` round-trips (used for the partner record) |

So **no explicit derivative strings are needed**: DEVSIM's own diff is used for the composites. The hazards
are silent zeros, and the design closes them: every declared variable gets its `<term>:<var>` model
before the composite derivatives are rebuilt, an unknown variable is refused, and a closed-form `derivs`
dict must cover every variable.

**Build time for 45 bins** (P3 K0 step 3; `spike_45bins.py`): 45 extra variables, each with an electron
and a hole term (90 single-carrier terms, closed-form derivatives), added one at a time: 1.1 s in total
(MEASURED; 0.01 s for 5 bins). It grows as K^2 because each add rebuilds the composites with up to K
variable derivatives, all of named models (no long expression is differentiated). The first assembly is
0.03 s and a DC solve 0.06 s on 101 nodes. The D1c 25 s cost (DEVSIM differentiating a 45-term explicit
sum) does not arise.

## 4. API for the later agents

**Kinetic traps (P3 K1-K3, next).** For a bulk level k with variable `TrapU_trap<k>` (create the
`node_solution` and its equation FIRST):

```python
BP.add_recombination_term(dev, r, "trap0", Rn_expr, carrier="electron", wrt=("TrapU_trap0",),
                          derivs={"Electrons": ..., "Holes": ..., "TrapU_trap0": ...},
                          pair=Pn_expr, partner=("TrapEquation_trap0", +1.0), mechanism="trap_n")
BP.add_recombination_term(dev, r, "trap0", Rp_expr, carrier="hole", ...,
                          pair=Pp_expr, partner=("TrapEquation_trap0", -1.0), mechanism="trap_p")
BP.add_charge_term(dev, r, "bulk_traps", Q_expr, wrt=("TrapU_trap0", ...), derivs={...})
```

* The SAME name for the electron and hole branch is allowed (`RTermN_trap0`, `RTermP_trap0`); it may not
  also be a `"both"` term (`RTerm_trap0`, the fast-trap pair): install one or the other.
* The partner coefficient follows the trap row's own convention (P3 1.3.4: `TrapNode = +q (R_n - R_p)`,
  so +1 for the electron branch, -1 for the hole branch). The noise source is then exactly P3's
  S = q^2 V [2 P_n |y_t - y_n|^2 + 2 P_p |y_p - y_t|^2]; K3 only has to supply `pair`, `partner` and
  `mechanism`. The FDT gate must still pin the signs (a wrong relative sign is an O(1) miss).
* **One gap K3 must close:** `noise_spectrum` refuses an event row of a NON-continuity equation on a
  circuit-contact node. A trap equation keeps its bulk row at contact nodes (P3 0.3), so DEVSIM's own
  adjoint field is valid there, but the refusal fires because the partner row covers every node. Either
  restrict that refusal to equations whose contact row is replaced, or skip contact nodes in the source.
  **Correction (2026-11-06, v0.15 close-out):** closed by K3: the refusal is restricted to equations a contact REPLACES, and a
  partnered event whose own row a contact replaces carries no source (the contact-node rule,
  docs/audit/2026-11-06-v0.15-trap-noise.md section 1). The partner-less convention of gate (b) above still
  counts contact-node events (an O(h/L) inconsistency flagged there, not changed).
* The trap row itself (`TrapEquation_*`) is not a recombination term; it goes through
  `eq_registry.record_region_equation` as P3 says.

**Oxide tunnelling (P1, `wip/v015_oxtun`).** No change is needed: the `custom_terms` public API is
unchanged, and the noise refusals fire for exactly the same terms as before (every live term of the
device; a term without `noise_sources` or with `jacobian_exact=False` is refused, same messages). Declare
`equations()` (the oxtun term presumably already does, for `rows_live`; **Correction (2026-11-06, v0.15 close-out):** it does, as
does the nonlocal-BTBT term) so the inventory attributes the
term to its own regions; an undeclared term is listed under every region.

**Nonlocal BTBT (P1 item 3, later):** same as oxide tunnelling.

## 5. Moved results

None. No digest was re-recorded. One string can change where nothing gated it: when a term is added AFTER
`setup_bipolar_dg(quantum_srh=True)`, `ElectronGeneration:QLambdaP` (and the hole twin) are now rebuilt by
DEVSIM's diff of the composite (`-ElectronCharge * (USRH:QLambdaP + ... + RTerm_dgsrh:QLambdaP)`) instead of
staying DG's hand-written `-ElectronCharge * RTerm_dgsrh:QLambdaP`. The value is the same bit for bit
(every other symbol is a missing model, i.e. 0) and, unlike before, it would include a later term's own
Lambda derivative. The shipped builders install DG last, so no shipped path takes it (inferred from the
call order in `setup_bipolar_dg`'s callers; the cross-version call log above covers the DG tests and is identical).

## 6. Open points

* The K^2 rebuild cost is fine for 45 bins (1.1 s); for many hundreds of terms a batch add (one rebuild)
  would be the fix.
* Single-carrier terms are node terms only; an edge/element single-carrier term (nonlocal BTBT's local
  analogue) would need the same split of `ElectronGenerationEdge` / `Elem*`. Nothing asks for it yet.

## Release-note lines

* `add_recombination_term(carrier="electron"|"hole")`: a rate that changes one carrier only (kinetic trap
  capture/emission branches), with its event rate, partner row and noise mechanism for the noise
  analysis. Default `"both"` is unchanged, character for character.
* `add_recombination_term` / `add_charge_term(wrt=...)`: terms may depend on extra node solution
  variables; the composites' Jacobian follows them (DEVSIM's chain rule through named models, measured).
* `recombination_terms()` is the one inventory of every term the noise analysis must see: the new
  single-carrier kinds and the live Python-assembled custom terms ("custom").
