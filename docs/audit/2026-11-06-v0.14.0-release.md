# DynaMeta v0.14.0 -- release note (2026-11-06)

Branch `feat/devsim-2.11-v0.14`, on top of v0.13.1 (main `b22a78f`). This is the **DEVSIM release**:
the carrier-transport side of DynaMeta (the DEVSIM-based drift-diffusion, density-gradient and
equilibrium solvers in `dynameta.carriers`) moves to DEVSIM 2.11.2 and gains most of the physics a
device simulator is expected to have. One fix lands outside DEVSIM, in the SOA gain model.

What is in it:

- DEVSIM 2.11.2, with DynaMeta now choosing DEVSIM's math library (BLAS) itself (section 1);
- new opt-in physics: band-to-band and gate-oxide tunnelling, trap levels and interface traps,
  Auger / radiative recombination, band-gap narrowing, incomplete ionization, heterojunctions,
  bipolar density-gradient, small-signal noise, extended (128-bit) precision (section 5);
- several defaults that change, chosen by the user on 2026-11-04 / 2026-11-06 (section 2);
- corrections that move results, some in code that shipped in v0.13 (section 3);
- new refusals and warnings, each with its opt-out (section 4);
- a correction of a DEVSIM geometry defect on unstructured meshes, applied automatically by both
  builders (section 6).

**Read sections 2 and 3 before upgrading.** Several defaults and results change on purpose. Every
number below is from the per-topic audit note named next to it (list in section 11); "measured" there
means run on the dev box, and the notes say which values are inferred.

## Terms used here

- **SG flux** (Scharfetter-Gummel): the standard way a drift-diffusion code writes the current along
  one mesh edge. It is built from the Bernoulli function B(v) = v/(e^v - 1), where v is the potential
  drop along the edge in units of kT/q.
- **DG** (density gradient): a quantum correction that adds a "quantum potential" to each carrier so
  that carriers are pushed away from hard walls (gate oxides), as Schrodinger-Poisson would give.
- **BGN** (band-gap narrowing): the shrinking of the band gap at high doping.
- **BTBT**: band-to-band tunnelling (Zener) generation inside a semiconductor.
- **ssac**: DEVSIM's small-signal AC solve (admittance Y(f) around a DC operating point).
- **FDT** (fluctuation-dissipation theorem): at equilibrium, current noise S_I = 4kT Re Y. It is the
  main oracle for the noise work.
- **D_it**: the density of interface trap states per unit area and energy.
- **Well-centred element**: a triangle or tetrahedron whose circumcentre lies inside it AND inside
  every face. DEVSIM's box-method geometry is exact only on such elements (section 6).
- **Kuhn (path) tetrahedra**: the 6 tetrahedra of a box obtained by walking its three edge directions in
  every order. They are well-centred for DEVSIM's purposes, so DEVSIM's volumes are exact on them.
- **Mott density**: the doping above which dopants form a band and are fully ionized; a single-level
  freeze-out model is wrong above it.
- **kT**: the thermal energy, 25.85 meV at 300 K, 6.6 meV at 77 K.

## 0. Before you upgrade: the five things most users will notice

1. **`pip install dynameta[solvers]` now needs `devsim>=2.11.2`** (was `>=2.10`). On Windows DynaMeta
   pins DEVSIM's BLAS before the first `import devsim` (section 1).
2. **3-D DEVSIM devices are meshed differently** (`Stacked3DSpec.mesher="tensor"` is the default). The
   old gmsh mesh inflated every 3-D volume by 1.20-1.52x; integrated charges, sheet charges and currents
   move by 15-25 % (section 2).
3. **`TransportModel.chi_eV` and `band_gap_eV` default to `None`** (were 4.5 / 3.6 eV). A device with
   two different semiconductor materials refuses to build until you set the electron affinities
   (section 2).
4. **2-D impact ionization uses an isotropic element quadrature.** Mesh-aligned devices barely move;
   oblique current moved by up to 3.7x (section 2).
5. **The default bulk SOA (`BulkGainParams()`) now peaks at 1612 nm**, not 1560 nm, because the
   In0.53Ga0.47As band gap was corrected. For a C-band device pass the gap explicitly (section 3).
   **Superseded in v0.15.1:** use `BulkGainParams.c_band()`, a sourced InGaAsP-on-InP material with its
   peak at 1549.7 nm (`2026-11-08-v0.15.1-release.md`).

## 1. DEVSIM 2.11.2 and the BLAS / solver environment

(`2026-11-03-devsim-2.11-core.md`)

- **Floor `devsim>=2.11.2`** in the `[solvers]` extra. 2.11.2 keeps the UMFPACK solver across
  `reset_devsim()`, loads its math libraries once at import, and (2.11.1) accepts a BLAS with prefixed
  symbol names. DEVSIM 2.10 -> 2.11.2 moved no printed value in the 33 DEVSIM validations; the only
  round-off-level movements come from the BLAS change below.
- **DynaMeta now chooses DEVSIM's BLAS** (the linear-algebra library its solver calls). All DEVSIM imports
  go through one module, `dynameta.carriers.devsim_env`, which sets the library before the first
  `import devsim`. Order, first match wins:
  1. your `DEVSIM_MATH_LIBS` (always wins);
  2. pip `mkl`'s `mkl_rt` (full path), if you installed `dynameta[pardiso]`;
  3. the LP64 OpenBLAS bundled in your scipy wheel (prefix `scipy_`);
  4. DEVSIM's own search.

  Why: on Windows, with `DEVSIM_MATH_LIBS` unset, DEVSIM took whatever `libopenblas.dll` came first on
  `PATH`. On the dev box that was a 2019 OpenBLAS 0.3.7 from an unrelated install, which crashed
  fresh-process imports under load: 9 of 72 at 24 concurrent processes, 0 of 144 after the pin.
  **Linux and macOS are unchanged by default.** Control: `DYNAMETA_DEVSIM_BLAS=pin|off|auto`
  (`pin` applies the scipy pin on Linux/macOS too; `off` restores DEVSIM's own search everywhere).
- **pip `mkl` switches DEVSIM to MKL-PARDISO** (DEVSIM's own behaviour, now documented). DynaMeta then
  sets `DEVSIM_NEW_SYMBOLIC=1` unless you set it: with DEVSIM's default reuse of the symbolic
  factorisation, the 2-D bipolar diode validation did not converge at any bias. With it, PARDISO
  matches UMFPACK to <= 1e-14 and is 1.3-2x faster.
- **Equilibrium semiconductor regions set up ~500x faster.** DEVSIM's `simplify()` of the
  Fermi-integral Jacobian took 150-300 s per region; DynaMeta now replays DEVSIM 2.11.2's own stored
  result, bit-identical. `test_devsim_smoke.py` 314 s -> 21 s; the 33 DEVSIM validations 8890 s ->
  2740 s (e.g. `gated_dd_2d` 253 s -> 2.4 s, `carriers_3d_multisemi` 1285 s -> 19 s). If a future
  DEVSIM simplifies differently, the cache misses and the live (slow but correct) path runs.
- Two environment changes chosen by the user (lazy ngsolve, a per-process 3-D mesh path) are listed
  with the defaults in section 2.

## 4. New refusals and warnings

Warnings are `dynameta.warning_types` classes: `UnreliableResultWarning` (a RuntimeWarning: the
returned value may be wrong) or `AdvisoryWarning` (a UserWarning: the result is trustworthy, read the
note). Filter them with the standard `warnings` module if you have decided to accept the condition.

| Trigger | What you get | Why | Opt-out / remedy |
|---|---|---|---|
| A Pearson-Bardeen lowering alpha that zeroes a donor or acceptor level below 1e17 cm^-3 | `IonizationUnitsError` (a ValueError) at `IonizationModel` construction | The field is in eV*m but the literature quotes eV*cm: an unconverted 3.1e-8 zeroes a 45 meV level at 3.06e12 cm^-3, and the clamp at zero hid that as full ionization | pass literature values through `IonizationModel.pearson_bardeen(..., alpha_D_eVcm=, alpha_A_eVcm=)`, which converts |
| Incomplete ionization in a region doped above the Mott density (donors 3.74e18, acceptors 4.5e18 cm^-3) | one `UnreliableResultWarning` per region, quoting the worst non-ionized fraction | The single-level model freezes dopants out where they are really fully ionized (Si:P at 1e19 cm^-3, 300 K: 39 % ionized) | `N_mott_D_m3` / `N_mott_A_m3` on `IonizationModel` (`math.inf` silences); or switch incomplete ionization off there |
| del Alamo BGN in a region with N_A > 7e17 cm^-3 | one `UnreliableResultWarning` per region | the fit has no basis in p-type or compensated material | use Slotboom / Klaassen for p-type regions |
| BTBT in a region with `BipolarOptions(T_K != 300)` | `AdvisoryWarning` at `setup_btbt` | A, B, P are used as given (300 K values); B ~ E_g^(3/2) is not rescaled (v0.15) | supply A, B fitted at T_K (the warning still fires: the code cannot tell which T a set belongs to) |
| Impact ionization (2-D / 3-D element form), BTBT (2-D / 3-D) or Hooge noise on a mesh whose element volumes are not exact | `InexactElementGeometryError` (a NotImplementedError) from `element_geometry.check_element_geometry` | DEVSIM's element volumes are wrong on non-well-centred elements (an obtuse triangle reads up to 11.1x; the pre-v0.14 gmsh noise bar 1.2249x, 544 of 932 tets inexact, and its Hooge result 1.0546) | the builders correct the geometry automatically (`exact_geometry=True`), so it fires only on raw-API devices or `exact_geometry=False` builds: call `devsim_geometry.apply_exact_geometry` (section 6) right after `create_device`, or use a library mesh. Diffusion and GR noise are not element quantities and still run |
| A heterostack at T != the affinities' reference temperature | `AffinityTemperatureError` | section 2, last row | `on_chi_temperature`, `chi_reference_T_K` |
| A heterostack with a defaulted `chi_eV` (or a bipolar one with a defaulted `band_gap_eV`) | ValueError naming the field | section 2 | set the field |
| A non-isothermal heterostack (two T_K values, or a T_K bipolar region next to a 300 K region) | NotImplementedError "NON-ISOTHERMAL" | Fermi-level alignment is an isothermal statement | one temperature for the stack |
| An `n_i_m3` inconsistent with `band_gap_eV` at T_K (bipolar heterojunction) | ValueError ("... AT that temperature") | `n_i_m3` is a direct input and must be given at T_K | give n_i at T_K |

| `mesher="gmsh", exact_geometry=False` | `UnreliableResultWarning` naming "pre-v0.14" and "exact_geometry=False" | DEVSIM's uncorrected geometry (section 2) | leave `exact_geometry=True` (the default) |
| The exact geometry has negative assembled couplings (gmsh / Delaunay meshes: ~1 % of edges on the gmsh stack) | ONE `UnreliableResultWarning` per device, "exact geometry on device ...", with the counts | the M-matrix property of the SG discretisation is not guaranteed there (measured harmless on the gmsh stack, section 6) | `exact_geometry="clip"` or `"raise"`, or a boundary-conforming remesh |

## 5. New physics (all opt-in; defaults off)

Defaults-off is guarded in every workstream. Since the SG kernel change (section 2) these guards are
numeric comparisons against the pre-change tree at derived round-off tolerances (they were byte
digests); `2026-11-04-sg-flux-two-bernoulli.md` section 4 lists them.

| Feature | How to turn it on | Validated against | Note |
|---|---|---|---|
| **Band-to-band tunnelling** (local Kane/Hurkx, inside the bipolar Newton) | `setup_bipolar_region(btbt=...)`, `TransportModel.btbt`, `Stacked3DSpec.btbt`; Si set `SILICON_HURKX` (Hurkx 1992) | Zener I-V vs the analytic depletion estimate, < 1 % over 2.5 decades; zero at equilibrium (Hurkx D factor); isotropic element field in 2-D / 3-D | `2026-11-03-devsim-tunneling.md` |
| **Gate-oxide tunnelling current** (post-processed) | `oxide_tunneling_current`, builder `extras["oxide_tunneling"]`; Fowler-Nordheim, full Schuegraf-Hu or Tsu-Esaki/WKB | oxide field vs Gauss's law 5e-8; FN slope -B to 1e-6; `reliability.leakage.tsu_esaki_current` == scipy quad to 6e-11 | the carrier profile is that of an ideal capacitor (section 7) |
| **Trap levels**: SRH at any E_t, several discrete bulk levels with charge, interface traps (uniform / Gaussian / discrete D_it, fixed oxide charge, surface SRH) | `setup_bipolar_region(srh_trap_energy_eV=)`, `TransportModel.srh_trap_energy_eV`, `physics_traps.TrapLevel`, `InterfaceTraps`, `LayeredDevsimBuilder(interface_traps=)`, `Stacked3DSpec(interface_traps=)`; `energy_reference="intrinsic"` (default) / `"conduction"` / `"valence"` (use the band references for DLTS-quoted levels) | tau(E_t) closed form, neutrality root, MOS LF C-V stretch-out vs Nicollian-Brews, dV_FB = -Q_f/C_ox, S = sigma v_th N_it | quasi-static (section 7); `2026-11-03-devsim-traps.md` |

| You want | Use |
|---|---|
| a heavily doped or wide-gap junction's DC current | `extended_precision=True` (DC only; for ssac / noise use the DC dI/dV) |
| an accumulation / inversion layer at a gate oxide with quantum confinement | bipolar DG with `setup_dg_insulator_wall` and `gamma=GAMMA_WALL` |
| smooth potentials, or comparison with published DG numbers | DG with gamma = 1 (the default) |
| a 3-D device | the default tensor mesher (exact without correction, fewer nodes); `mesher="gmsh"` is accurate too now (geometry-corrected); `exact_geometry=False` to reproduce a pre-v0.14 gmsh number |

| 2-D substrate current / HCI | the default element quadrature; `quadrature="edge"` only for mesh-aligned current |

## 6. DEVSIM geometry correction (automatic in the builders)

(`2026-11-06-devsim-geometry-workaround.md`)

**The defect.** DEVSIM 2.11 builds its finite-volume geometry (node volumes, edge couplings) from the
circumcentric dual of each triangle or tetrahedron, but adds the MAGNITUDES of the pieces instead of
their signed values. On a well-centred element the two agree. On any other element (obtuse triangles,
most gmsh / Delaunay tetrahedra) DEVSIM over-counts. The library meshes DynaMeta builds (2-D
rectilinear, 3-D Kuhn tensor) are not affected; your own meshes may be.

**The workaround.** `dynameta.carriers.devsim_geometry.apply_exact_geometry(device, region, *,
negative="raise")` recomputes DEVSIM's own construction with the signs kept and writes it into
DEVSIM's built-in `ElementEdgeCouple` (and, in 3-D, `SurfaceArea` / `ContactSurfaceArea`). DEVSIM then
rebuilds `EdgeCouple`, `NodeVolume` and the element volumes from it with its own code, so every
equation DEVSIM assembles and every DynaMeta kernel that reads those models sees exact volumes.
**Decision (user, 2026-11-06): automatic, default policy `"warn"`, gmsh mesher kept.**
- Both builders call `devsim_geometry.correct_device_geometry(device, exact_geometry)` right after
  `create_device`: `LayeredDevsimBuilder(..., exact_geometry=True)` and `Stacked3DSpec.exact_geometry`
  (also `Stacked3DSpec.from_design(..., exact_geometry=...)`). `True` means negative policy `"warn"`;
  `"raise"` and `"clip"` select the other policies; `False` keeps DEVSIM's uncorrected geometry. The
  per-region reports are on the builder as `geometry_reports`.
- `apply_exact_geometry` (for raw-API devices) also defaults to `negative="warn"` now.
- **Library meshes are not touched.** A read-only test (`geometry_already_exact`: devsim `get_*` calls
  only) decides first; on the 2-D rectilinear and 3-D Kuhn meshes it finds no negative piece beyond
  64 eps h^(d-1) and returns without writing. Gates: a recorder that wraps every non-`get_` devsim
  function sees no call on those meshes (and sees the write on a 5-tet mesh); a tripwire on the write
  path never fires in builds of 3 tensor topologies and the 2-D builder (and fires on the gmsh mesher).
  The read costs 0.01-0.5 s per region on the validation topologies and 1.85 s on the largest measured
  (60 nm patch cell, 108,864 tets).
- **`mesher="gmsh"` stays** (no removal in v0.15) and is corrected by default.

**What moved (MEASURED):** nothing on library meshes. The D2c tensor gates M1-M5
(`validation/devsim_3d_mesh.py`) give the same values as recorded (volumes to 8.9e-16, sheet charge and
Gauss to 2-3e-16, lateral spread 0, D_it ratio 0.9888). For gmsh users:

Measured on the legacy gmsh 3-D stack (`validation/devsim_geometry.py`):

| Problem | DEVSIM geometry (`exact_geometry=False`) | `"warn"` (default) | `"clip"` |
|---|---|---|---|
| sum NodeVolume / true volume (semiconductor / oxide) | 1.1957 / 1.2932 | 1 + 2.2e-16 | -- |
| lateral psi_s spread (MOS cap, 0.5 V) | 4.97 mV | 0.21 mV | 0.31 mV |
| series capacitor C / C_exact | 1.203236 | 1 - 5.6e-16 | 1 + 6.8e-4 |
| bipolar MOS cap Gauss residual at 0.5 V | 0.228 | 1.28e-5 | 7.6e-4 |

**Negative couplings.** The exact geometry can have negative assembled couplings near non-conforming
boundaries: on that stack 124 of 13473 (semiconductor) and 130 of 12746 (oxide) edges, worst
-0.028 / -0.053 L^2, no negative node volumes; a random-point Delaunay square reaches -24 L. The
`negative=` policy says what to do:

- `"warn"` (the default): keep the exact values and emit one `UnreliableResultWarning` per device.
  Most accurate on the realistic mesh (60x better than `clip` above); the bipolar Newton converged
  with the negatives.
- `"raise"`: refuse and report the counts; the device is left untouched (the builder measures every
  region before writing any).
- `"clip"`: set negatives to zero (keeps the M-matrix property) and return the measured cost; on the
  pathological random square it added 14x the region volume.

On meshes where DEVSIM is already exact (Kuhn, rectilinear) the call only reads (see above). Cost: ~0.35 s per 10k-tetrahedron region. After it, the element-geometry check
(section 4) passes. In 3-D, `SurfaceArea` changes on obtuse interface triangles, while
`physics_traps.interface_node_area` keeps barycentric thirds there.

## 7. Known limitations

**Measured or inferred gaps in this release:**

- **Impact ionization.** No device with genuinely 2-D current (a well corner, a drain corner) is in the
  validation set. The move there is inferred from the uniform and harmonic-field gates (the old edge
  form read 0.27-0.36 of the truth at b/E = 4), not measured on a device. The edge form on a
  non-rectilinear 2-D mesh is not refused.
- **FD built-in correction Delta(u)** (`physics_bipolar_dd`). The docstring says "under 1 %
  everywhere degeneracy matters"; measured against scipy F_1/2 quadrature it is +3.27 % at eta = 2,
  +2.68 % at 3, +1.72 % at 5, +1.16 % at 7, +0.78 % at 10, +0.60 % at 15, +0.55 % at 20. So the
  "< 1 %" holds from eta ~ 8 up; in the moderately degenerate range eta 2-7 the offset error is 1-3 %
  of Delta (~1 mV at eta = 5, 250 K). Docstring correction pending (`2026-11-06-v0.14-temperature-fixes.md`).
- **Gate-oxide tunnelling is one-sided and post-processed.** Fowler-Nordheim and Schuegraf-Hu give a
  nonzero current at equilibrium, the current never removes carriers from the body, and the result is
  wrong for a floating or deep-depleted body or heavy FN injection. Self-consistent tunnelling is v0.15.
- **BGN double count on degenerate layers.** Both builders hard-wire Fermi-Dirac statistics, so a
  Boltzmann-fitted ("apparent") BGN is double-counted on degenerate layers; an `AdvisoryWarning` fires.
  Fix planned for v0.15.
- **BGN presets are unpaired with n_i.** No shipped set was fitted with n_i = 1.0e10 cm^-3 (old
  Slotboom ~1.44e10, del Alamo ~1.36-1.45e10, both inferred); pairing them with the modern 9.65e9
  under-predicts n_ie^2 by about 2.3x (~21 meV). Pass the n_i the preset was fitted with.
- **Compensated nodes below 7e17 cm^-3 acceptors** move under the del Alamo correction without a
  warning (e.g. 5e17 / 5e17: 6.67 meV -> 0).
- **Hooge noise on uncorrected gmsh / Delaunay meshes is refused** (section 4): raw-API devices and
  `exact_geometry=False` builds. With the correction (automatic in the builders, or
  `apply_exact_geometry`) it is exact (3e-9 on an oblique 3-D resistor).
- **Traps are quasi-static.** Trapped charge is an instantaneous function of n and p, so ssac and
  transient with CHARGED traps are not charge-conserving: the FDT misses by 5.6e-3 / 6.6e-2 at
  100 kHz / 10 MHz (pinned by a strict xfail). DC and LF C-V are exact.
- **Thermionic-emission heterointerfaces have no noise source** (the interface shot noise is
  missing): the FDT misses by -0.69 at 1 Hz on a resistive interface (strict xfail).
- **Extended precision does not fix ssac or noise.** Re Y(1 Hz) of a p+n diode moves from -0.27 to
  -0.073 S/m^2 against a true 2.6e-5. More generally, ssac Re Y at low frequency is round-off in double
  (repeat spread 3-6e-4 on a 0.1 V Si diode); DEVSIM's dBdx is inaccurate near v = 0 (2.4e-10 at 1e-6,
  4.8e-5 at 1e-12), which reaches only Jacobians and the ssac / noise systems.
- **Default absolute Newton tolerance** (1e10 m^-3) is below one ulp on degenerate devices
  (densities above ~1e24 m^-3), so Newton can stall for 10-18 iterations there. A density-scaled
  tolerance is planned for v0.15.
- **Density-gradient inversion** converges only up to weak inversion in 1-D; accumulation and
  depletion converge for both carriers.
- **External-generation shot noise has no oracle** (no photodiode gate yet).
- **Still refused by name:** 2-D lateral sidewall heterointerfaces, unipolar-next-to-bipolar
  interfaces, 3-D bipolar heterostacks, bipolar heterojunctions whose band gap disagrees with n_i.
- **Tensor mesher:** axis-aligned boxes only (layers, a centred patch, centred full-layer inclusions); a
  patch or inclusion edge refines the whole lateral line.
- **No Mott-transition model**: incomplete ionization above the Mott density only warns. Schenk BGN,
  temperature-dependent Auger / radiative coefficients and III-V recombination presets are not shipped.
- **BTBT parameters are not rescaled with temperature** (warning, section 4).

## 9. CI

- **New `solvers-devsim` job** (ubuntu, py3.12, `[solvers]` + mpmath, 40-min cap). It runs 18 DEVSIM
  test modules, `-m "not slow"`. The first 13 ran on no CI leg before 2026-11-04: each one
  importorskips devsim, which only the solver jobs install, and those name their files explicitly.
  Measured for those 13 under WSL Ubuntu: 488-567 s; the five added since measured ~65 s together on
  the Windows dev box (per-file timings in the job's comment).
- **Coverage drift gate** `tests/test_ci_solver_coverage.py`, on every `test` leg (no solvers needed):
  fails when a test file that importorskips devsim / ngsolve / netgen / gmsh (or calls
  `import_devsim`) is named by no solver job, and pins every named file to exist. **New in the close-out:**
  it also shell-splits every pytest `run:` command (continuations joined as bash does) and requires
  every positional argument to be an existing path under `tests/` with no stray backslash. A typed
  `\n` in place of a line continuation happened twice during the release; it is valid YAML and the
  file-name pattern does not see it, but bash passes pytest a stray `n` argument.
- `tests/test_devsim_heterojunction.py`'s equilibrium built-in-potential gate is no longer `@slow`
  (0.8 s on the dev box since the simplify replay) and runs on the PR job; the nightly `@slow` set is
  27 tests.
