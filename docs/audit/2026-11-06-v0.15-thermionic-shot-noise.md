## 1. What was wrong

A D1a thermionic-emission (TE) heterointerface is a DEVSIM `fluxterm` on each continuity equation, and it
had no noise source. Wherever the interface resistance matters, the impedance-field sum was missing a
physical source, so the fluctuation-dissipation theorem (FDT) failed. It was a strict xfail that missed by
-0.69 at 1 Hz with A* x 1e-6.

The physics: each direction of the Richardson current is an independent Poisson stream of carriers over the
barrier. So, per node pair i,

    S_i = 2 q A_i (J_01 + J_10)_i |y_r0,i - y_r1,i|^2 .

This is 4kT G_int at zero bias and 2qJ coth(qV/2kT) under bias.

## 2. What changed

**`physics_heterojunction`**
* `thermionic_flux_and_pair(pref, w0, w1)` builds both strings from the same w0 / w1. It is the ONE source
  of truth for them:
  * flux = pref (exp(w0) - exp(w1)). This is byte-identical to the v0.14 string, and gated.
  * pair = |pref| (exp(w0) + exp(w1)) = J_01 + J_10.
* `setup_heterointerface_carriers(model="thermionic")` also writes the interface model `<iface>_HJ<n|p>_pair`
  (name from `pair_model_name`, suffix `TE_PAIR_SUFFIX`). No equation references it, so DC and ssac are
  unchanged (cross-version, section 5).

**`noise_analysis`**
* `_interface_sources(device, region_names, mech)` provides `te_n` / `te_p`. It runs only in noise_spectrum's
  source collection; the GR, Hooge and custom-term code is untouched. For each interface whose two regions
  are both noise regions, and for each fluxterm interface equation:
  * **Refusals.** It requires a fluxterm between the same continuity equation of both regions. A `hybrid`
    equation, or a fluxterm on any other equation, raises `NotImplementedError` ("no noise model").
  * **Pair model.** It requires the pair model. Without it, it raises `RuntimeError` (decision 44). This is
    checked only when te_n / te_p is requested; excluding the key skips the check.
  * **Pairing.** It reads DEVSIM's own node pairs: the interface models `node_index@r0` / `node_index@r1`,
    in the order `get_interface_model_values` reports them. It cross-checks them against an independent
    coordinate pairing: the two regions' interface element nodes, matched on (x, y, z) within 1e-12 of the
    device extent, asserted one-to-one and equal to DEVSIM's pairs.
  * **Area.** A_i is each region's `surface_area_model` node model (`SurfaceArea`) at the pair. That is what
    DEVSIM's fluxterm assembly multiplies the flux by. Read in source: `InterfaceEquation.cc`,
    `NodeVolumeType2Assemble`, which loads +J SA0[node0] into the r0 row and -J SA1[node1] into the r1 row.
    MEASURED against the assembled residual (section 3). The two copies' areas must agree on every loaded
    pair (1e-12 of the largest). Otherwise DEVSIM's own flux does not conserve current and the noise
    refuses.
  * **Active pairs.** The source covers only the pairs DEVSIM actually loads (`_flux_active_pairs`, which
    mirrors `GetActiveNodesFromList`, read in source). A node copy is skipped when a contact on the same
    region at that node solves the same equation, or when ANOTHER interface at that node carries an equation
    of the same name on that side.
* `TwoPointSource` gains `interface: Optional[str] = None`, a new last field with a default.
* `NoiseSpectrum` gains `by_interface: Dict[str, Dict[str, ndarray]]` (default `{}`). An interface source
  goes there, not into `by_region` / `by_region_mechanism`. The invariant becomes
  `S = Sum by_region + Sum by_interface = Sum by_mechanism`.
* `maps=True` splits each interface event equally among its node rows, i.e. half to each copy.
* `te_n` / `te_p` were already in `DEFAULT_MECHANISMS`. They now have a provider, so the default changes S
  for every TE device (decision 43).
* This also builds the per-interface attribution (`by_interface`) that the two-point-source note lists as
  missing. A custom term can use it by setting `TwoPointSource.interface`.

* Keep the default `mechanisms`. The TE source is then present wherever the device has a TE interface, and

## 3. T0: the area DEVSIM's flux assembly uses (measured first)

Method. Set the flux model (and its derivatives) to a unit constant, then to zero, at the same state. Take
the residual difference -(rhs_1 - rhs_0) per region row. The round-off bound per row is
16 eps (Sum |terms of the row| + |w|), where the row's terms are the edge currents times EdgeCouple and the
generation times NodeVolume.

| Mesh | Assembled weight vs the source's area | vs SurfaceArea | vs `physics_traps.interface_node_area` |
|---|---|---|---|
| 1-D (xfail diode) | exactly +1 / -1 | equal | equal |
| 2-D z-stack, lateral 10 -> 50 nm | <= 1.4e-16 of max (0.093 of the bound) | equal on the interface's nodes; SurfaceArea also holds the region's CONTACT faces | equal |
| 2-D split top layer (corner shared by jn, jn2, jv) | <= 3.3e-16 | equal | equal. The mesher gives the corner to the FIRST interface; jn2 loses its half-edge (0.99 of 1 um loaded) |
| 3-D Kuhn tensor (graded axes) | <= 3.2e-16 (0.12 of the bound) | equal | equal |
| 3-D jittered, DEVSIM geometry | <= 2.2e-16 | equal (sum 1.00598 x the true area) | off by **11.0 %** of max |
| 3-D jittered + exact geometry (both regions) | <= 1.6e-16 | equal (the OVERWRITTEN SurfaceArea; sum exact) | off by **4.6 %** (barycentric thirds on obtuse triangles) |
| 3-D split (jn, jn2, jv share a line of nodes) | <= 3.2e-16 | **off by up to 100 %** of max: at the shared nodes SurfaceArea sums both interfaces, and DEVSIM SKIPS those pairs (18 of 24 jn pairs, 12 of 18 jn2 pairs loaded) | off by 25-75 % |

Conclusions:
* The area is DEVSIM's `SurfaceArea` over DEVSIM's active pairs. Measuring it beat assuming it in two ways.
* `interface_node_area` is right only on well-centred single interfaces.
* `SurfaceArea` alone is wrong wherever interfaces share nodes.

**DEVSIM findings (not ours to fix; nothing posted upstream):**
1. On gmsh interfaces that meet along a line, DEVSIM drops the TE flux at the shared nodes entirely. It
   prints only "interface shares a node" warnings. There the pairs carry neither current nor noise, so the
   noise is consistent with that, but the device has a current-free seam.
2. With the geometry correction on one region only, the fluxterm is non-conservative: +J A0 against
   -J A1 with A0 != A1. The noise refuses that.

ebd9e65 dynameta` with this tree's validation fixtures.

**Adversarial checks.** Each passing gate has a perturbation that must break it:
* Equal area shares, same total: 2-D +2.27 %, 3-D Kuhn +1.30 % (both > 1e-3).
* Loading the pairs DEVSIM skips (no active mask, SurfaceArea as the area) on the split 3-D stack: +151 %.
* Dropping te_n / te_p on the xfail fixture: -0.69.
* `interface_node_area` instead of the assembled area moves the 3-D FDT by only -2.3e-6, below the budget.
  That is why T0 is a separate per-node gate: it catches 4.6-11 % per node.

**Finding against the plan's T-c oracle.** The plan's form S = 2q(J + 2 J_s) with ONE J_s = (kT/q) G_0 misses
by -44 .. -57 % forward and by -0.3 .. -6 % reverse (MEASURED). The cause is that the isotype junction's
reverse stream J_10 depends on bias: the barrier-side interface density moves from 4.6e19 to 7e16 m^-3 over
+8 kT/q, so the J-V curve is not ideal.
* For the quasi-Fermi-level flux, J_01 / J_10 = exp(q dE_F / kT) EXACTLY.
* An interface-dominated device has dE_F = V.
* So S = 2qJ coth(qV/2kT) is exact, and that is the gate.

It is the same physics as the plan's form, with J_s(V) = J / (e^v - 1).

**Not done.**
* P3's T-c' crossover (series-chain oracle as the bulk takes over). Not in the brief's gate list. T-b shows
  the source tracks the interface share at zero bias.
* T-e, the native adjoint on the interface copies against scipy. MEASURED agreement is ~1e-9 relative.
  However, the equilibrated condition number is 1.85e11, so the derivable bound is eps x cond = 4e-5, and a
  1e-12 gate would have been tuned, not derived. The FDT gates are the independent check of those fields.

## Release-note lines

* **Behaviour change (noise):** thermionic-emission heterointerfaces now carry their shot noise,
  S = 2q (J_01 + J_10) A per node pair (mechanisms `te_n` / `te_p`, on by default). `noise_spectrum` results
  change for every device with a thermionic interface. The old number was missing a physical source and
  failed the fluctuation-dissipation theorem (by -69 % in the documented xfail); DC and ssac are unchanged.
* `NoiseSpectrum.by_interface` reports interface sources separately: S = Sum by_region + Sum by_interface. A
  fluxterm interface without its pair model, a `hybrid` interface equation, and a fluxterm on a
  non-continuity equation are refused rather than left silently noiseless.
* The interface area is the one DEVSIM assembles (`SurfaceArea` over DEVSIM's active pairs). With
  `devsim_geometry.apply_exact_geometry`, correct BOTH regions of an interface; otherwise the noise refuses,
  because DEVSIM's interface flux is then not conserved.
