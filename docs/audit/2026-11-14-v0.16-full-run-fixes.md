## 2. Three defects reported by a consumer run (added to this package)

1. **fem_2d_tm corner grading** (confirmed, fixed). `corner_mode="metal"` graded every corner touching a region
   with Re eps < 0 anywhere. Reproduced with a few-nm film graded to Re eps < 0 within ~1 nm of its top face, cut
   into 31 lateral blocks under a metal strip (the earlier strip-cell fixture; the counts and timings in this item
   were not re-measured on the generic fixture): 66 corners, 57750 elements, 90 s per solve. The rule now judges the four quadrants at the corner itself (a gridded region by its face row at the
   nearest x sample) and grades only where the metal / non-metal boundary bends (one, three or two diagonal
   quadrants metallic). Same case: 4 corners, 5700 elements, 2.0 s. Accuracy, against a converged reference
   (order 5 at h/2 and h/2.9, which agree to 1.1e-8): new default 4.7e-6 off, old default 4.6e-6 off,
   new vs old 2.0e-7. A plain metal strip grating on a spacer over a mirror (genuine corners) meshes identically,
   with the same r on both trees (element count and r not re-measured on the generic fixture). `corner_mode="all"` reproduces the old mesh of
   the graded case exactly. One existing gate (a metal block inside a metal sheet, test and validation gate F of
   `fem_2d_tm_hydro`) was ABOUT a corner-graded mesh; it now requests `corner_mode="all"` (same four corners and
   mesh as before). Test: `test_fem_2d_tm_planning::test_metal_corner_rule_judges_each_region_at_the_corner`.
   Found alongside (coverage work) and fixed: a block whose name is already a layer or another layer's block was
   merged into that region silently with ITS permittivity (now refused,
   `test_block_names_cannot_alias_a_layer_or_another_block`).
2. **abs_tol with the equilibrium density gradient** (confirmed, refused). DEVSIM has one absolute error for all
   equations, so the volts-only meaning cannot be given to the sqrt(n) rows; per-equation scaling is not
   available through its solve call. `LayeredDevsimBuilder.solve(abs_tol=x)` on a device with DG regions raises
   a ValueError before any solve when x is below the round-off-attainable value (`dc_solve.ABS_TOL_ULPS` unit
   round-offs of the solution size, the criterion `default_abs_tol` uses), naming QSqrtNEquation, the sqrt(n)
   magnitude and the smallest attainable value; abs_tol=None still converges. Restricted to DG devices: on
   drift-diffusion / bipolar devices callers pass density-scale tolerances on purpose (e.g. 1e8, 1e10), and a
   blanket check in `solve_dc` would turn tests that pin the stall of an unattainable explicit tolerance into
   refusals. Test: `test_equilibrium_density_gradient::test_abs_tol_in_volts_is_refused_on_a_dg_device_before_any_newton`.
3. **Electrode footprints without x mesh lines** (confirmed, fixed). A 16 nm Rectangle gate (x 11..27 nm) on a
   full metal layer over the 4 nm x mesh of the gated-film fixture captured the nodes at x 12..24 nm only (unique x
   lines 0, 4, ..., 40 nm). The builder now adds the x edges of every CrossSection electrode footprint as x lines
   (fixed lines for the junction band); an edge within `_LINE_MERGE_M` of an existing line adds nothing, so a gate
   drawn on its own inclusion (the shared validation device) and every full-footprint design keep their meshes (the
   v0.15.1 call-log identity gates pass). After the fix the contact spans 11..27 nm. Test:
   `test_mesh_screening_grading::test_patterned_gate_footprint_edges_are_mesh_lines`.

## 3. Found here, fixed at release integration (reported by the coverage work)

- `fem_2d_tm._auto_buffer` classified an order as evanescent only when |Re kz| < 1e-12 k0, which no lossy
  cladding satisfies, so a substrate index with a 1e-6 imaginary part shrank the auto substrate buffer to a few
  hundred nm near an order cutoff without a warning, although the near-cutoff order still decays over microns.
  FIXED at release integration: an order is evanescent when Re(kz^2) <= 0 and the buffer follows 1/Im(kz) of the
  full complex kz (measured in docs/audit/2026-11-14-v0.16-fem-2d-tm.md: 26.4 um instead of 448 nm at
  n = 1.45+1e-6j; lossless claddings bit-identical).
- `gate_leakage.solve_lateral_1d`: NaN / inf input reaches `scipy.linalg.solve_banded`, whose ValueError escapes
  the continuation loop's `except (RuntimeError, FloatingPointError)` (the module's own "non-finite Newton update"
  message is unreachable); a singular Jacobian would escape as LinAlgError. FIXED in the generic-fixture pass: the
  inputs are validated up front (ValueError naming the argument) and a non-finite residual / Jacobian or a singular
  Jacobian fails the Newton step with the module's FloatingPointError, which the continuation handles
  (tests/test_devsim_gate_leakage.py, the solve_lateral_1d gates).
- Minor: `_softplus_expr` returns 0 below x = -37 (absolute error < 2.2e-16); `_dielectric_neighbours` calls a
  neighbour without recorded physics (e.g. a metal) "another semiconductor" in its refusal; one guard in
  `fem_2d_tm_hydro` (line ~344) is unreachable (the dataclass already enforces it). In the generic-fixture pass:
  the softplus behaviour is documented in `_softplus_expr` (not changed: the error is below double resolution of
  the other trap-charge terms), and the setup_equilibrium_dg refusal now names each non-dielectric neighbour and
  what it is (a semiconductor kind, or no recorded Poisson physics: a metal or an unset region).
