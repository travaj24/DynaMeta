# v0.15.1: platform-independent call-log digests and an SVD-floor gate (2026-11-10)

Follow-up of `2026-11-08-v0.15-linux-ci-exactness.md`, which fixed one call-log digest and one SVD ratio after
the Linux CI failed on them and listed the same construction in other tests as latent. This note removes those
latent cases. No library code changes: only tests and test helpers. Every number below was MEASURED on the
Windows dev box (Python 3.14, numpy 2.4.4, UCRT) and in the WSL proxy of the CI runner (Python 3.12, numpy
2.5.4, glibc, OpenBLAS 0.3.26) unless it is marked otherwise.

## Terms

- **Call log.** The ordered list of DEVSIM definition calls (models, equations, parameters, node values) a
  fixture makes, each with `repr()` of its arguments. Its **digest** is the sha256 of that list. A gate that
  pins a digest says "this definition is character-for-character the recorded one".
- **Correctly rounded.** The double nearest to the exact mathematical value. IEEE-754 requires it for + - * /
  and sqrt, so those give the same bits everywhere. It does not require it for exp, log, pow, tanh, ...: each
  C library (Windows UCRT, glibc) or numpy's own vectorized code may round a hard case either way.
- **Canonical log.** A call log recorded inside `tests/_cr_libm.correctly_rounded()`, where the math / numpy
  transcendentals return the correctly rounded double. It is then the same on every platform, and it still
  records every other operation bit for bit.
- **ulp.** The spacing of doubles at a value (one unit in the last place).
- **sigma_min / sigma_max.** The smallest / largest singular value of the (equilibrated) Jacobian; their ratio
  measures how close the linear system is to singular.

## A. The three other call-log digests

### What changed

- New `tests/_calllog.py`: the ONE implementation of what the four recorders share -- the interceptor that
  logs every definition call, `recording(canonical)`, `digest()` and `skeleton()` (the log with numbers masked).
  `_bipolar_calllog.py`, `_btbt_calllog.py`, `_dg_calllog.py` and `_fdext_calllog.py` now use it (each had its
  own copy of the interceptor and the digest) and record canonically by default (`canonical=True`;
  `canonical=False` gives the raw log). The bipolar recorder passes the flag to its child process.
- `tests/_cr_libm.py`:
  - **tanh** is now correctly rounded (it was refused): the DG fixture's wall seed calls `np.tanh`, and the
    context refused it -- the fail-closed rule working as intended.
  - **A vectorized fast path** for numpy exp / log / power arrays. The FD-statistics bipolar log evaluates
    1388023 `np.power` / `np.exp` / `np.log` elements (the Gauss-Legendre rule of `fd_potential_shift` inside
    the FD equilibrium root); through `decimal` that took 254 s. Each element is now first evaluated in
    double-double arithmetic (about 106 bits, IEEE basic operations only) with an a-priori error bound; when
    the value +- bound rounds to one double, that double is the correctly rounded result. Otherwise the
    element goes through `decimal` as before. This is Ziv's strategy: it only decides early; `decimal` stays
    the definition. The decision bound is 2^15 times the derived error budget.
  - Measured: on the bipolar default log, 1388006 of the 1388023 elements were decided by the fast path, 0 of
    them differ from `decimal`, 17 went to `decimal`; the whole log recorded with the fast path disabled has
    the same digest. On 440017 random arguments (exp, log, pow at y = 1/3, 2/3, 4/3, 0.5, 3, random): 0
    mismatches, on Windows and in WSL. The log now records in 19 s (raw: 1.4 s).
  - New `tests/test_cr_libm.py` (5 tests, < 1 s) keeps 3000 of those comparisons per function, the known
    UCRT hard case `exp(-7.384693350077327)`, tanh, and the refusal. Its refutations (measured): ln 2 without
    its low word, an expm1 series cut at t^3, or a decision bound of 2^-20 each fail it.
- `tests/_custom_terms_child.py` records its same-machine A/B raw (`canonical=False`).
- The bipolar default-vs-explicit-FD equality in `test_bipolar_recombination_bgn_ionization.py` compares two
  RAW logs of one machine (the canonical FD log costs 19 s; the fdext gate made the same choice).

### Still not covered

- Python's `float ** float` and numpy's `ndarray ** x` call the C `pow()` directly and cannot be intercepted.
  These logs reach it in import-time constants (e.g. `tunneling.BTBTParams.from_cgs`, `100.0 ** -P`) and in
  `fd_potential_shift` (`s ** 3`). Measured: the raw logs of Windows and WSL are identical, so these are
  bitwise equal there today. Measured on 20000 random arguments: the Windows platform `pow(x, 3.0)` is not
  correctly rounded in 18 cases (x in [0, 200]), so this is a real residual exposure on another platform.
- A function bound before the context (`from math import exp`) keeps the platform version.
- tanh and pow through `decimal` are correct unless the exact value lies within about 1e-58 (relative) of a
  rounding midpoint; exp and log are proven correctly rounded (Lefevre & Muller worst cases).

## B. `test_quasi_equilibrium.py::test_closure_removes_the_near_null_mode`

### The problem

The test (gate G1-0) takes the dense SVD of the equilibrated DC Jacobian of a 1-D MOS at 0.70 V of band
bending: the full drift-diffusion model, the model with the minority electrons replaced by the
quasi-equilibrium closure, and both carriers closed. The full model's sigma_min is below what a dense SVD can
resolve, so the reported number is the SVD's own round-off. The old assertions divided by it:
`closed / full >= 1e8` and `qfl / full < 10` (qfl: the same matrix after the quasi-Fermi change of
variables).

Measured (n = 804 unknowns; the floor n eps = 1.8e-13):

| Quantity | Windows | WSL |
|---|---|---|
| full sigma_min (sigma_max 3.86) | 2.61e-16 | 4.56e-16 |
| the same full model reached by the 0.05 V ramp | 3.94e-16 | 2.76e-16 |
| closed sigma_min (sigma_max 3.24) | 5.07e-8 | 5.07e-8 |
| old `closed / full` (gate >= 1e8) | 1.9e8 | 1.1e8 |
| old `qfl / full` (gate < 10) | 1.7 | 1.1 |

One physical state gives four different "full sigma_min" values, and the old 1e8 gate had a 1.1x margin in WSL.

### The fix

The budget is the one of `test_well_posedness.py` (2026-11-08 note, section (a)). LAPACK's SVD is backward
stable: the computed singular values are the exact ones of J + E with ||E|| <= p(n) u ||J|| (LAPACK Users'
Guide, 3rd ed., section 4.9; p(n) taken as 2n, u = eps/2). By Weyl's inequality,
|sigma_computed - sigma_true| <= n eps sigma_max. So:

| Assertion | Old | New | Measured (Windows / WSL) |
|---|---|---|---|
| (i) full model is singular to working precision | (in the quotient) | sigma_min / sigma_max <= n eps | 3.8e-4 / 6.6e-4 of n eps |
| (ii) the closure removes the mode | closed / full >= 1e8 | closed sigma_min / sigma_max >= 100 n eps (then the computed value is within 1 % of the true one) | 8.8e4 n eps (880x margin) on both |
| (iii) both closed is well conditioned | cond <= 1e6 | unchanged (a resolved value: 1.46e4) | 3.8e8 n eps |
| (iv) the quasi-Fermi variables do not help | qfl / full < 10 | qfl sigma_min / sigma_max <= n eps | 1.2e-3 / 1.4e-3 of n eps |

`_sigma` now also returns n and the qfl sigma_max; `_svd_floor` holds the budget.

### The new gate fails on (measured, both platforms)

- closure disabled on the "closed" case (`closure=False`): 5.7e-4 / 4.0e-4 n eps, fails (ii);
- the wrong singular value (`s[-2]`, an off-by-one): the full ratio becomes 5.7e-7 = 3.2e6 n eps, fails (i).

### Other SVD-noise assertions in tests/

Searched every test for assertions on sigma_min, singular-value ratios or values near 1e-15..1e-17. None other
divides by an SVD round-off value:

- `test_well_posedness.py::test_mos_inversion_stall_carries_the_near_singular_diagnosis` -- already on the n eps
  budget (2026-11-08).
- `test_well_posedness.py::test_r26_floating_slab_is_refused`: `rep.confirmed[0].r <= 1e-15`. This is the
  residual |y^T J| of an exact null vector (a sparse product, not an SVD), measured 6.6e-18 / 4.6e-18: 150x
  inside its 1e-15, which is itself 14x below the library's `TOL_SINGULAR` (64 eps). Not the same pattern
  (nothing is divided by it); left unchanged.
- `test_devsim_oxide_tunneling_sc.py::test_o7_newton_quality` mentions sigma_min/sigma_max <= 4.4e-16 in its
  docstring only (no assertion on it).
