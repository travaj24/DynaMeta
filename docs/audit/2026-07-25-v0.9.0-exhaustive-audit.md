# DynaMeta exhaustive audit -- 2026-07-25 (v0.9.0 @ c81a4c8, post ENZ/BIC/NL merge)

Whole-library audit of DynaMeta at main commit c81a4c8 (v0.9.0). Axes: physical correctness,
seams between library portions, conventions, library organization, dead/duplicated code, test and
CI infrastructure, and speed/memory improvements that do not sacrifice accuracy.

**Method.** Ten parallel auditors, each owning one domain or one repo-wide dimension (carriers /
ngsolve-FEM / FDTD / frequency-domain+analysis / amplifiers / conventions / dead-code /
test-infrastructure / core-and-infra / performance), every one of them read-only and probe-backed
rather than read-only-inferred. Their output was then handed to **five adversarial re-graders**
briefed to REFUTE every P0/P1: each re-verified the cited file:line against the working tree,
re-derived the physics from primary theory before reading the auditor's argument, and rewrote every
probe from scratch (~50 fresh probes; `regrade_probes_*/`). **Every P0/P1 in this document has been
independently re-verified or re-graded by a second agent.** Where a re-grader and an auditor
disagree, the re-grader's verdict is the one recorded here.

Severity: P0 = wrong physics/results in a mainline path; P1 = wrong in an edge path, or a seam
mismatch / silent drop that corrupts results without a diagnostic; P2 = quality/robustness/
organization defect; P3 = nit/polish.

**Headline: 0 P0. 28 verified P1.** The one P0 the FEM auditor filed (F-1) survived refutation as a
real defect but was re-graded to P1: its mechanism was mis-attributed, and no shipped test,
example or validation script reaches the failing configuration. Ten of the 28 P1s are silent-drop
or missing-guard seams; nine are physics/numerics errors with measured magnitudes; five are
CI/test-infrastructure holes that make whole regression classes structurally uncatchable.

# READ THIS FIRST -- remediation-critical corrections

Five of the auditors' prescribed fixes are **wrong as written**. Applying them verbatim would make
the defect worse, leave it in place, or fail to catch it. These corrections are the load-bearing
output of the re-grade wave.

1. **C-1 -- do NOT use the `mu(T_e)` closed form.** The carriers auditor prescribes
   `<m*(T_e)> = m0 (1 + 2 alpha mu(T_e)/q)`. At fixed carrier density `mu(T)` *falls*, so this
   expression makes the hot-electron mass **drop**: measured -9.07% at 3000 K against a true
   +13.80% -- it inverts the sign of the R9 plasma shift, which is the entire observable. Only the
   second option in that finding ("evaluate the f-sum integral directly") is valid. A correct
   Sommerfeld closed form would need the second derivative of `Phi(E) = N(E)/(1 + 2aE)` at `mu`,
   not `mu` alone. (Re-grade finding N1.)

2. **D-2 -- the prescribed exponential has the wrong sign.** The FDTD auditor prescribes multiplying
   the recorded `Hx`/`Hy` rfft by `exp(-i w dt/2)`. The correct factor is **`exp(+i w dt/2)` on the
   H transform** (equivalently `exp(-i w dt/2)` on the E transform). Measured: the auditor's version
   *doubles* the error it targets (ratio 1.9978 against the predicted exactly 2); the correct
   version reduces the residual `max|Im|/max|Re|` from 4.019e-2 to 2.282e-5 (1760x) and drives a
   synthetic evanescent-order flux from +3.067e-2 to -3.75e-15.

3. **R-3 -- half-weight the endpoints in BOTH parities, not just the odd branch.** The core auditor
   prescribes halving the endpoint weights in the `dn[odd]` branch. That is correct only for an
   **odd-length** grid. With an even-length grid -- reachable through the public
   `e_grid_J=(lo, hi, N)` override -- the last index is odd, so the even branch also sums a
   double-weighted endpoint and **both parities collapse to O(h)** (measured: order ~1.0 on both).
   `_KK_N = 3001` is odd today, which is the only reason the shipped default escapes. The fix must
   halve the weight of indices `0` and `N-1` in whichever branch sums them.

4. **Q-4 -- the fix must be a PROXIMITY test; the sign test is provably insufficient.** The
   frequency auditor prescribes validating `pole_rad` with `Im < 0, Re > 0` plus a proximity check.
   The re-grader's independent reproduction (different Drude parameters) escapes to a root with
   `Re > 0` **and** `Im < 0` -- correctly signed, a genuine zero of `D`
   (`|D| = 1.55e-23` vs an off-pole reference 5.28e-07), and it would sail through the sign test.
   Only `|pole_rad - pole_total| < tol * |pole_total|` catches it (the measured Re shift is
   +2256.83%). Every warm-start seed escapes; the sign of the escape is basin chaos, not seed luck.

5. **Q-6 and Q-3 are single-constant mis-calibrations -- no redesign required.**
   - Q-6: `froissart_frac = 0.05` should become **~1e-4**. Measured pole-zero separations are
     0.90-1.06 for genuine poles and 3.8e-14..1.6e-13 for manufactured Froissart doublets -- a
     14-decade gap, so the shipped threshold is ~4 orders of magnitude looser than it needs to be.
     `froissart_frac = 1e-4` simultaneously passes the module's own Froissart gate and recovers
     every under-coupled resonance down to `ge/gi = 1e-3`. The auditor's proposed
     "use both signals jointly / scale by `res.max_error`" rebuild is unnecessary. (Note also: on
     the module's only Froissart gate the geometric filter is a **no-op** -- the residue floor alone
     removes all 13 doublets -- which contradicts the docstring's justification for it.)
   - Q-3: `gtol = 0` **alone** fully restores exactness (measured: FWHM 6.000000e12 -> 2.000000e12,
     Q 166.67 -> 500.00 at a feature amplitude of 1e-12). The y-normalization the auditor proposes
     is a defensible hardening but is not required for the fix.

Two further "fix" notes worth carrying into remediation:

- **F-1 -- gate on `GetPeriodicNodePairs` completeness, not on a `Periodic(H1).Set()` point probe.**
  The re-grader measured the point probe giving false positives (1.5e-1 "violations" on geometries
  whose periodic entity tables are provably complete) *and* a false negative (the auditor's
  "marginal 7.94e-06" row). The evaluation-free entity-pair count is the artefact-free check.
- **Q-5 -- normalizing `h` is only half the fix.** The re-grader showed the "causal floor" is
  exactly O(h) quadrature error (`rms_norm/h` constant to 4 significant figures over a 16x range of
  N) *and* that the chosen causal reference is the problem: a manifestly causal 2-oscillator Lorentz
  scores 330x lower than plain Drude on the same shipped grid, because the Drude DC pole is
  under-resolved at the grid's low edge. The reference model matters more than `h`.

### C-1 [P1] [FIXED wave-1] `kane_mass_of_Te` returns `m*(<E>)`, not the Drude/conductivity mass

`carriers/carrier_heating.py:51-81`; consumed at `carrier_heating.py:177-183` (`drude_of_t`),
`materials/optical_model.py:165-198` (`DrudeOptical.eps`), and -- the re-grader's addition --
`optics/hot_carrier.py:153-156` (the FDTD hot-carrier `wp` ratio), so the FDTD R9 path inherits it.

**Claim.** `wp^2 = n e^2/(eps0 m)` requires the f-sum-rule / conductivity mass, whose exact T=0
value for a Kane band is the Fermi-surface mass `m_c = m0 (1 + 2 alpha E_F)`. The module instead
evaluates `m*(<E>) = m0 (1 + 2 alpha <E>)` at the mean energy, on a parabolic `(3/5)E_F` base. This
directly contradicts `DrudeOptical`'s own docstring ("m_opt_kg is the OPTICAL (conductivity)
effective mass -- NOT the DOS mass").

**Re-grade.** The f-sum identity was re-derived symbolically (not numerically) and the auditor's
parameter cell reproduced exactly -- but the auditor did not evaluate at the repo's own preset
(`validation/carrier_heating_enz.py:53`, `tests/test_carrier_heating.py:14`:
`m0 = 0.35 m_e, alpha = 0.5/eV, n = 1e27`, `a E_F = 0.378`), where the effect is ~5x larger:
mass **17.2% low**, `wp^2` 20.8% high, cold ENZ crossing off by **148.8 nm** (1493.4 vs 1642.2 nm),
and the R9 `d(Re eps)` modulation depth over-stated **1.22x at 600 K rising to 1.31x at 3000 K**.
88.6% of the T=0 gap is the functional (f-sum) error; only 11.4% is the documented `(3/5)` base, so
the "documented convention" defence covers the smaller half only. Re-fitting `m0` cancels the offset
but not the multiplicative error in `dm/m`, which is the observable.

**Fix (corrected).** Evaluate the f-sum integral directly, keeping the exact `alpha -> 0 -> m0`
off-switch. **Do not** use the `mu(T_e)` prescription -- see READ THIS FIRST item 1. Also note N5:
below `a E_F ~ 0.15` the sign flips and the module *under*-states the rise (0.82x), so the finding
should be stated as keyed on `a E_F`, not as a universal over-statement.

**Status: FIXED wave 1** (commit `d602866`). `kane_mass_of_Te` now evaluates the f-sum conductivity
mass as a direct Fermi-Dirac k-space integral (exact `mu(T_e)` brentq solve), and
`optics/hot_carrier.py` inherits it. Gate: the T=0 identity `m0 (1 + 2 a E_F)` to 1e-15, an
independent `scipy.quad` oracle to 1e-12, and `alpha -> 0 == m0` bit-exact. The ITO preset was
re-baselined (`m_c(300 K)/m0` 1.456 -> 1.759; cold ENZ crossing 1493.4 -> 1642.2 nm).

### C-2 [P1] [FIXED wave-1] LC backflow uses the Leslie coupling coefficient with alpha2/alpha3 swapped

`carriers/lc_dynamics.py:315-319` (dataclass defaults `:227-234`, docstring `:26-33`).

**Claim.** The code computes `g_th = a2 sin^2(theta) + a3 cos^2(theta)`; with the module's
field-axis `theta` convention the Leslie director-flow coupling is
`m(theta) = a3 sin^2(theta) - a2 cos^2(theta)`. Because `m` is squared in
`gamma1_eff = gamma1 - m^2/eta`, the swap maps the backflow enhancement onto the **complementary**
angle: maximal exactly where it should be minimal.

**Re-grade.** Re-derived independently from the Rayleigh dissipation function (sympy), which also
upgrades the auditor's secondary point to a theorem: positive-definiteness of `[[g1,m],[m,eta]]`
requires `gamma1*eta >= m^2`, so the silent `0.05*gamma1` floor fires exactly where the local model
has left thermodynamic validity. Two independent convention pins (the 5CB flow-alignment angle
`p_L = 10.96 deg`; the measured Miesowicz `eta_b = 0.0204`, `eta_c = 0.1052 Pa s` reproduced from
the same dissipation function). Literature cross-check is decisive: true 5CB backflow is ~5.2x at
homeotropic and ~0.8% at planar; the code inverts this exactly. On the **shipped** oracle cell
(`validation/lc_dynamics_anchoring_backflow.py`) the reported speed-ups are wrong by 1.23x (rise)
and 1.85x (decay), with `gamma1_eff` floored on 74.2% of nodes; on a VA cell the error inverts
(code under-states). **Trim the auditor's "pure artefact" framing**: it is valid only for cells whose
director stays near planar -- a strongly-driven cell genuinely has ~1.46x with the correct
coefficients.

**Fix.** `g_th = a3*s*s - a2*c*c`; warn (do not silently floor) when `m^2/eta >= gamma1`; validate
the Leslie identity `gamma1 = alpha3 - alpha2` when `include_backflow=True`. Insufficient on its
own -- see N4.

**Status: FIXED wave 1** (commit `d602866`). Leslie coupling `m = alpha3 sin^2 - alpha2 cos^2` with
a theta-dependent Miesowicz `eta(theta)` (Parodi-consistent `eta_c`), so N4 landed with it; the
floor now fires only where `gamma1 eta >= m^2` genuinely fails. Gate: Miesowicz anchors 0.994 planar
/ 0.196 homeotropic and flow alignment 10.96 deg -- the near-threshold spurious 2.44x speed-up
becomes 1.0003 while the strong-drive 1.41x survives.

### C-4 [P1] [FIXED wave-1] `director_profile_bvp(field_model='poisson')` normalises on `solve_bvp`'s midpoint grid

`carriers/lc_director.py:538-555` (the RHS rebuilds `LCGeometry` from whatever abscissae scipy hands
it) + `:331-342` (the global series-capacitance normalisation).
**Also `chiral_director_profile_bvp` at `lc_director.py:766-767`** (re-grade finding N2).

**Claim.** `solve_bvp` evaluates the RHS on `x_middle`, a grid short by one full cell, so the LC
thickness seen by the voltage division is `d_lc - h`: `E` too large by `~1 + h/d_lc` and the
dielectric torque by `~1 + 2h/d_lc`. An O(h) bias inside a 4th-order collocation scheme.

**Re-grade.** Instrumented spans of 0.980/0.990/1.000 of `d_lc` measured inside the RHS; the bias
is +2.0408% at `nz=51`, matching the closed form `1/(1-h/d_lc) - 1` exactly at every `nz`. Impact
reaches a **shipped accuracy claim**: re-running the repo's own exactness cross-check with only the
normalisation corrected takes the unit-test residual from 1.1861e-2 rad to 6.7986e-3 rad against a
2.0e-2 budget (`tests/test_lc_director.py:112-122`) and GATE B's max from 1.0919e-2 to 8.8745e-3
(`validation/lc_two_constant_bvp.py`). **43% of the unit test's reported residual is this bug**, and
the docstring's advertised "~8e-3 rad" is actually 1.19e-2 because of it. Near threshold the returned
midplane tilt moves by up to 1.29 deg.

**Fix.** Precompute the normalisation on the *geometry* grid once and pass `(d_lc, denom_lc)` into
the RHS so it evaluates `E(z)` pointwise only. Apply to **both** `director_profile_bvp` and

### R-1 [P1] [FIXED wave-1] `IntersubbandEffect` silently drops every transition into an UNOCCUPIED sub-band

`core/effects/electroabsorption.py:431-443`:

```python
idx = np.where(ns > float(self.occ_floor_m2))[0]        # occ_floor_m2 defaults to 0.0
for a in range(len(idx)):
    for b in range(a + 1, len(idx)):
```

**Claim.** Both `i = idx[a]` and `j = idx[b]` are drawn from the occupancy-filtered set, so a
transition survives only when the FINAL state is also populated. The physically standard ISB
absorber -- ground sub-band full, first excited EMPTY -- has the LARGEST population difference and
therefore the STRONGEST line, and it is exactly the configuration the filter removes. No warning.

**Re-grade.** Reading settles the question the re-grade had to answer: the gate is on **both**
indices. Reproduced from an independent construction (analytic infinite square well; dipole `z_12`
matches `-16L/(9 pi^2)` to 1.4e-14): populating the upper sub-band with `1e-30 m^-2` -- a physically
null change -- swings `Im(eps_zz)` from 0.028 to **89.2** (3155x), and at exactly zero the module
returns bare intraband Drude with `eps_zz == eps_xx`. **Not defensible in any convention:** the
occupancy physics is already carried by the code's own line strength `N_ij = (n_s,i - n_s,j)/L_eff`
(`:437`), which is *maximal* when the upper band is empty -- the filter double-gates it. Changing
only `occ_floor_m2` to -1.0, with `ns` untouched, recovers the hand-derived answer to <1e-9.
**NEW:** the same filter silences the *inverted* configuration `ns = [0, n]` (the strongest possible
population inversion) -- bare Drude, zero warnings, because the `N_ij < 0` gain warning at `:439`
cannot fire on a pair that was removed first. The module's only unphysical-occupancy diagnostic is
unreachable in the configuration it exists for. The repo's own gate
(`validation/intersubband_eps_zz.py:88`) is written *around* the limitation.

**Fix.** Select INITIAL states by occupancy; let the FINAL state range over all bound sub-bands;
keep the `N_ij >= 0` clamp as the physical gate.

**Status: FIXED wave 1** (commit `d602866`). ISB pairs are gated on the population DIFFERENCE, not
on both occupancies. Gate: the canonical full-ground / empty-excited absorber matches the closed
form to 1e-15, and the inverted `ns = [0, n]` case now fires the `N_ij < 0` warning instead of
vanishing.

### R-2 [P1] [FIXED wave-1] `BursteinMossEdge`'s default auto KK grid truncates the Tauc tail

`core/effects/electroabsorption.py:303` (`_KK_SPAN_J = 5.0 * Q_E`), `:343-348` (grid build and a
guard that only checks the grid BRACKETS the gap and the probe).

**Re-grade -- CONFIRMED, magnitude UNDERSTATED, convergence reasoning WRONG.** The probe sits below
the optical gap and `_eps2` is identically 0 below `Eg`, so the KK integral has no pole in range and
`scipy.quad` on the substitution `E' = Eg/t` evaluates it exactly **including the tail to infinity**.
Against that oracle: the shipped default delta is **14-16x too large (1300-1550%)**, not 397% --
because the auditor's "Eg+60 eV FIXED" reference column is itself 3.0-3.3x too large. Absolute `dn`
is 44-50% low, not 39%. **The integral DOES converge:** the Tauc tail gives an `E'^-2.5` integrand
with truncation error `(2 alpha Eg^1.5)/(3 pi) * E_hi^-1.5`, verified to ratio 0.9956 at a 320 eV
span, and the sequence converges monotonically to -0.001518. The auditor's "no converged value on
any practical grid, because the model's Tauc tail is unbounded" is false, and the observed
halving-per-doubling **is** the convergence law, not evidence against it.
**Mechanism the auditor missed:** `e_hi = max(Eg_hi, E_ph) + 5 eV` is rebuilt **per `eps()` call**,
so `DeltaEffect` (`base.py:100-102`, two independent calls with different `Eg`) integrates its two
halves on **different grids** and the large common truncation offset does not cancel. The surviving
residual (`Delta(tail) ~ 0.0054` in `dn` -> ~-0.0216 in eps) accounts for the entire -0.0223 delta
error -- which is why a 48%-wrong absolute `dn` becomes a 1469%-wrong delta. Guard blindness
re-verified: a grid ending 1 meV above `Eg` is accepted.

**Fix.** Give the Tauc edge a finite bandwidth (high-energy cutoff / oscillator wing) so the integral
converges fast; add the closed-form `E_hi^-1.5` tail correction; replace the bracket-only guard with
a real tail test; and **pin the grid across a `DeltaEffect` pair** so the offset cancels. At minimum
document that `alpha_edge` absorbs the grid choice, so a calibration on one grid is invalid on
another.

**Status: FIXED wave 1** (commit `d602866`). The KK grid is built once per config (both
`DeltaEffect` halves share it), `E_hi` comes from a closed-form tail criterion, and the analytic
tail correction is applied; wave 3's verifier masked the `p = 0` Tauc divergence found en route.
Gate: `dn` against `scipy.quad`-to-infinity at 4.4e-5 (was 44-45% low).

### R-3 [P1] [FIXED wave-1] `kramers_kronig_dn` is first-order accurate at ODD grid indices

`core/effects/base.py:140-169` (docstring claims "an O(h^2) estimate"; `:167-168` is the parity
split).

**Re-grade -- derivation exact.** For a uniform grid with odd `N`: the **even**-index branch sums the
odd nodes, which are exactly the midpoints of the `(N-1)/2` width-`2h` panels, so `2h * Sum` is the
composite midpoint rule -- O(h^2), endpoints never touched. The **odd**-index branch sums the panel
NODES, weighting `E_0` and `E_{N-1}` by `2h` where composite trapezoid needs `h`, so
`code = trapezoid + h*(f(E_0) + f(E_{N-1}))`. The predicted excess matches the observed one to
1.3e-13 at three grid sizes. Measured convergence orders: **2.00 (even) vs 1.00 (odd)**, with the odd
branch 1.8e4x worse at N=6401; the endpoint-corrected variant restores 2.00 and drops the odd error
four orders of magnitude. Cross-link verified: `BursteinMossEdge`'s grid has `dalpha(grid[0]) = 0` but
a large `dalpha(grid[-1])`, so exactly one endpoint term survives -- R-3 does bite R-2's regime -- and
the batched `e_eval_J` path genuinely interpolates between one 2nd-order and one 1st-order row.

**Fix (corrected).** Halve the weight of indices `0` and `N-1` in **whichever branch sums them**. With
an **even**-length grid -- reachable through the public `e_grid_J=(lo, hi, N)` override -- the last
index is odd, so *both* parities carry a double-weighted endpoint and *both* collapse to O(h)
(measured order ~1.0 on both). `_KK_N = 3001` is odd today, which is the only reason the shipped
default escapes. See READ THIS FIRST item 3.

**Status: FIXED wave 1** (commit `d602866`). Endpoint half-weights in all three paths -- the
corrected fix, not the odd-branch-only form. Gate: measured convergence order 2.00 at BOTH grid
parities.
