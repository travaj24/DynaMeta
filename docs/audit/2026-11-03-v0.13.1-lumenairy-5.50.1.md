# v0.13.1 -- adopting lumenairy 5.50.1 in the RCWA bridge (2026-11-03)

lumenairy 5.50.1 is the correctness release that answered this bridge's 2026-11-02 findings
report (`Lumenairy/docs/audits/AUDIT_DYNAMETA_BRIDGE_FINDINGS_2026_11_02.md`, L-1 .. L-10). This
patch release makes the RCWA bridge use the two capabilities it added, each behind a measured
`_common.FEATURE_FLOORS` gate, and records that the third headline fix needs no DynaMeta change.

## Behaviour changes (lumenairy >= 5.50.1 only; older lumenairy routes exactly as in v0.13.0)

| What | v0.13.0 | v0.13.1 on lumenairy >= 5.50.1 | Opt-out |
|---|---|---|---|
| `inclusion_model='auto'` with `formulation='li'`/`'fff'` | every inclusion layer rasterized (shapes layers were Laurent-only) | analytic shapes with Li's rule where lumenairy takes them (1-D stacks: y-invariant shapes; 2-D stacks: axis-aligned rectangles); any other layer (e.g. a disk under 'li' on a 2-D stack) is refused by lumenairy and rasterized, still 'li' | `inclusion_model='raster'` |
| `inclusion_model='analytic'` with `'li'`/`'fff'` | `ValueError` ("requires formulation='laurent'") | builds the analytic 'li' layer; `ShapesNotRepresentable` for a layer lumenairy refuses | -- |
| `make_lumenairy_rcwa_solver(absorption=True)` | `'auto'` rasterized every layer; `'analytic'` refused at construction | the analytic layers are kept (lumenairy reconstructs `layer_absorption` on them) | `inclusion_model='raster'` |

New feature floors: `rcwa_shapes_li` (5.50.1) and `rcwa_shapes_absorption` (5.50.1), measured by
calling the raw API: 5.50.0 raises for `formulation='li'` with `shapes=` and has no
`layer_absorption` on shapes layers.

## Measured (tests/test_lumenairy_shapes_sem_wrap.py)

* TM on the GATE B metal-line cell (600 nm, 50 % eps -20+2i, 120 nm), oracle the 1-D PMM at
  degree 32 (no factorization rule involved): |R - PMM| at N = 8 / 16 / 32 is 2.37e-2 / 9.72e-3 /
  4.86e-3 for the analytic 'li' layer (converging at the first-order metal-corner rate, lumenairy
  L-1) against 8.83e-2 / 2.37e-2 / 3.04e-2 for analytic Laurent (not converging): 6x closer at
  N = 32.
* Shapes-layer absorption (lossy rectangle + disk, 2-D, n_orders 5, 11 deg): the analytic layer's
  absorbed fraction vs lumenairy's own AREA-AVERAGED eps_cell (built in the test, independent of
  the bridge): 1.31e-5 / 1.11e-5 / 2.32e-6 at S = 128 / 256 / 512.
* `layer_absorption()` RESCALES the per-layer integrals to sum to 1 - R - T by default, so for a
  single lossy layer `A_independent == 1 - R - T` by construction. The honest closure is the raw
  volume integral (`return_raw=True`): exact in-plane on the analytic layer (identical at nx 64 /
  128 / 256) and within 1.5e-3 relative of 1 - R - T at n_orders 5 -- the field-truncation error.
  Gated at 3e-3.
* The pre-5.50.1 routing stays covered on a 5.50.1 install: the two gates' features are switched
  off by monkeypatch (`_pre_5501`) and the v0.13.0 assertions run unchanged.

## The point-mirror fix needs no DynaMeta change

lumenairy 5.5.0 .. 5.50.0 solved every patterned RCWA / PMM layer as eps(-x, -y). The bridge never
compensated for it (no mirror logic anywhere in `lumenairy_bridge/`), so 5.50.1 simply makes its
results correct. Verified 2026-11-03 against a lumenairy v5.50.1 worktree: all 158 bridge tests
(157 fast + 1 slow) and all 11 `run_all lumenairy` validations pass unchanged -- no DynaMeta pin was
taken on an origin-asymmetric cell at oblique incidence, where the mirror changes efficiencies.
DynaMeta results computed with lumenairy <= 5.50.0 on such cells (asymmetric unit cell, oblique or
conical incidence, or per-order / internal-field outputs) should be re-run on 5.50.1.
