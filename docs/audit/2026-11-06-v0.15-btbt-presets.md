## What changed (`dynameta/carriers/tunneling.py`)

* **`BTBTParams` gains five keyword fields with defaults, appended after `P`** (backward compatible:
  `BTBTParams(A, B, P)` and every v0.14 call are unchanged; `SILICON_HURKX` keeps its bits):
  * physics (compared, hashed): `T_K: Optional[float] = None` -- the temperature A, B are quoted at (None =
    T_REF); `scale_B_with_gap: bool = False` -- the opt-in E_g^(3/2) scaling of B;
  * provenance (`compare=False`, no physics): `source: str = ""`, `process: None | "direct" |
    "phonon_assisted"`, `verification: None | "primary" | "secondary" | "computed"`;
  * `from_cgs(A, B, P, **fields)` passes the keyword fields through; property `quoted_T_K`.
* **`kane_direct_params(Eg_eV, m_r_over_m0, g=2.0, *, source, verification="computed")`** -- THE function for
  Kane direct-process sets (Sentaurus UG N-2017.09 Eqs. 495-496, read; Kane's g = 2 form). A computed preset
  is a call of it.

  Not shipped: vendor defaults (Sentaurus E2, Sentaurus Ge 9.1e16 / 4.9 MV/cm), Atlas BBT.STD, any InGaAs fit.
* **Several processes per region.** `btbt=` (`setup_btbt`, `setup_bipolar_region`, `TransportModel.btbt`,
  `Stacked3DSpec.btbt`) accepts one set or a non-empty tuple. One set: exactly the v0.14 names (term `btbt`,
  `BTBT_U` / `BTBT_U0`, `BTBT_U1`). A tuple: term `btbt_<k>`, models `BTBT_U_<k>` (1-D) / `BTBT_U0_<k>`,
  `BTBT_U1_<k>` (2-D/3-D), one shared `BTBT_Emag`; the terms sum through the one additive mechanism, each
  with its own noise pair rate. `btbt_generation_current(..., index=None)` returns the sum of the per-term
  currents, or term `index`.
* **Temperature (decision 20, opt-in).** `btbt_at_temperature(btbt, T_K, gap_ratio)` is the one scaling:
  B -> B ratio^1.5, A and P unchanged, result tagged `T_K` (sets without the flag are returned as the same
  object). `btbt_for_material(btbt, transport_model)` is the builders' hook: for each flagged set, ratio =
  `materials.band_gap_ratio(tr, T_region, T_set)` from the material's band-temperature model (the one gap
  law); without a model the set passes unscaled. The 2-D `LayeredDevsimBuilder` and
  `Stacked3DSpec.from_design` call it (one line each; `devsim_layered.py`, `devsim_3d.py`).
  `setup_btbt` warns (the v0.14 row 3.2-9 advisory, wording kept so its gate still matches) for every set
  whose quoted temperature differs from the region's V_t, names the sets' temperature, and says when a set
  is flagged but no ratio reached it.
* Docstrings: module header (sets table, units, which set for which calculation, temperature options),
  `setup_bipolar_region`, `TransportModel.btbt`, `Stacked3DSpec.btbt`, `bipolar_options` item 4,
  `band_gap_ratio`.

## Root cause: the Si Kao Zener non-convergence (2026-11-06, coordinator follow-up)

**Symptom.** The first P4 study (DEVSIM `add_1d_mesh_line` meshes, lines at x_j - W, x_j, x_j + W with ps = h)
gave Si direct (1e26 m^-3, n_i 1e19, 0.3 V) +7.9 / +15.1 / +17.1 % at h = 0.2 / 0.1 / 0.05 nm and +11.8 % at
0.025 nm, and Si indirect +1.8 / +2.7 / +1.5 %.

**Measurements that located it** (all MEASURED, Si direct, 0.3 V):
1. *Not the D factor / quasi-Fermi assumption.* The solved quasi-Fermi split at the peak is 0.3000 V, and
   I_dev / I(D = -1 on the same discrete field) = 0.9555 / 0.9679 / 0.9707 / 0.9711 against the analytic
   ratio I_A / I_B = 0.9696. The whole deviation is already present with D = -1.
2. *Not the field.* The discrete edge fields equal the continuum triangle sampled at the edge midpoints to
   <= 3e-4 (Gauss's law makes the FV edge field exact at the midpoint), and the peak edge field equals the
   analytic E_max to 2.5e-4.
3. *The mesh.* At EVERY ps the junction edge was [99.87173, 100.00000] nm, 0.12827 nm long: the line
   mesher left the remainder of the non-integer (W / ps) in the edge ending at the junction line. The FV
   charge boundary of the abrupt doping lies at that edge's midpoint (the junction node takes +N for its
   whole volume), so this fixed-length edge carries the field PEAK.

**Mechanism (derived).** The rate falls off from the peak as exp(-k s) with k = (B/E^2)|dE/ds| = B/(V_bi + V_r)
for the abrupt junction (7.0e9 /m: 1/k = 0.14 nm for Si direct; 1.8e9 /m for Si indirect; 1.4e9 /m for
Hurkx/Z1). The edge-midpoint quadrature assigns the peak edge h_e f(E_max), while the continuum over that edge
is (2 f(E_max)/k)(1 - e^(-k h_e/2)). Relative to the total 2 f(E_max)/k the excess is
k h_e/2 - 1 + e^(-k h_e/2) = +8.8 % for h_e = 0.128 nm (pure exponential; the E^P prefactor and the
curvature of B/E(s) add the rest: MEASURED +11 %), and it does not shrink when the other edges are refined.
On a UNIFORM mesh the same rule is (kh/2) coth(kh/2) - 1 ~ (kh)^2/12, second order.

**Fix (test fixture) and proof.** The Zener fixtures now place explicit nodes (`_nodes`: uniform h over the
junction region, the junction a node). Si direct then converges at order 1.995 with dev - limit = 1.14e-2 /
2.87e-3 / 7.2e-4 against (kh)^2/12 = 1.03e-2 / 2.57e-3 / 6.4e-4 (ratio 1.1-1.12: the prefactor/curvature
excess again); Si indirect at order 1.998. Both Richardson limits are inside 1 % + delta_D (gate P4c, table
above). The fixed 0.128 nm junction edge re-inserted into the uniform mesh pins the error at +10.6 / +11.0 /
+11.1 % (the adversarial). The Ge and InGaAs P4 deviations also dropped (2.3e-3 max at 0.2 nm, from 3.2e-3).

**Is the v0.14 kernel wrong? No.** `setup_btbt`'s 1-D edge assembly (and the 2-D/3-D element assembly, same
rule per element edge) is a consistent second-order quadrature; nothing in `tunneling.py` changed for this.
It IS a resolution hazard for existing users: the local BTBT current carries a mesh error ~ (k h)^2/12 that
is large when B/(V_bi + V_r) is large, and an O(k h_e) error from any long edge on the field peak. v0.14's own
Z1 fixture has a SHORT (0.102 nm) edge on the peak between 0.2 nm neighbours, k h <= 0.3, consistent with its
measured 0.2-0.6 % quadrature spread. Documented in the module header (MESH RESOLUTION: h <= 0.35/k across the
peak for <= 1 %, and explicit 1-D nodes there). A runtime under-resolution advisory was not added (a possible
follow-up: flag edges where the rate changes by more than e^0.35 between neighbours). **Correction (2026-11-06, v0.15 close-out):**
added as a post-solve ESTIMATE of the quadrature error (`tunneling.btbt_quadrature_error`, warned by
`btbt_generation_current` above 1 %, 1-D); the neighbour-ratio criterion was measured and rejected
(docs/audit/2026-11-06-v0.15-followups.md item 1).

**The Si-direct (E_g, m_r) = (3.58 eV, 0.069) decomposition does not enter.** k depends only on B (the
printed 101 MV/cm) and the junction voltage; how Kao split B into E_g and m_r is irrelevant to the numerics.
(3.58 eV is an INFERRED split from the printed pair; Si's direct Gamma gaps are ~3.4 eV (E0') and ~4.2 eV, so it
is not implausible, but it cannot be checked without the primary.)

## Findings (reported; outside the gates or the plan's claims corrected)

* **Plan P6 claim corrected.** "The direct share grows with field for Ge" is false for Kao's numbers:
  direct/indirect = (A_d/A_i) F^-0.5 exp((B_i - B_d)/F) = 8.7e5 F^-0.5 exp(5.1e7/F) DEcreases with F but
  stays > 1 up to ~7.6e11 V/m. That is Kao's own abstract statement ("direct tunneling always dominates
  over indirect tunneling in Ge"), so it doubles as an independent check of the re-typed digits.
* **The Si Kao Zener non-convergence: ROOT-CAUSED** (section below). It was the test fixture's mesh, not
  the kernel and not the analytic estimate.
* **CODATA vintage.** `dynameta.constants.M_E` is CODATA 2018 (9.1093837015e-31); scipy 1.17 ships CODATA 2022
  (9.1093837139e-31), 1.36e-8 relative higher. The Kane oracle pins the 2018 literal; with scipy's m_e the
  Kane sets move by 6.8e-9.
* **InGaAs masses are low-temperature values** (Vurgaftman's recommendation), used with the 300 K gap. A
  k.p-consistent 300 K electron mass would be ~10 % lower (INFERRED: m_e ~ E_g scaling), lowering B by ~5 %.
  Stated in the set's source.
* **Direct-process sets in indirect materials** scale with the material's FUNDAMENTAL gap ratio (the one
  band-temperature model); the Gamma gap's own temperature law is not modelled. Stated in the module.
* `docs/plans/.../P1_tunneling.md` still quotes the old InGaAs gap row (0.763 eV); not edited (plan file).
  **Correction (2026-11-06, v0.15 close-out):** P1 now marks that row RESOLVED (commit 3e18d17).
